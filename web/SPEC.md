# web/：网页前端（F1）

规格：HMI v1.1 §2 五条禁令、§3 各原理的强制点、§4 信息架构、§10 线框、§11 端点表、§13 安全；基座规格 v1.4 §3.1.2 人的操作。
契约：`graph/SPEC.md` 的「HTTP 绑定」。前端是图服务 API 的又一个客户端，与 `pd` 同级，不持有任何权威状态。

## 实现的契约接口

只读层

- 题目列表（`/v1/problems`）：终态三值、Goal 判官徽章、画像、花费。
- 题内驾驶舱：前沿列表（主区默认）、图（确定性布局）、检视与下钻、成本仪表、时间轴回放、待办。
- 读数面板：每解成本、按角色分项、验证池；本机的界面使用读数（H5）。没有读端点的量显示“暂不可用”，不编数字。

交互层（写入全部走 `POST /v1/problems` 与 `POST …/proposals`，带人的令牌，与 `pd` 是同一条提议通道）

- 开题向导四步（Origin、判据、授权、预算）：材料先 `PUT /v1/blobs`，登记与 `open_problem` 同批提交。
- Hint 注入与效果追溯；审批卡（批准、带理由的拒绝）；续期门对话（随 M1，见下）。

## 五条禁令怎么落地

| 禁令（HMI §2） | 落地 | 测试 |
| --- | --- | --- |
| 不内嵌 reducer，不算等级 | 节点、等级、等级词、判据卡、前沿、待办、卡片字段全部取自服务端投影；回放靠 `as_of`。本机的事件序列只用来画时间轴刻度与知道链头 | `boundaries`「不内嵌 reducer」 |
| 不持有权威状态 | 本机只存：图服务基址、人的令牌、图开关、使用读数（`localStorage`） | — |
| 写入只走提议通道 | 只有 `api/client.ts` 发写请求；操作集合是规格 human 一行的子集，别的操作在发出请求前被拒 | HT-12 |
| 不调模型 | 请求路径都在 `/v1/` 下；源码里没有别的出网手段；构建产物 CSP `connect-src 'self'` | HT-12 |
| 不把日志文本当标记 | 一切文本经 `Plain`（纯文本节点，控制字符显形）；没有 `innerHTML`，没有把网址变链接 | HT-15 |

## 四语域（HMI §3.4）

语域由图服务按出处类别查表，随每段文字给出（`{src, register, value}`）。前端只认 `register`，不看内容；三重编码是字体、边框、文字标签，不靠颜色。

| 语域 | 样式 | 入口 |
| --- | --- | --- |
| 证据 | 等宽、实线框、命令行与退出码在首行、哈希徽章与本地校验 | 只能由 Artifact 登记记录渲染（`ArtifactCard`）；没有接受裸字符串的证据组件；authored 类不论标什么语域都进不去 |
| 叙述 | 引文、左竖线、“模型撰写” | `Text` |
| 人 | 作者与时间在首行、“人” | `Text` |
| 估 | 小号、“≈”前缀，只在折叠区，不与等级同框 | `Text` |

## 确定性（HMI §3.9）

- 视图模型是四份投影（`status`、`view`、`budget`、`work`）的纯函数；四份必须同一 `as_of`，否则拒绝拼装。排序只用 seq 与 id，时间取事件的 `ts`。
- 实时就是“`as_of` 跟着链头走”：每到一条事件，按它的 seq 取四份投影。所以实时跑到 s 与冷启动回放到 s 是同一条路，视图模型哈希相同（HT-10）。
- 图布局：列 = 1 + 前提里最大的列，行 = 同列里更早的节点数，Hint 在顶上一条泳道。只增不挪（HT-14）。
- 事件流：`fetch` 读 SSE，带 `Last-Event-ID`；无重靠 seq，无缺靠按题的 `prev_hash`，缺了用 `/events` 补；断开时顶栏写“已断开，停在 seq=…”，写操作全部禁用（HT-16）。

## 一句话新建（kaiti 设计第二期）

- `/new` 是一个输入框：回车起草，⇧回车换行。输入时显示前置抽取（`POST /v1/drafts/extract`，确定性，不调模型）。答案栏默认收起，以圆点遮住。
- 回车后 `POST /v1/drafts` 给出校验结果，页面只排版：确认卡左栏原文（被引用的区间按位置编号，句子细下划线、词元粗下划线加底色，读屏器读"原文第 n 段到此"），中栏任务单按目标与题面、判据、授权、预算四组排，每行带出处记号（摘、表、估、草、人），右栏"为什么要你看"（唯一用朱色的地方）与画像预览（`/v1/profile/preview`）。
- 卡上能改的只有每条规则的风险（三选一）与预算的金额、时限；改了即把草案交回重新校验（不再调模型），出处变"人"。其它字段要改，"在高级模式里改"：有答案时先写保密库，草稿里只带引用与出处记号，向导左栏顶部折叠显示原文。
- 拒绝页：标题写结论，引用目标句，三条路（补一个可判定的终点、人工验收、进高级模式）；人工验收在内核放开 `accept = human` 之前灰显并写明原因。
- 创建任务走 `app/submit.ts` 的 `submitVetted`：材料先存（服务端、本机、起草结果三方哈希一致才继续），有答案时 `PUT /v1/vault` 换回引用替换 `"$answer"`，最后整批原子提交。零确认在这一期没有入口。
- 假服务只回放 `tools/record_kaiti.py` 从真 qicao 录下的应答（`mock/kaiti.json`），前端没有第二份抽取与校验规则。

## 界面（P2-2）

- 外壳（`src/shell/`）：左侧栏（导航、⌘K 搜索、正在运行）、顶栏（面包屑与本页主操作，下沿制图刻度）、内容区（十二栏界栏）、底部状态行（只说连接与能否写；数字都在页面里，不在状态行重复）。工作区把侧栏收成图标栏。快捷键：⌘K 或 Ctrl+K 命令面板；C 新建任务，只在顶栏有“新建任务”按钮的页面生效；工作区里 H 打开“给出指导”，Esc 收起卡片（焦点在输入框里时都不触发）。
- 工作区左栏三节：01 待你（`/work` 的 human 项）、02 会话（`status.leases` 原样排版，在途与结局取服务端字段，不推断进度）、03 你的指导（未关闭的指导）。图节点的无障碍名称以可见的三行文字开头，再补全称（WCAG 2.5.3）。
- 写操作的反馈三段式（`src/ui/feedback.ts`）：提交中 → 已记录（带 seq）→ 被拒（拒绝码翻成人话）。仍不做乐观更新。
- 可访问性：`e2e/a11y.spec.ts` 对每个页面在宣、墨、素三套主题下跑 axe（WCAG 2.1 AA），不许有违规。

- 顶栏分主次：主栏只放任务名、终态与判定器徽章、连接状态、花费仪表；目标尝试次数、画像、状态哈希收在“详情”里。
- 窄屏（宽度 < 1024px）：三栏改为一栏，顶部一排按钮切换“待办、前沿与图、检视”；选中节点自动切到检视，打开待办自动切到主区。
- 图：滚轮或 + − 缩放（以指针或视口中心为不动点），拖动或方向键平移，0 复原，“适合窗口”。视口获得焦点后可用键盘操作；每个论断与尝试节点都能 Tab 聚焦，Enter 或空格检视，读屏器读到类型、id、等级与标题。视口只是本机的看法，不改布局坐标。
- 徽章：等级、终态、裁决结果各带一个形状记号（○◔◑◕●✕、✓◇✕…、✓✕？），与文字并排，不靠颜色与线宽区分；记号对读屏器隐藏。

## 阅读质量（视觉与阅读质量轮）

- 字体只三族：宋体（`--serif`）只给页标题与节标题 h1–h3；无衬线（`--sans`）给全部正文、标签、按钮、数字读数；等宽（`--mono`）只给 id、seq、哈希、金额与代码。手写体与楷体已去掉，朱批改成普通的提示文字。
- 字号只六级令牌：`--fs-xs 12 / --fs-sm 13 / --fs-md 14 / --fs-lg 17 / --fs-xl 22 / --fs-2xl 30`，最小 12px；样式里不写裸 px 字号（`tests/words.test.ts` 扫描）。
- 界面用词只一套（`src/ui/words.ts`）：任务（不写题、题目、题集）、新建任务（不写开题）、关闭任务（不写关题）、指导（不写 Hint、提示）、尝试（不写 Intent）、会话（不写租约）、判定器（不写判官）、目标（不写 Goal）。协议字段、事件种类与模板给的材料槽名（如“题面”）是数据，不改。`tests/words.test.ts` 扫旧词。
- 每页一个焦点：页标题说当下最要紧的事，导语只说下一步，不复述页面里的数字；同一个数字同屏只出现一次。
- 空态：一句话说清为什么空，并给出下一步动作；不列一排“—”占位。
- 按钮语义：墨（`ink`）是本页唯一的主操作；朱（`zhu`）实心只给卡片里的拍板动作（批准、确认关闭）；线框（`line`）是次要操作与列表里的“去处理”；无框（`bare`）是第三级操作。旧的 `.btn-small`、`.chip` 与默认 `button` 在样式上对齐线框按钮。
- 列表行二选一：整行是一个链接或按钮、里面不再套链接；或整行不可点、操作放在行里的链接与按钮上。今日页与待办页用后一种。
- 金额：两位小数加千分位，不足一分写“< $0.01”，始终带“$”。

## 运行时扩权（`docs/design/runtime-grants/` §7，第三步）

- 扩权卡 `ui/ScopeCard.tsx`：新增规则与现有范围并排，风险来源照写（风险表第几条，或未命中按缺省 r2）；理由是申请方（模型）写的，叙述语域；批准后的画像变化与没有自动批准的原因都由图服务给出。批准绑定 `card_hash`，与审批卡同法（打开期间变了就列出差异、要求重新确认；服务端以 `stale_view` 兜底）。风险只可上调，档位由服务端给。原文对照是前端对题面的逐段字面查找（`model/scope.ts`），只帮人读，不作判断依据。随尝试而来的申请不在这张卡上决定。
- 出现的地方：工作区左栏待办（`why: scope_request`）、会话面板上方的横幅“等你批准访问 N 个地址”（只在实时时出现，点开是同一张卡）、收件箱（按任务分组，印“权”）。时间轴的 S 节点：人批、人拒、随审批、自动批准（写明信封版本）与撤销各说各的。
- 写操作 `grant_scope`、`revoke_scope` 与 `pd scope` 发出同一组字段（`api/ops.ts`）。假后端的 demo-4 是一道开题零出站的题：一条已自动批准，两条等人批。

## 目录

- `src/api/`：线格式类型（生成物）、客户端、人的操作的事件体、SSE。

数据路径（P2-1）：冷启动取一次 `/ticks`（时间轴）和一次 `/snapshot`（四份投影）。事件流里的事件只追加到刻度表；每批之后的 `event: view` 帧带四份投影的哈希，会话只对哈希变了的那几份发一次 `snapshot?parts=`，没变的沿用，`as_of` 与上一帧相同则不发请求。
- `src/model/`：视图模型、布局、刻度、等级词、语域、向导草稿，都是纯函数。
- `src/app/`：本机配置、路由、题目会话（事件流加视图模型）、使用读数。
- `src/ui/`、`src/pages/`：组件与页面。
- `mock/`：开发与测试用的假后端，线格式与图服务相同；多出来的只有 M1 的续期门。`stale_view` 校验两边都有：图服务在内核里校验 `seen.card_hash`，拒绝时在结果的 `card` 里附上最新卡片。
- `tests/fixtures/real/`：真图服务录下的应答（`tools/record_fixtures.py`）。
- `e2e/`：Playwright 浏览器测试与它用的服务（构建产物加不自动播放的假后端，测试自己推进剧本）。
- `e2e-real/`：连真实图服务的浏览器测试（`playwright.real.config.ts` 起 `scripts/run.py`，执行层 none、没有会话脚本，事件由测试以人的身份经 HTTP 写入）：总览列出题目、驾驶舱渲染、Intent 与 Hint 经 SSE 推到页面且不刷新、图视图画出节点。
- `lint/`：ESLint 单独一个包。typescript-eslint 的解析器要 TypeScript 的 JS 接口，`web/` 用的 TypeScript 7 没有，这里固定 5.9 只供解析。
- `tools/live_demo.py`：起一个真图服务，按固定脚本经 HTTP 提交事件，给网页一份实时数据。

## 实现取值（异议 005 已于 2026-11-18 裁决，见 `docs/m0/adjudication-004-005.md`）

1. 线格式类型由图服务的 JSON Schema 生成（`graph/src/paoding_graph/wire_schema.py` → `scripts/gen-types.py` → `src/api/types.ts`，不手改；CI 带 `--check`）。契约测试照旧对着真应答核。
2. 批准与拒绝都带 `seen {seq, card_hash}`。图服务在链头重算卡片哈希，不等即 `stale_view` 并附最新卡片；前端的差异高亮只是便利，判定以服务端为准。
3. 续期门、争议卡、暂停与恢复随 M1：图服务返回 `not_enabled` 时如实显示“暂不可用”；暂停与恢复没有做按钮。
4. 能否批准只听卡面的 `approve_enabled`，与 `pd` 一致；r2 而没有回退声明时，卡头另挂“r2 · 未声明回退”的徽章，回退一节醒目提示，但不自己再加一道禁用。**裁决（004-8、005-3）已落实**（P2-2）。
5. “无证据根”由图服务按整条前提链给出（`no_evidence_root`）；检视只读这个字段，不自己算。**裁决（005-4）已落实**（P2-1）。
6. 人的令牌只存在本标签页的 `sessionStorage`，带到期时间（缺省 8 小时），只随写请求发出；到期即清，界面回到只读。旧版本留在 `localStorage` 里的令牌读一次就删，不再沿用。**裁决（005-6）已落实**（P2-2）。
7. 模板目录的 `data`：**裁决**把暂行字段名定为约定，即 `fields.scope`、`fields.goal`、`fields.budget`、`fields.materials`、`judges`；取不到就留空，目录为空时用“不用模板”。

## 工作台（设计：`docs/design/web-workbench-v1.md`；待裁决的出入：`docs/m0/dissent-web-workbench.md`）

- **今日**（`/`）：读 `/v1/problems`（每 5 秒，页面不可见时跳过）。标题写成结论句（几件事等你拍板），紧接着是等你处理的清单（唯一焦点，没有待办时整块不出现）；下面运行中，右栏概况四格（不含等你处理，那个数只在标题与侧栏徽章里）、近七日、最近完成。进行中卡片列在途租约的种类（服务端的 `active`），不推断“阶段”；Goal 根结论取 `goal_level`；待人处理数取 `human_todo`；墙钟取 `wall`。最近完成按终态三值筛。今日解题与近 7 日趋势按 `closed_ts` 在本机时区分日计数，成功率 = solved ÷ 当天已关题数；本机时钟由 `app/clock.ts` 注入，视图层不读时钟。
- **待办**（`/inbox`）：读 `/v1/problems`（每 8 秒），对 `human_todo > 0` 的在跑任务再读 `/work` 的 human 项，按任务分组；类别取服务端的 `why`，“去处理”带 `node=<target>` 进工作区。链头或待办数变了才重读 `/work`。
- **任务库**（`/problems?q=&terminal=&judge=`，别名 `/tasks`）：终态用页签切换，搜索与筛选都在 URL 里。标签、难度、领域要 Problem 新字段，暂缺。
- **主题**：跟随系统、亮色、暗色、高对比，写在 `<html data-theme>`，存本机 `paoding.theme`。等级与终态仍是形状记号加文字，颜色不承载信息。
- **开题向导**（`/new`、克隆 `/new?from=<pid>`）：四步——要做什么（基本信息与材料）、怎么算做完（判据）、能动用什么（授权）、花多少（预算、初始提示与复核），即 HMI §3.2 的四步各占一页，基本信息并入第一步、复核并入最后一步。右侧“任务单”随草稿实时变化，只回显草稿内容与服务端的画像预览，不推导任何量。材料可以是文件、文字或网址（网址只当文字存，`text/uri-list`，不抓取）；文字类材料在提交时先 `PUT /v1/blobs`（本机核对哈希）再进开题批次。初始提示在开题成功后作为第一条 Hint 提交，不进开题批次。草稿存本机 `paoding.wizard_draft`，提交成功即清。克隆从原题的 `status`、`budget`、材料登记预填，材料按哈希重新登记为 input 类。
- **导入**（`/import`）：JSON（数组或 `{problems: [...]}`）与 CSV（列映射：id、题名、目标陈述、题面文字）在本机解析成草稿，没写的字段取自所选模板；逐题走与向导相同的 `app/submit.ts`，逐题显示 seq 或拒绝码。YAML 暂不支持。
