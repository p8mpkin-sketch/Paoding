## 附录：解题过程对照庖丁核心原则（逐条验证）

> 用第一轮全栈真实测试的 232 条事件日志逐条对照。结论：五条红线全部守住，两条核心理念得到实证，一条暴露已知边界。

### 红线 1「写入路径无模型」——实证守住

232 个事件的写入者全部是确定性代码：
- `lease ← sinan`（调度器）
- `register_artifact ← executor`（采集器）
- `add_fact ← adapter/reason`（校验后转发模型的提议）
- `judge_verdict ← judge`（判定器）
- `close_problem ← graph`（图服务自己）

模型说了什么从来直接写不进去——它只能通过 `submit` 提议，图服务校验后落账。

### 红线 2「反幻觉不变量」——实证守住，而且救过一次场

- 模型不能直接报告"完成"——必须走 `claim_done` → `exact_match` 判定器 → 核对值比对 → 通过 → 图服务关题。第一轮测试里模型反复找到答案但**没有一条捷径让它自报成功**，这正是当初设计的意图
- 证据只认执行环境采集的 Artifact——模型自己写的"我看到 X"不算数

### 红线 4「删简律与官知止」——实证运行

未到里程碑的结构全部带开关躺在配置里（市场分配、跨题记忆、旁观会话），M0 只启用了清单上的部分。在岗的官都在履职：哮天犬真的在告警上游服务失败率（`backend_unhealthy, fail_rate: 0.6`）。

### 红线 5「诚实对照」——第一批真实读数

| | B1（裸 CLI） | B1b（全栈） |
|---|---|---|
| 成本 | ~$0.01 | $0.011–0.012 |
| 耗时 | 26s | 30–90s |
| 可审计/独立判定 | ✗ | ✅ |

外壳税 10–20%——按规格 §8.3 的 G2 标准（≤3×）大幅达标。架构没有把简单事情变昂贵。

### 「吾生有涯」——预算真的在管钱

预留 500 毫美元/租约、释放、`budget_mark` 事件全程记录。首轮 $0 是计量缺陷（已修），修后的 $0.012 是真实数据。

### 「依乎天理」——画像推导正确

画像 `{partial, hard, r0}` 是推导出来的：外部资源 → partial；廉价判定器 → hard；最高风险 → r0。不是人填的，也不是模型自报的。

### 「薪火相传」——从口号变成物理事实

232 条事件 + 按题哈希链，整个过程可以完整回放。"个体会死，图存续"得到了实证。

### 已知边界（诚实清单）

- **「怵然为戒」（r2 审批门）未被真实触发**——M0 题目只有 r0 规则，审批门、豁免、凭据按次发放已实现但未接受真实数据检验。它们将在 M4 的运维场景首次真实运作。这是已知边界，不是缺陷。
