# 异议报告 006：执行层出站闸门与访问摘要

日期：2026-11-18。来源：质量提升第一阶段的 P0-4（出站白名单做到端口级）与 P0-3（堵恒真谓词）。对应实现见 `executor/SPEC.md` 的"出站闸门"与 `judgebox/SPEC.md` 的"恒真谓词与 `require_touch`"。第 1–3 项来自 P0-4，第 4–6 项来自 P0-3。

每项给出：规格怎么写、实现时碰到的不清楚之处、这次采取的做法、请裁决的问题。在裁决之前，实现按"采取的做法"运行。

## 1. 没写端口的 `net` 规则

- **规格**：§3.1.1 的 `scope.pattern` 是字符串，内核不解释；§3.6.2 的 `egress_allow: string[]`；HMI 设计 §3 的例子写的是 `"<主机>:<端口>"`。`compile.py` 原先的注释写"pattern 是 host 或 host:port"。
- **不清楚之处**：只写主机名的规则是什么意思。读成"整台主机全部端口"，就又回到了审计指出的问题（同一容器的端口要么都通要么都不通）；而且闸门是逐端口监听的 TCP 转发，没有"全部端口"这一档。
- **采取的做法**：`net` 规则的 `pattern` 必须是 `host:port`（端口 1–65535）。没写端口的规则在授权编译时报 `ScopeError`，会话与判官容器起不来（判官一侧记 `inconclusive(env_error)`），不默认放行。
- **请裁决**：是否把 `host:port` 写进规格，并让图服务在 `open_problem` 与 `approve --scope-amend` 时就拒绝没写端口的 `net` 规则（现在要到起容器时才报错）。这需要内核经资源种类登记表校验 `pattern`，属于图服务的改动，本次没有做。

## 2. 闸门是 TCP 转发，目标端口没开时 `connect()` 仍然成功

- **规格**：§3.6.2 只说"出站白名单"，没有规定实现手段；任务书指定"出站代理容器（DNS + TCP 转发）作为唯一出口"。
- **不清楚之处**：TCP 转发在接受连接之后才去拨上游。目标端口没在监听时，执行容器看到的是"连接成功，随后被重置"，而不是"连接被拒"。只看 `connect` 返回值的端口探测会得出"端口开着"的错误观察。
- **采取的做法**：上游接不通时闸门立刻以 RST 关闭，并在逐连接记录里记 `ok=false`。没有去掉这个差异：要做到完全透明需要在闸门里做内核级转发（NAT 加包过滤），闸门就得带 `NET_ADMIN` 能力和包过滤工具，信任面更大，也更依赖宿主内核配置。
- **请裁决**：是否接受这个差异（并在任务包的工具说明里提醒"判断端口是否开放要读到数据为准"），还是要求改成内核级转发。提醒文字在 Adapter 的任务包里，本次没有改。

## 3. `actions` 里除 `connect` 之外的动作

- **规格**：`scope.actions: string[]`，内核不解释。现有题目与测试里出现过 `connect`、`*`、`read`、`write`。
- **不清楚之处**：`net` 资源上 `read`、`write` 这类动作指什么、由谁执行。TCP 转发分不出一条连接是"读"还是"写"。
- **采取的做法**：按任务书"`connect` 放行、其余拒绝"：闸门只为 `actions` 含 `connect` 或 `*` 的规则开端口。只写了别的动作的 `net` 规则不开任何通路（规则仍然交给闸门并记在它的启动记录里）。`workspace` 资源的 `actions` 仍然没有执行手段（工作区是整目录读写挂载），不在本项范围内。
- **请裁决**：`net` 资源的动作词表是否就定为 `connect` 一个；`*` 是否保留。

## 4. `require_touch` 对纯计算的题

- **规格**：§3.3.2："观察对象是外部资源时打开，纯计算时关闭，写在判官配置里。"
- **不清楚之处**：判官配置是全局的一份（`judges.d/replay.yaml`），而一道题是不是纯计算是题目的属性。任务书要求把默认值改成打开；照字面全局打开，只有 `workspace` 规则的题（例如全栈冒烟用的算术小题）里每一次重放都没有任何可碰的东西，全部变成 `inconclusive(untouched)`，这类题就走不通了。
- **采取的做法**：配置默认打开；判官在运行时再看题目的授权范围：有外部资源（资源种类登记表里 `external` 为真的，与画像推导同一张表）才要求，没有就不要求。没登记过的资源种类按外部算（宁严）。
- **请裁决**：是否认可"配置打开 + 按题目授权范围生效"；还是要每道题在开题时显式选择（那需要 `Problem` 或 `Check` 增加字段，属于图服务的改动）。

## 5. 没碰过资源、谓词又不成立的重放

- **规格**：§3.3.2 说没有访问任何资源时"裁决为 `inconclusive(untouched)`"；§3.3.5 第 8 条只举了打印常量（谓词成立）的例子。
- **不清楚之处**：重放没碰任何资源，同时谓词不成立（例如读一个洁净容器里不存在的文件）时，是判定性的 `fail`（论断被证伪，等级到 X），还是 `untouched`。
- **采取的做法**：一律 `untouched`。没碰过观察对象的运行，对它成立与否都说明不了什么。影响：在有外部资源的题上，"伪造的工作区文件过不了重放"这类情形从"证伪"变成"无结论"，论断停在 E0 而不是 X；它仍然到不了 E3。原有的伪造文件测试改用纯计算题，行为不变。
- **请裁决**：是否认可；或者规定"没碰过且谓词不成立"仍判 `fail`。

## 6. 哪些东西算"碰过"

- **规格**：§3.2.2 `touched`："连到过的授权目标、按哈希挂入的输入"；§3.3.2："没有访问任何授权资源、input 材料或挂入的可采信 Artifact"。
- **不清楚之处**：(a) 连接到了闸门、但目标端口没开，算不算"连到过"；(b) "可采信"的类别是 `exec`、`judge`、`input`，而一条 `echo ok` 的输出本身就是 `exec` 类，把它当候选挂进去就能满足字面要求；(c) 规格脚本自己也是按哈希挂入的。
- **采取的做法**：(a) 算，它确实去碰了授权范围内的地址，"端口没开"是关于这个资源的观察；白名单外的连接不算。(b) 挂入的候选只在自身有出处时算：`input` 类算，`exec` 与 `judge` 类要求自身访问摘要非空，`authored` 类不算。(c) 规格脚本不算。M0 的重放只挂规格与候选两样，题目材料还没有挂入洁净容器的途径，所以"input 材料"目前只经候选这一条路出现。
- **请裁决**：三条是否认可；题目材料是否需要一条挂入洁净容器的途径（否则有外部资源的题上，只依赖材料的纯计算观察到不了 E3）。
