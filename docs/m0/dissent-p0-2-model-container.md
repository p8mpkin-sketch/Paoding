| 1 | 修复说明第 3 步写“模型容器接入与执行容器相同的 `--internal` 网络”。按字面是同一张网络，那么代理与工具端点要在那张网络上可达，执行容器就连得到模型端点；模型容器也与授权目标同网。这与 3.6.4 的 4（“执行容器连不上模型端点；模型容器连不上授权范围内的目标”）和 §3.4.2（“出站只放行工具端点与模型端点代理”）相抵。Reason 会话也没有执行容器，没有那张网络可接 | 读作“同一种网络”：每个会话另起一张 `--internal` 网络，上面只有模型容器与端点中继。执行容器的网络（P0-4 的闸门方案）不受影响，两边互不依赖 | 确认；若确要同一张网络，需要先改 3.6.4 的 4 |
| 2 | 端点代理与工具端点是 Adapter 进程里的本机服务，规格没写内部网络上的容器怎么到达它们 | 每个会话一个端点中继容器（通用 Python 镜像加一个只用标准库的转发脚本），经只读挂载的 Unix 套接字连回 Adapter 进程。端点仍只监听本机回环。没有采用“端点监听网桥地址”：那样宿主上监听全部接口的服务对模型容器也可达 | 确认；或把端点代理与工具端点本身做成容器（改动更大） |
| 3 | 内部网络默认仍能到宿主在网桥上的地址 | 建网络时加隔离网关（`gateway_mode_ipv4=isolated`，Docker 27.1 起）。老版本不认这个选项时退回普通 `--internal`：仍无出站，但宿主上监听全部接口的服务可达 | 是否把 Docker 27.1 定为最低版本，不认就拒绝启动 |
