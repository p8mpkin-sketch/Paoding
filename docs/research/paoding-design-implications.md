# 调研对“庖丁”架构设计的启示

> 基于 [agent-architecture-survey.md](agent-architecture-survey.md) 的调研结论，以及对一份“黑板架构攻防智能体集群”设计思考的评审。
> 本文是进入架构设计前的方向性思考，不是最终方案。日期：2026-11-16。

## 0. 一句话

**庖丁 = 一个很薄的通用求解内核 + 一块以“证据梯”为核心的共享状态 + 按场景插拔的领域包，每个领域包必须自带判官。**

“依乎天理，批大郤，导大窾，因其固然”：先看清问题的结构（有没有判官、信息全不全、动作可不可逆），再决定用什么刀法。

---

## 1. 定位：收口类问题，以判官为中心

庖丁只承诺解决**收口类**问题：目标可以被判定，答案可以被验证。这既是能力边界，也是设计的出发点。

每个任务进入系统时先做**问题画像**，回答三个问题：

| 维度 | 取值 | 决定什么 |
| --- | --- | --- |
| 判官类型 | 确定性（测试、旗标、证明检查、复现）／ 部分（指标恢复、规则校验）／ 无（只能靠共识和人） | 自主程度上限、证据梯能升到哪一级 |
| 信息完整度 | 完全（题面即全部）／ 不完全（需要探查） | 求解范式（见第 3 节） |
| 动作可逆性 | 可逆（沙箱、git）／ 有成本 ／ 不可逆（生产、患者） | 权限等级、是否需要人工闸门 |

画像结果决定后面所有配置。CTF 和数学是“确定性判官 + 可逆”，可以放手自主、大量并行；医学和运维是“部分或无判官 + 不可逆”，必须保留人在回路。

## 2. 核心抽象：证据梯

调研中医学（AMIE、MAI-DxO）、CTF（攻击树）、运维（根因假设）三个场景的有效系统，都显式维护了“带置信度的假设集”。评审的那份设计把它发展成了证据梯，这是值得庖丁直接采纳的核心。

### 2.1 等级定义（草案）

| 等级 | 名称 | 升级条件 |
| --- | --- | --- |
| L0 | 猜想 | 任何智能体提出，附理由 |
| L1 | 有支持 | 有至少一条可追溯的观察支持（工具输出、文献、日志） |
| L2 | 独立支持 | 由**不同上下文**（最好不同模型或不同方法）的智能体独立得到支持 |
| L3 | 判官确认 | 通过确定性判官（跑通、复现、旗标被接受、证明通过） |
| ✗ | 已证伪 | 有反例或判官否定，保留理由，作为负知识 |

### 2.2 关键规则

- **高层只认判官，不认共识。** 同一模型的多个智能体犯的错是相关的，“多次认同”不能升到 L3。没有确定性判官的场景，证据梯最高停在 L2，并且输出必须带置信度。
- **证伪和证实同等重要。** 被证伪的路径要保留并被检索，防止其他智能体重复踩坑（对应 Manus 的“保留错误”、CTFExplorer 的失败记录交接）。
- **每条证据都可追溯。** 指向原始观察（命令、输出、文件），便于审查和复盘。
- **允许输出“未解决”。** 最终产物可以是“已排除路径 + 当前最可信假设 + 置信度”，这是合法结果。

## 3. 两种求解范式，同一个内核

| 范式 | 适用 | 典型循环 | 规划形态 |
| --- | --- | --- | --- |
| 假设驱动的序贯探查 | CTF 侦察、医学诊断、运维排障 | 维护假设集 → 选信息增益与成本比最高的下一步 → 观察 → 更新证据梯 | 假设集 + 攻击树／排查树 |
| 搜索加验证 | 数学、写代码、构造利用 | 生成候选 → 判官检验 → 失败反馈 → 修正或换路 | 分解（引理、子任务）+ 并行多路 |

两者共享内核和证据梯，差别在领域包提供的策略提示和判官。

## 4. 内核做薄，外壳做厚

调研最一致的结论：循环本身不值得创新，100 行的 bash 智能体离榜首只差几个百分点；差距在外壳。所以：

- **工作者内核**：标准的“收集上下文 → 行动 → 验证”单循环，尽量复用成熟实现，不自研花样。
- **外壳投入重点**：
  - 上下文工程：状态落盘、可恢复压缩、目标复述（待办清单）、工具输出降噪。
  - 工具接口：清晰描述、防呆参数、报错里写修复办法。
  - 判官与验证器：每个领域包的第一优先级。
  - 预算：步数、token、金钱、对目标的请求频率都有硬上限，并在 50%／80% 预算处触发反思。
- **为删除而设计**：每一块为弥补当前模型短板而加的结构，都要能单独关掉。D-CIPHER 式的复杂分工一年内就被“强模型 + 简单外壳”超过。

## 5. 多智能体：单写者，多贡献者

评审的设计里最大的风险是“上千智能体并行写黑板”。调研给出的原则是**写入单线程，智力可并行**。

### 5.1 写入路径

- 共享状态采用**只追加的事件账本**（参考 OpenHands 的事件溯源）。智能体只能提交“提议”（新假设、新证据、证伪），不能直接改状态。
- 由**仲裁者**（可以是确定性规则 + 必要时一个模型）把提议合并进证据梯，处理冲突和重复。
- 这样调度者和仲裁者都是无状态的，可以多实例，避免单点瓶颈，同时保证一致性。

### 5.2 角色（全部可开关，用消融决定去留）

| 角色 | 作用 | 调研依据 |
| --- | --- | --- |
| Solver（求解者） | 主力推进 | 所有系统 |
| Falsifier（证伪者） | 用**干净上下文**专门找反例 | MAI-DxO 的质疑医生、Cognition 的审查者 |
| Reviewer（审查者） | 检查证据链和最终报告 | Mythos 的验证智能体、XBOW 验证器 |
| Free-form（自由探索者） | 换角度、换模型，提供多样性 | Atlantis 的正交 N 版本、Co-Scientist 的邻近聚类 |
| Infra（基础设施） | 把重复劳动沉淀为可复用服务 | Theori 的输入编码器复用 |
| Scheduler（调度者） | 分配预算、识别死胡同、对接人类 | XBOW 协调者、清华战队的规划者 |

### 5.3 扩展原则

- **并行靠多样性，不靠复制。** 不同模型、不同策略、不同起点；同模型同提示的副本收益很低。
- **规模逐级放大并测量。** 先证明 3–5 个智能体比 1 个好，再谈几十、上千。CTFExplorer 的数据显示加预算、加智能体常常只是让死胡同变长。
- **识别死胡同。** 一条路线在若干次尝试后没有让任何证据升级，就降低其优先级或交给批评者。

## 6. Infra 智能体与共享服务

评审设计里的 infra agent 思路正确，但要加约束：

- 只有被**多次重复**的工作才服务化（侦察结果、输入编码器、环境搭建脚本、知识库检索）。
- 服务要有**版本、测试和所有者**，否则一个错误的共享服务会污染所有使用者（Atlantis 的字符串启发式事故）。
- 服务化的产物本质上就是**技能 + 工具**，与领域包用同一套机制管理。

## 7. 领域包

每个场景一个领域包，内核不含任何领域逻辑。领域包必须包含：

1. **判官**（必选）：怎样确定性地判定对错。
2. **技能**：领域知识与流程，按需加载。
3. **工具**：MCP 或脚本。
4. **画像默认值**：自主程度、权限、预算。
5. **评测集**：带检查点的部分得分。

建议第一个领域包是 **CTF**：判官明确、环境容易搭、参考实现最多、你已有积累。数学作为第二个，用来验证“搜索加验证”范式。

## 8. 安全与权限

- 沙箱按风险分级：bwrap／容器为基线，内核利用或强对抗用虚拟机。
- 网络默认隔离，按白名单放开；对目标的请求速率由确定性调度器控制。
- 动作风险分级 + 确认策略；不可逆动作（生产变更、对真实系统的攻击）必须有硬闸门，不能只靠提示词。
- 第三方技能、外部协作模型的输出一律视为不可信数据。

## 9. 评测从第一天开始

- 自建小型评测集（20–50 题起步），按检查点给部分分。
- 每个可选组件都要有消融：去掉 falsifier、free-form、infra 后，解题率和成本各变化多少。这也是“闲人智能体有用”这类主张唯一有说服力的证据。
- 全量轨迹追踪，记录每条证据的来源和升级过程。
- 跟踪单题成本，和单智能体基线对比。

## 10. 需要你拍板的问题

| 问题 | 倾向 | 理由 |
| --- | --- | --- |
| 自研内核还是基于现成外壳 | 工作者内核复用现成（如 Claude Agent SDK、OpenHands SDK），自研证据梯、账本、调度和领域包 | 价值在外壳和共享状态，不在循环 |
| 证据梯 L3 是否只认确定性判官 | 是 | 否则共识会冒充证据 |
| 多智能体写入方式 | 只追加账本 + 仲裁者 | 避免并行写入冲突 |
| 首个领域包 | CTF | 判官明确、积累最多 |
| 并行规模目标 | 先 1 → 5 → 20，用数据决定是否继续 | 现有证据不支持直接上千 |
| 已有的 8 万行代码怎么用 | 作为参考实现拆解，挑出证据梯、infra、沙箱等经过验证的模块迁移 | 避免继承未经测量的复杂度 |

## 11. 下一步建议

1. 把第 2 节的证据梯和第 5.1 节的账本写成正式规格。
2. 搭最小可运行版本：1 个求解者 + 1 个证伪者 + 证据梯 + CTF 判官。
3. 建 20 题 CTF 评测集，跑出单智能体基线。
4. 在基线之上逐个加角色，用消融决定去留。
