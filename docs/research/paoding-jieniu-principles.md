# 庖丁解牛：逐句提炼与基座对账

> 状态：研究笔记（2026-11-17），不是规格变更。可补的设计点在第 4 节，人逐条裁决后才写进[基座规格 v1.1](../design/base-layer-spec-v1.md)。
> 原文：《庄子·内篇·养生主》。释义取通行注本（郭象注、成玄英疏、俞樾说），有异读处注明。
> 标注沿用规格：`[观点]` 作者判断，`[假设]` 待 M0/M1 验证；规格条目写作"规格 3.1.2"。本文不引入新的调研编号。

## 0. 结论

1. 这个典故讲的不是"刀快"，而是**同一把刀、不同的用法，磨损相差两个数量级以上**：族庖月更刀，良庖岁更刀，庖丁十九年不换。换成庖丁的语言：同一个模型，架构决定每解一题的成本。这正是规格 M1 首轮"所有角色与瘦基线同模型"（规格 4.2）和北极星"每解出一题的成本"（规格 §7）的立意。
2. 原文可以提炼出 12 条原理。对账结果：6 条已在 v1.1 里有确定性的落点，5 条部分体现，1 条是结构性缺口。
3. 已体现的部分最扎实的是三处："依乎天理，因其固然"对应画像推导与带判据的 Intent；"以无厚入有间"对应按风险注入能力与外壳税 B1b；"所解数千牛而刀刃若新"对应 M3 的"内核零改动接入第二个领域"。
4. 最大的缺口是**"每至于族"**：规格的谨慎只按**风险**（可逆性）分级，没有按**难度**分级。遇到难点时，原文的做法是收拢、减速、小刀，规格现有的一条规则（卡住的 Intent 开 `race_k` 条竞速路线）方向相反，另一条（失败两次升强档）相当于换一把更重的刀去砍骨头。
5. 可补的设计点共 6 条（第 4 节），都不进写入路径，不调用模型，4 条是日志上的投影或司南规则表的几行。优先级最高的是 D1"族"标记和 D2 折损账。

## 1. 原文

篇首定下全篇的约束，庖丁解牛是它的例证：

> 吾生也有涯，而知也无涯。以有涯随无涯，殆已！……缘督以为经，可以保身，可以全生，可以养亲，可以尽年。

庖丁解牛全文，按语义切成 12 句，编号即下文的 Q#：

| Q# | 原文 | 释义 |
| --- | --- | --- |
| Q0 | 吾生也有涯，而知也无涯。以有涯随无涯，殆已 | 生命有限而可知者无限，以有限追无限，必然困竭 |
| Q0′ | 缘督以为经 | 顺着中间那条脉（督脉）作为常道，不走两端 |
| Q1 | 庖丁为文惠君解牛，手之所触，肩之所倚，足之所履，膝之所踦 | 手、肩、足、膝各有分工，同时作用（踦：用膝顶住） |
| Q2 | 砉然向然，奏刀騞然，莫不中音，合于《桑林》之舞，乃中《经首》之会 | 皮骨相离、进刀的声响都合乎音律，动作合乎乐舞的节拍（向：响；会：节奏） |
| Q3 | 嘻，善哉！技盖至此乎？ | 文惠君赞叹的是"技" |
| Q4 | 臣之所好者道也，进乎技矣 | 我追求的是道，已经超出技了 |
| Q5 | 始臣之解牛之时，所见无非牛者。三年之后，未尝见全牛也 | 起初眼里是一整头牛；三年后看到的只是结构与间隙，不再是浑然一体的牛 |
| Q6 | 方今之时，臣以神遇而不以目视，官知止而神欲行 | 如今以心神接触而不靠眼看；感官的作用停下来，心神在运行 |
| Q7 | 依乎天理，批大郤，导大窾，因其固然 | 顺着天然的肌理，劈开大的缝隙，引刀进入大的空处，完全依照牛本来的结构（郤：隙；窾：空） |
| Q8 | 技经肯綮之未尝，而况大軱乎 | 经络相连、筋肉附骨之处都不去碰，更不用说大骨（"技"俞樾读作"枝"；肯：附骨之肉；綮：筋肉结合处；軱：大骨） |
| Q9 | 良庖岁更刀，割也；族庖月更刀，折也。今臣之刀十九年矣，所解数千牛矣，而刀刃若新发于硎 | 好厨师一年换刀，因为是割；普通厨师一月换刀，因为是砍。我这把刀用了十九年，解了几千头牛，刃口像刚从磨刀石上磨出来（族：众；硎：磨刀石） |
| Q10 | 彼节者有间，而刀刃者无厚；以无厚入有间，恢恢乎其于游刃必有余地矣 | 骨节之间有缝，刀刃几乎没有厚度；没有厚度的刀进入有缝的骨节，宽绰而有余地 |
| Q11 | 虽然，每至于族，吾见其难为，怵然为戒，视为止，行为迟。动刀甚微，謋然已解，如土委地 | 即便如此，每到筋骨交错聚结之处，我看出它难办，就警惕起来，目光专注，动作放慢，下刀极轻，哗啦一下牛体解开，像泥土散落在地（族：交错聚结处，与 Q9 的"族庖"异义） |
| Q12 | 提刀而立，为之四顾，为之踌躇满志，善刀而藏之 | 提刀站起，环顾四周，从容自得，把刀擦拭干净收起来（善：通"缮"，拭） |
| — | 善哉！吾闻庖丁之言，得养生焉 | 文惠君从中领悟的是养生，即如何让有限的生命长久运转 |

## 2. 提炼的原理

每条原理写成可以对设计提要求的句子。括号里是来源句。

| P# | 原理 | 对智能体的要求 |
| --- | --- | --- |
| P1 | **有涯随无涯，殆**（Q0） | 搜索空间无限、预算有限。预算是硬约束而不是参考值；在无望的方向上停止花费本身是一种能力 |
| P2 | **缘督以为经**（Q0′） | 先走中间那条最可能的主线，再视情况加厚；既不一上来就铺开编队，也不死守单次尝试 |
| P3 | **分工协同，动作有即时的回响**（Q1、Q2） | 各部件各管一件事；每个动作当场产生可感知的反馈（"砉然向然"），整体有可审计的节拍 |
| P4 | **道进乎技**（Q3、Q4） | 底座承载与具体刀法无关的原则；刀法（领域知识、技巧）可以替换，原则不随刀法变 |
| P5 | **由见全牛到未尝见全牛**（Q5） | 先把问题从一个整体变成带关节的结构，再动手；分解是第一步，而不是边砍边看 |
| P6 | **以神遇，官知止而神欲行**（Q6） | 熟练之后，逐项的显式检查让位于内化的判断；显式的管控在需要的地方才出手 |
| P7 | **依乎天理，因其固然**（Q7） | 切口由问题本身的结构决定，不由执行者的偏好决定；先大缝后小缝 |
| P8 | **不碰肯綮，更不砍大骨**（Q8） | 遇到硬阻力绕开，换缝隙，而不是加大力量硬砍 |
| P9 | **割与折：磨损由方法决定，不由工作量决定**（Q9） | 衡量工具的磨损，并把磨损区分为正常消耗（割）与错误用法造成的折损（折）；比较方法时刀相同 |
| P10 | **以无厚入有间，游刃有余**（Q10） | 介入的厚度必须小于问题留出的间隙；每次动作只带完成它所需的最小能力，并保留余量 |
| P11 | **每至于族：识难、警惕、专注、减速、微动**（Q11） | 难点要被识别出来；在难点上收拢注意力、放慢节奏、缩小每一步，直到关键关节解开，其余随之瓦解 |
| P12 | **四顾、满志、善刀而藏**（Q12） | 完成后先环顾检查周边，再收尾；把刀擦净收好，不在完成后继续挥刀；下一头牛开始时刀仍如新 |

## 3. 对账：原理在 v1.1 中的落点

判定分三级：**已体现**，指规格里有确定性的机制和验收；**部分**，指有机制但只覆盖一部分，或推到了 M4 之后；**缺口**，指规格里没有对应机制。

| P# | v1.1 中的落点 | 判定 | 说明 |
| --- | --- | --- | --- |
| P1 有涯 | 预算账本：租约预留、硬顶由端点代理执行（3.5.2）；50%/80% 预算复盘期；续期门（无判官确认的进展就不再开新探索）；题预算取瘦基线 3 倍（§10 #9） | 已体现 | 续期门就是"以有涯随无涯，殆"的机械形式。规格 4.1 引用的"追加会话多半只让死胡同变长"是同一判断 |
| P2 缘督 | 先瘦后厚：Bootstrap 的预算正好是一次完整的瘦基线运行，解不出才进厚路径（4.1 规则 1） | 已体现 | 易题上成本倍数约为 1 [假设] |
| P3 协同与回响 | `submit` 当场返回校验结果与 30 秒内的裁决（3.4.2）；事件日志与哈希链（3.1.2）；角色白名单由租约强制（4.1） | 已体现 | "莫不中音"对应同回合可见的拒绝码：错了当场改，不另起修复轮 |
| P4 道与技 | 红线 3 领域知识不进内核；锦囊承载领域内容（4.3）；T-0/T-1 两类结构（文首标注） | 已体现 | 可以把 T-0 读作"道"（模型再强也需要），T-1 读作"技"（下一代模型可能吃掉）。删简律就是"技可弃，道不弃" |
| P5 未尝见全牛 | 解牛图：Fact、Intent、依据边；Reason 是唯一的意图生成者（3.1.1）；带判据的 Intent"把题目沿可判定的关节切开"（§2） | 已体现 | 规格自己已经用了关节的说法 |
| P6 神遇 / 官知止 | 消费时验证：r0 的 Intent 只要前提非 X 即可放行，验证在被有风险的动作消费时才触发（3.1.3）；写入路径无模型（红线 1） | 部分 | 分工是对的：确定性代码管"止"，模型管"行"。但"神遇"还指经验的内化，即系统从厚路径逐步退回薄路径，这一半见 P12 与 D6 |
| P7 依乎天理 | 画像由判官与授权范围推出，人不填、模型不自报（3.1.2"结构自识"）；扇出规则按画像分广度优先与深度优先（4.1） | 部分 | "因其固然"在**题目一级**已经机械化。**Intent 一级**的切口由 Reason 决定，规格没有度量切口切得准不准，见 D3 |
| P8 不砍大骨 | Goal 判定有次数上限、失败只返回原因类别（5.2 场景 3）；Intent 失败两次放弃（3.1.2）；证伪后依赖的 Intent 自动放弃（剪枝，8.4 `pruned`） | 部分，且有一处反向 | 4.2 第 4 条"同一 Intent 在中档失败两次后升到强档重做"，在原文的框架里是"换一把更重的刀砍同一块骨头"。见 D2 |
| P9 割与折 | 北极星是每解出一题的成本（§7）；同模型对照（4.2 第 1 条、8.3 执行规则 2）；归因表记录每个 T-1 结构名下的花费（8.4） | 部分 | 族庖、良庖、庖丁正好是"同刀不同法"的三臂对照，规格的 Bk、B1、庖丁同构。缺的是把花费区分为"割"与"折"，见 D2 |
| P10 以无厚入有间 | 执行容器按 Intent 的风险注入能力，低报风险的后果是容器里没有它要的能力（3.6.1）；任务包三层视图、长输出留在 Blob 仓库按引用取回（3.4.2）；外壳税由 B1b 单独量出（8.3）；任务软线 90% 留出一轮收尾（3.5.2） | 已体现 | 外壳税就是"刀刃的厚度"：外壳比模型能力留出的间隙还厚时，它就是净损失。规格要求外壳税超过 5 个百分点先改工具面，正是"刀要无厚" |
| P11 每至于族 | 按风险分级的消费门（r1 要 E1 无争议，r2 要 E3 加人批准）；裁决翻转需连续两次一致（A6）；`unstable`、`disputed`、`premise_lost` 等派生标记；剩余预算低于 20% 时并发 1 | **缺口** | 这些机制各自存在，但没有被组合成"识别难点并改变行为"的一条通路。谨慎只随**风险**升级，不随**难度**升级。见 D1 |
| P12 四顾与善刀 | Goal 到 E3 时自动关题、取消其余租约、销毁容器（3.1.2、6.1 第 15 步）；任务结束令牌作废（3.5.5）；判官的守护项（5.2 场景 3）；复盘与锦囊发布要人审、按哈希签名、只读挂载（4.3） | 部分 | "善刀而藏"已到位：收刀即停花费，刀（容器、令牌）不留到下一题。"四顾"只在指标类判官的守护项里有，r1/r2 题关闭前没有一张确定性的收尾清单，见 D5。复盘管线在 M4，见 D6 |

另有一条不是缺口、而是规格已经做到原文之外的地方：庖丁的"以神遇"不可检验，基座则规定 E3 的含义是"回路里没有模型"（3.3.1）。所以本文只把"神遇"类比为**探索与规划**，从不类比为证据，见第 5 节。

## 4. 可补的设计点

六条都满足：不进写入路径、不调用模型、带开关或本身是观测投影、领域中立。标签沿用规格的 T-0/T-1。

### D1 "族"标记：按难度收拢，而不只按风险（P11）

**现状。** 规格里已经有难点的各种信号，散在不同章节：同一 Intent 已失败一次（`attempt`）、前提带 `disputed` 或 `unstable`、在途租约收到 `premise_lost`、单个事件引发影响面告警（3.1.3）、同一操作连续被拒（3.4.4）。它们各自只触发局部动作（复判、取消、停止转发），司南的扇出规则（4.1）不读它们。司南对卡住的 Intent 的规则是开 `race_k` 条竞速路线，即在难点上**加宽**。

**提案。**

1. 图服务派生一个标记 `knot`（族），挂在 Intent 上。它是这些已有信号的析取，纯函数，与 `disputed`、`unstable` 同类：

   ```
   knot(i) := i.attempt ≥ 1 且上次结束为 failed 或 nothing
            ∨ ∃p∈i.premises: disputed(p) ∨ unstable(p)
            ∨ i 的在途租约带 premise_lost
   ```

2. 司南的规则表（4.1）加一行，在 `race_k` 之前生效：

   | 输入 | 规则 |
   | --- | --- |
   | Intent 带 `knot` | 视为止：并发 1，不开竞速路线。行为迟：先由 Reason 拆出一个 r0 的观察类 Intent（"先看清这一处"），带判据，预算为原 Intent 的一半以下。动刀甚微：原 Intent 在观察 Intent 达成之前不再认领 |

3. `race_k` 竞速保留给**不带** `knot`、只是慢的 Intent（深度优先下长时间无进展）。

**为什么不是直接沿用风险。** 风险描述动作的后果，难度描述对象的不确定。r0 的题（CTF、数学）没有任何风险升级，但难点集中在少数几个关节上。现在这类题在难点上的唯一反应是多开路线 [观点]。

**代价与验证。** 内核增加一个派生标记，约十行；司南规则表一行。T-1，开关 `knot=off`。M1 的消融臂只跑难段 8 题。原文是一条操作经验，不是证据；"收拢优于加宽"是 [假设]，可能在判官廉价的题上不成立（候选交给判官筛的成本很低），所以规则表里 `judge=hard 且判官廉价` 一行优先于本行。

### D2 折损账与"换缝优先于换刀"（P8、P9）

**现状。** 归因表（8.4）按结构记花费，回答"这个结构有没有用"。它不回答"钱花在割上还是折上"。4.2 第 4 条规定 Intent 在中档失败两次后升强档重做。

**提案一：折损账（T-0，日志投影）。** 每题关闭时，归因记录增加一个字段：

```ts
wear: {
  cut:   Budget,   // 割：产出了被判官确认的对象（E3 论断、达成的带判据 Intent），或产出的排除结论被下一轮 Reason 引用
  break: Budget,   // 折：以下任务的花费
  break_by: Record<"no_output"|"stalled"|"budget_killed_empty"|"reject_loop"|"scope_violation"
                   |"flaky_rejudge"|"repeat_same_intent", Budget>
}
```

"折"的七类都已经是日志里的事件或释放结果（3.4.4、3.5.4、3.6.2、3.3.4），投影不需要新数据。M1 报告里与成本倍数并列报告 `break ÷ 总花费`，也就是"更刀的频率"。良庖与族庖的区别在于折，不在于割；同理，庖丁对 Bk 的成本优势如果存在，应当体现为折损率更低 [假设]。

**提案二：换缝优先于换刀（T-1，改 4.2 第 4 条的次序）。** Intent 第一次失败后，不直接在同一个 Intent 上升档，而是先让它带上 `knot`（D1），由 Reason 读到失败原因和折损类别后决定：换切口（新 Intent，前提或方法不同），或者显式标注"同一切口，升档重做"。后者再按 4.2 第 4 条执行。

规格为升档引了"弱模型向强模型求助"的证据（4.2 第 4 条），所以这里不是否定升档，而是把它从默认动作改为 Reason 的一个选项。两种次序做成一条消融臂（`escalate=first|after_reroute`）。

### D3 切口命中率（P5、P7）

**现状。** 带判据的 Intent 让切口可检验，但规格不统计 Reason 切得准不准。归因表只看结构是否在解题链上。

**提案。** 归因记录增加三个计数，均为投影：带判据的 Intent 中达成的比例；达成者中在解题链上的比例；因前提被证伪而放弃的比例。前两个低说明切口不在关节上（"见全牛"，按自己的想象下刀），第三个高说明切口建立在没有核实的前提上。

这三个数是 Reason 角色提示与锦囊质量的读数，也给 §10 第 6 条"续期门的进展谓词会不会被琐碎观察满足"提供旁证：如果达成率高而在链上的比例很低，说明 Intent 在切容易而无关的地方。T-0，无开关，M1 随归因表一起做。

### D4 关节度：先切能解开最多的那一刀（P11 的"謋然已解"）

**现状。** 司南按 `expected_gain ÷ budget` 排序（4.1），`expected_gain` 由 Reason 填写，内核不解释。

**提案。** 图服务派生一个确定性的量 `unlocks(i)`：以 i 为前提（直接或经带判据的 Intent 传递）、当前处于 blocked 的 Intent 数。司南在同等条件下优先 `unlocks` 大的 Intent。它是"因其固然"的排序依据：取自图的结构，不取自模型的估计。

T-1，开关 `order=gain_only`。计算是一次反向可达，图规模在 10³ 到 10⁴ 节点时可忽略。它不改变资格，只改变先后，出错的最坏后果是浪费预算（与 4.1"资格与优先级分开"一致）。

### D5 四顾：关题前的收尾清单（P12）

**现状。** Goal 到 E3 时图服务自动 `close_problem`（3.1.2 操作表）。M0 只有 r0 题，这样做没有问题。r1/r2 题（运维、医学辅助）关题时，可能仍有生效的范围修订、签发过的 r2 凭据、解题链上带 `stale` 或 `disputed` 的论断。

**提案。** 对画像为 r1 或 r2 的题，`close_problem` 之前由投影生成一张收尾清单，确定性地列出：本题的范围修订与是否仍生效；签发过的 r2 凭据与是否已作废；解题链上的 `stale`、`disputed`、E3d 论断；守护项的最近一次结果。清单非空项为零时自动关题，否则题目进入 human 项，由人 `pd accept`。

它与 6.2 第 13 步已有的"报告写明根因为 E3d"同源，只是把它从报告文字变成关题条件。T-0，M4 与 r2 凭据按次签发一起做；M0 不需要。

### D6 由厚回薄：通鉴记录"这类牛用不用分解"（P6 的"以神遇"）

**现状。** 锦囊的使用记录只有使用题数与解出题数（4.3）。归因记录里有 `path: thin|thick`（8.4），两者没有连起来。

**提案。** 锦囊与画像的使用统计按 `path` 分开计。某个画像（或某个锦囊适用的题）累计足够多题、薄路径解出率不低于厚路径时，在报告里标出"该类题厚路径无增量"，由人决定是否对这类题把 `bootstrap_share` 调到 1（即只跑瘦路径）。

这是系统层面的"三年之后，未尝见全牛；方今之时，以神遇"：经验和更强的模型让分解变得不必要时，外壳应当自己退下来。它也是删简律在单个题类上的版本，比全局消融更细。T-1，统计部分在 M1 随归因表做（只是多一个分组键），自动建议在 M4 随通鉴做，调整始终由人确认。

## 5. 比喻在哪里失效

照搬一个比喻最大的风险是把它不具备的性质也带进设计。四处不成立：

1. **神遇不能当证据。** 庖丁的判断没有旁人复核，也不需要。基座的红线 2 要求证据来自执行层的可采信 Artifact，E3 要求回路里没有模型。所以"以神遇"只对应 Bootstrap 的直觉式尝试和 Reason 的规划，"官知止"只对应消费时验证放行 r0 的探索，绝不对应"熟练的模型可以免检"。
2. **牛是静止的，也不会反击。** 牛的结构不随时间变化，也不会诱导刀走错。庖丁的题里，运维环境会变（规格用判据有效期处理，3.1.3），目标内容可能含提示注入（5.1 场景 4）。执行层隔离、端点代理、证据出处类别在原文里都没有对应物，它们是基座在比喻之外必须多做的部分。
3. **庖丁只解一种牛。** "十九年、数千牛"建立在同一种解剖结构之上，经验可以直接复用。庖丁的五个领域结构不同，对应物是"画像加锦囊"：画像给出题目的解剖类别，锦囊按类别取用（4.3"按结构取用"）。跨领域时能保持"刀刃若新"的只有内核，这正是 M3 的验收条件，而锦囊与经验不能跨领域照搬。
4. **一个庖丁，没有编队。** 原文是单个执行者手、肩、足、膝的协同，不是多个独立个体的协作。所以原文对"编队是否有价值"不提供任何支持。这个问题仍然只能由 G1（同成本下赢 Bk）回答，赢不了就按红线 5 删除编队，退回"瘦基线加判官"（8.3 执行规则 4）。从这个角度看，原文更支持瘦路径加判官这条底线，而不是厚路径。
