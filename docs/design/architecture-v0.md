## 0. 设计哲学：解牛五诀 → 五条设计公理

| 庄子原文 | 设计公理 | 架构落点 |
| --- | --- | --- |
| 臣之所好者**道**也，进乎**技**矣 | 通用方法论 > 领域技巧；领域知识走锦囊（技能包）不进内核 | 内核不含任何领域逻辑 |
| **依乎天理**，因其固然 | 先识别问题结构，再选解法形态 | 问题 intake 做两范式判定（§1） |
| 批大郤，导大窾 | 沿问题天然纹理分解：Intent 从证据缺口里长出来 | 解牛图生长规则（§3.4） |
| 以无厚入有间 | 最小干预：薄内核、薄 harness，能力放模型里 | Worker 复用成熟 CLI（§5） |
| 每至于族，**怵然为戒** | 高危处自动降速：风险分级 + 审批门 | 治理层（§8） |
| 善刀而**藏**之 | 收尾归档：复盘 → 通鉴，错误轨迹保留 | 记忆层（§10） |

另有一条贯穿性的元公理——**约束删简律**（调研 §9.4-1）：每引入一个结构，必须回答"下一代模型会不会把它吃掉"；会被吃掉的放外壳（便于拆除），不会被吃掉的（验证、工具治理、预算）才进核心。

## 1. 问题模型与两范式

### 1.1 收口类问题

庖丁只受理**收口类**问题：有明确起点（Origin）与可验证终点（Goal）的任务。形式化：

```
Problem = (Origin, Goal, Judge, Env, Budget)
```

- `Judge`（判官）：能独立于模型自述判定"Goal 是否达成"的机制。每个领域先找判官（调研 §10.1-2）
- `Env`（环境）：沙箱化的工具容器（Kali / Lean+sage / k8s 诊断环境 / 病例模拟器）
- `Budget`（预算）：token、钱、动作数、时间、对目标的请求频率上限——显式参数（调研 §10.1-7）

### 1.2 两范式判定（依乎天理的机械化）

intake 时由三个观测值分类，决定后续状态生长规则、扇出策略与验证策略（调研 §9.3）：

| 观测 | 范式 A：不完全信息 | 范式 B：完全信息 |
| --- | --- | --- |
| 信息状态 | 需侦察/问诊/查日志（CTF 侦察、医学、运维） | 题面/仓库即全部（数学、软工） |
| 判官 | 无即时判官或判官昂贵（共识、后续证据、指标恢复延迟） | 确定性判官（flag、测试、Lean、PoV） |
| 动作可逆性 | 低（检查有成本、生产变更不可逆） | 高（git、沙箱重置） |
| **状态生长规则** | 按**信息增益/成本**给 Intent 定价，广度优先 | 按**证明义务**收拢（未证引理/失败测试），深度优先 |
| **验证策略** | 判官缺失时：假设面板 + 唱反调 + 延迟验证（后续证据回溯修正等级） | 形式验证优先，分层过滤 |
| **人的位置** | 审批门 + Hint 通道（医学最终决定权在人） | 高自主、大量并行 |

范式不是二选一的标签，而是两个端点上的刻度；一个真实任务（如"内网渗透中拿到一段源码后找 0day"）会跨段，图上允许**子目标各自声明范式**。

## 2. 总体架构：五层 + 两横

```
            ┌──────────────────────────────────────────────┐
            │  治理层  预算 · 审批门 · 哮天犬(watchdog) · 审计 │
            └──────────────────────────────────────────────┘
   人 ──Hint──▶ ┌───────────┐        ┌───────────┐
               │ 司南(调度) │◀──────▶│ 解牛图     │ ◀── 复盘/通鉴
               └───────────┘        │ (共享状态) │
                    │ 派发任务       └───────────┘
            ┌───────┼───────────────────────┐        ▲ 读写
            ▼       ▼                       ▼        │
        ┌──────┐ ┌──────┐ ┌────────┐ ┌──────────┐ ┌──┴──────┐
        │Worker│ │Worker│ │闲人生态 │ │ 谛听(验证)│ │Artifact │
        │(探索) │ │(推理) │ │falsifier│ │ 判官池    │ │ 仓库     │
        └──┬───┘ └──┬───┘ └───┬────┘ └────┬─────┘ └─────────┘
           └────────┴─────────┴───────────┘
                     ▼
            ┌──────────────────────────────────────────────┐
            │  执行层  如意(工具) · 沙箱分级 · 工具容器        │
            └──────────────────────────────────────────────┘
```

两横：**司南**（调度，§4）与**通鉴**（跨项目记忆，§10）。

## 3. 解牛图：状态层（核心创新 ①）

### 3.1 节点

| 节点 | 含义 | 备注 |
| --- | --- | --- |
| `Origin` / `Goal` | 起点 / 终点 | 继承 Cairn [Z3]；Goal 必须绑定 Judge |
| `Conjecture` | 猜想（E0 级） | 任何 Worker/闲人可提出，必须引用至少一个 Artifact 或已有节点 |
| `Fact(E1..E3)` | 带等级的事实 | 证据等级见 §3.3 |
| `Intent` | 意图：下一步探索方向 | 携带 expected_gain / budget / risk（§3.4） |
| `Hint` | 人类注入的判断 | 继承 Cairn [Z3]，Worker 下次读图时吸收 |
| `Artifact` | 工具执行的产物（输出、PoC、脚本、图、日志切片） | **内容寻址（哈希）**，实体存对象仓库，图上存引用 |
| `Playbook` | 复盘蒸馏的可复用经验 | 产出即候选锦囊（§10） |

### 3.2 边

`supports` / `contradicts`（证据指向）/ `derives_from`（推断来源）/ `yields`（Intent → 结果）/ `proves`（直通 Goal）/ `invalidates`（证伪传播）。

**证伪传播是创新点**：一个 E2 事实被证伪时，沿 `derives_from` 回溯，把下游依赖它的节点自动降级或标记待重审——**污染不靠隔离解决，靠降级解决**（针对 sapper 修复的"坏事实污染下游" [Z4] 与 MAST"幻觉式成功" [S32]）。

### 3.3 证据等级（Evidence Ladder）

| 等级 | 名称 | 晋级条件 | 谁能消费 |
| --- | --- | --- | --- |
| E0 | 猜想 | 提出 + 引用 Artifact | 只能推导出新 Intent，不能进执行链 |
| E1 | 单源佐证 | 一个**独立会话**复核通过 | 低风险 Intent 可引用 |
| E2 | 异构佐证 | **不同模型或不同方法**的第二次独立确认 | 高风险/高扇出 Intent 可引用 |
| E3 | 判官确认 | 确定性判官通过（flag/测试/Lean/ASan/指标恢复）；范式 A 无判官时允许"延迟 E3"（后续证据到达后回溯晋级） | 进执行链、触发 proves |
| X | 已证伪 | falsifier 给出反例 Artifact | 保留在图上（负知识："已排除路径"是合法产出） |

两条防回声室规则：
1. **E1→E2 必须异构**（不同模型家族，或同模型+不同方法/视角）——多样性是要求不是选项（MAI-DxO 唱反调的泛化 [S28]；Atlantis 正交集成 [S15]）
2. **反幻觉不变量**：任何晋级必须引用沙箱内真实执行产生的 Artifact 哈希；模型自述的"观察"不构成证据（针对 soliloquizing [Z7]）

### 3.4 图的生长规则（两范式）

- **Intent 结构**：`(claim, expected_gain, budget, risk_level)`。
- 范式 A：司南对候选 Intent 按 `expected_gain / cost` 排序（起步用 LLM 打分 + 简单 bandit，验证定价见 §6.2），广度优先、按侦察价值扇出。
- 范式 B：Intent 从证明义务生成（未证引理、失败测试、未覆盖分支），深度优先、按义务收拢；例外是 Atlantis 式正交集成——对单一高价值猜想做多路并行抢答 [S15]。
- 三层访问视图（继承 sapper [Z4]）：title / summary / evidence，Worker 按需下钻——**物理隔离上下文、逻辑共享状态**（调研 §9.4-2 的解法）。

### 3.5 存储

- 权威状态：图数据库（PostgreSQL 起步，ARTEX 同款 [Z5]），单写者协议（Dispatcher/司南串行写入，Worker 并行只在意图粒度——"写入单线程、智力并行" [S44]）
- 投影：人可读 Markdown 镜像目录（人可审计、可 git 版本化 [S39]），Worker 的上下文从投影构建

## 4. 司南：调度器（核心创新 ②：调度即导航 + 人机通道）

名字取自指南车——黄帝在蚩尤的迷雾里靠它辨向：**在对抗性不确定中给方向**。

### 4.1 职责

1. 读图 → 生成任务队列，四类任务（Worker 与闲人统一消费）：

| 任务 | 触发 | 产出 |
| --- | --- | --- |
| `Bootstrap` | 项目启动 | 直接尝试 Origin→Goal（Cairn [Z3]） |
| `Reason` | 周期 / 图变更事件 | 判定 Goal 达成与否；生成新 Intent；触发复盘 |
| `Explore` | 认领一个 Intent | 一个新 Conjecture/Fact + Artifact |
| `Verify` | 晋级请求（E1→E2、E2→E3） | 谛听执行记录（§6） |

2. **扇出控制器**：决定当前并行度——范式 A 按信息增益、范式 B 按证明义务；预算紧张自动收拢（调研 §9.4-4，尚无开源实现，是庖丁的潜在贡献点）
3. **人机通道**（替代"蜂后"的错误比喻）：Hint 注入接口 + 审批门 + 状态问答（"现在到哪了/为什么卡住"）——Hint 是 Cairn 实战验证过的协同原语 [Z3]

### 4.2 反单点

- 司南**无权威状态**：图才是唯一事实源，司南崩溃由哮天犬重启，重建队列只需读图（sapper "个体会死，图存续" [Z4]）
- 未来上千并发的扩展路径：司南退化为纯调度器（任务队列分片），协调全部走图（stigmergy）

## 5. Worker 与闲人生态（核心创新 ③）

### 5.1 Worker：薄到不能再薄

- **M0 复用成熟 CLI**（Claude Code / Codex / GLM CLI）作为最小调度单位（Cairn 路线 [Z3]），包一层 Worker Adapter（统一 prompt 进 / 结构化出）
- Adapter 接口预留自研薄循环的插槽（mini-SWE-agent 式百行循环 [S3]），用于特殊角色或降本
- Worker **无固定角色**：任务由图状态动态生成（"角色分工是人类局限的投影" [Z3]）

### 5.2 闲人：常驻的"无用之用"

| 闲人 | 职能 | 依据 |
| --- | --- | --- |
| `falsifier`（谛听化身之一） | 专找反例：对高扇出/高等级节点主动证伪 | MAI-DxO 质疑医生 +85.5% vs 20% [S28]；波普尔式证伪 |
| `reviewer` | 干净上下文复审判官之外的推理链 | Cognition"生成者+独立审查者"有效形态 [S44] |
| `free-form` | 无目标漫游：随机扰动、跨界联想、读"无关"领域 | 多样性注入跳出局部最优（模拟退火；JoyAgent 投票 [S9]） |

三条约束保证闲人不添乱：
1. 闲人**只读黑板、只写 Conjecture(E0) 和反证**，不写决策性 Intent——避开 Cognition"冲突隐含决策" [S43] 与 MAST 失配 [S32]
2. free-form 时间盒限定（如每 30 分钟一轮），预算独立、上限小
3. 闲人刻意**用异构模型**（便宜 + 多样性一举两得，§9）

## 6. 谛听：验证层与验证定价（核心创新 ④）

### 6.1 判官池

按成本从低到高分四档，分层过滤（RoboDuck 两级过滤的推广 [S16]）：

1. **确定性判官**：flag 比对、测试套件、Lean kernel、ASan/消毒器、指标恢复断言——零模型成本，优先（调研 §10.1-2）
2. **程序化检查**：重放 Artifact、幂等复算、schema 校验
3. **模型面板**：干净上下文的独立复核 + 唱反调（无判官场景的主力）
4. **延迟验证**：范式 A 特有——标记"待后续证据"，证据到达后回溯晋级/降级

### 6.2 验证定价（市场机制）

**一个节点值得花多少验证算力 = 它承载多少下游决策。**

```
verification_budget(node) = k × (fan_out_dependents × risk_level × proximity_to_goal)
```

- 叶子猜想（无下游依赖）：不值得花 E1→E2 的钱，让它自然过期
- 扇出中心节点（多条 Intent 依赖它）：自动升级到异构确认 + 判官
- 这是 Atlantis（预算按模块分配）[S15] 与 XBOW（全押验证）[S18] 两个极端的中间路线：**按信息结构定价**

### 6.3 "未解决"是合法输出

允许且鼓励 Goal 以 `unsolved + 已排除路径集` 收口（IMO 第 6 题主动认输的正面价值 [S23]；调研 §10.1-9）。已排除路径写入通鉴，防止下次重蹈。

## 7. 如意：执行层

- **沙箱分级**：bwrap（轻隔离，默认）→ Docker（基线）→ VM（内核利用/强对抗）[S13][Z13]；范式 B 代码任务默认 Docker+git
- **工具容器按域配置**：CTF=Kali + 交互式工具会话化（EnIGMA IAT：gdb/radare2 封装为 start/stop+子命令、非阻塞并行 [Z7]）；数学=Lean+sage+sympy；运维=k8s/日志 CLI + 只读副本环境；医学=病例模拟器 + 文献检索
- **工具接口即人机接口**（ACI [S7]）：防呆参数、有指导性的报错（报错信息里写修复办法 [S40]）
- **扩展机制三档**：钩子（零上下文成本）→ 锦囊（低）→ MCP（高）[S7]；安全工具走 MCP 池（HexStrike 式 [S29]）

## 8. 治理层

| 机制 | 设计 | 依据 |
| --- | --- | --- |
| 预算 | 每题硬顶（token/钱/动作/时间）；50%、80% 节点强制触发复盘 | sapper/CTFExplorer [Z4][S13] |
| 审批门 | 动作风险分级；不可逆动作（生产变更、真实网络请求、医疗建议输出）需人批准 | 调研 §7.8；ARTEX 审批门 [Z5] |
| 哮天犬（watchdog） | **纯脚本零策略**：保活、重启、key 轮换、成本熔断、截止收尾 | sapper [Z4]——治理最小化 |
| 审计 | 全轨迹 + Artifact 哈希链 + 预算流水；攻击性工具预留 taggant 水印接口（sapper 提案 [Z4]） | ARTEX 滥用事件 [Z6] |
| 授权边界 | 任务 intake 必须声明授权范围；越界动作直接拒绝并记录 | Gemini 逃逸事件反证 [Z13] |

## 9. 模型经济层

| 角色 | 模型档位 | 理由 |
| --- | --- | --- |
| 司南 / Reason 任务 | 最强模型（编排智能） | token 用量解释 80% 方差 [S37] |
| Explore Worker | 中档，可多家路由 | 多厂商避免锁定 [S15] |
| 闲人（falsifier/reviewer/free-form） | **异构便宜模型**（刻意不同于主力） | 多样性是晋级要求（§3.3）+ 成本 |
| 判官 | 确定性程序优先，模型判官兜底 | §6.1 |
| 正交抢答 | 同任务 2-3 家模型并行，先到先得 | RoboDuck [S16] |

目标指标：**每题成本** 与 **单题 token 效率**（对标 sapper 1B token 赢 4.5B [Z4]）。经济层不是旁路，是图 schema 的一等字段（Intent 携带预算）。

## 10. 通鉴与锦囊：记忆与技能

```
复盘(单题) → Playbook(存图) → 蒸馏 → 锦囊(跨项目技能库, SKILL.md 渐进披露 [S42])
                ↓ 结构同构检测（"这道题家族似曾相识"）
            新题直接注入 playbook（sapper 后期 3 分钟一题 [Z4]）
```

- **通鉴 = 跨项目的 Playbook 索引 + 证据等级**：蒸馏出的锦囊带出处、适用条件、历史胜率；胜率衰减的锦囊自动退役（防漂移）
- **防投毒**（OpenClaw 市场 12–20% 恶意 [S34]、自我沉淀是新趋势但有风险 [S47]）：锦囊只从本项目复盘生成 + 人工审核入库 + 哈希签名；不直接引入第三方技能市场
- 长期：infra agent（自举平台层，§12-M4）把高频 Playbook 产品化为内部服务

## 11. 创新点对照表（诚实版）

| 机制 | 最近的前身 | 庖丁的增量 |
| --- | --- | --- |
| 证据梯（E0–E3/X，晋级/证伪传播） | Cairn 二元 Fact [Z3]、sapper 静态三层 [Z4]、ARTEX proves 边 [Z5]、MAI-DxO 假设集 [S28] | 认识论状态做成节点一等属性 + 证伪沿边传播 + 异构晋级要求 + 反幻觉 Artifact 不变量 |
| 验证定价 | RoboDuck 两级过滤 [S16]、Atlantis 预算分配 [S15] | 按下游依赖结构动态定价验证算力（市场机制） |
| 两范式自适应 | 调研 v2 §9.3（两报告交叉综合） | intake 判定 → 生长规则/扇出/验证策略三联动；子目标可异范式 |
| 闲人生态 | MAI-DxO 五角色 [S28]（医学专用）、diversity ensemble [S9][S16] | 常设化、领域无关、约束在"只写猜想与反证"以避开多智能体失效模式 |
| 司南（调度+人机通道） | Cairn Dispatcher+Hint [Z3]、ARTEX Planner [Z5] | 扇出策略控制器（信息增益/证明义务）+ 反单点设计（图是唯一事实源） |
| infra agent（M4） | sapper 涌现的 shellcode 模板 [Z4]、Hermes 自沉淀 [S47] | 把"重复劳动→内部服务"做成常设角色（平台工程 for agents） |
| 通鉴 | sapper playbook [Z4]、Anthropic 长时外壳进度文件 [S39] | 跨项目蒸馏 + 证据等级 + 胜率退役 + 防投毒 |

明确**不创新**的部分（克制即设计）：内核循环（复用 CLI）、MCP 工具接入、沙箱技术本身、Markdown 技能格式（用开放标准 [Z19]）。

## 13. 评测方案

- 自建 **~20 题代表性评测集**起步 [S37]，检查点式部分得分 [S13]
- 北极星指标：**每题成本**（钱 + token）× **解题率**；按 METR 时间跨度口径记录"可稳定解决的题目的人类等效时长" [Z25]
- 每天跑一遍防模型漂移；每题保留完整轨迹与错误（"错误恢复是真正 agent 行为的最清晰指标" [S41]）
