# 任务详情页 v6：把智能体的整个执行过程摊开给人看、让人随时插手

> 起因：cz 2026-11-21 对任务页“结果 / 过程 / 结构 / 文件”四栏的评价是“设计的太简单”。点名要的有：实时刷新的工作流图、与智能体交互、看到编排信息、调用的命令与工具及其输出、全过程的思考和模型调用的判定；并要求主动补齐没想到的部分。本稿是设计，也是同一 PR 里实现的依据。
>
> 界面用词按 cz 同日的裁决：品牌叫焚决，界面用常规技术词，设计名词（功法、火位、炼档……）不上界面。
>
> 硬约束照旧：页面只排版服务端给的字段，不内嵌 reducer、不推断状态；回放（as_of）时一切写操作禁用；凭据在适配层遮盖之后才出现在任何条目里；不读本机题库与校准目录。

## 0. 一页结论

1. **数据先补齐。** 现在的会话活动只有“工具调用 / 结果 / 自述 / 一轮结束”。本稿给适配层的活动流水加三样：每次模型调用一条 `turn`（模型、输入/输出/缓存 token、停止原因，取 CLI 流里 assistant 消息自带的 usage，不另算）、扩展思考一条 `think`、每条一个本机毫秒时间 `t`（不进链哈希、不进入账段，回放照样逐字节一致）。端点代理本来就按请求写 `cost` 事件（模型、token、花费），两者按会话内序号对齐，花费以代理的为准。
2. **过程 = 全链路追踪。** 把事件账（编排、授权、预算、交付、判定、人的操作）与每个会话的活动（思考、模型调用、自述、工具调用与输出）按时间合成一条轨迹，按会话与轮次分组。可以按类型筛、按文字搜、按会话看、在概要与详细之间切换，在途时自动跟到最新。
3. **结构 = 实时执行图。** 一张从左到右的图：任务 → 各个会话（接力用箭头连）→ 每轮的模型调用 → 它发起的工具调用 → 工具产出的登记文件；交付、复核、判定、人的指导与授权作为节点挂在发生的位置。在途节点闪动，图随轮询生长；时间轴拨到哪一刻，图就停在哪一刻。点任意节点，右侧给出完整详情。严格判定任务另保留“推理图”（原来的前沿与事实/计划图）。
4. **交互不藏在别处。** 执行中随时“插话”（给出指导）、叫停、追加预算；它要访问外部地址时，申请卡直接出现在过程里请求发生的那一行；交付之后在同一个输入框里追问。所有写操作都标明“只影响下一步”，回放时整块禁用并说明原因。
5. **结果与文件也加深。** 结果按交付版本切换（追问后的每一次交付都能回看），每条主张的依据可以一键跳到产出它的那次命令；文件改成左列表、右预览的两栏，按来源分组，写明是哪个会话、哪条命令产出的，可以搜、可以只看某个会话的。
6. **右栏加“模型调用”。** 调用次数、输入/输出 token、缓存命中率、用到的模型，按会话列出；花费仍按代理计量。

## 1. 数据来源（只排版，不推断）

| 要显示的 | 来源 | 说明 |
| --- | --- | --- |
| 编排：会话起止、种类、接力、预留、结束原因 | 事件 `lease`、`release`、`expire_lease`、`/budget` 的按会话行 | 已有 |
| 模型调用：模型、token、停止原因 | 活动条目 `turn`（新增） | 来自 CLI 流里 assistant 消息自带的 usage |
| 模型调用的花费 | 事件 `cost`（端点代理按请求写） | 与 `turn` 按会话内序号对齐；对不上时各自单列，不硬配 |
| 思考 | 活动条目 `think`（新增） | 上游遮蔽的思考记为“已遮蔽”，不显示内容 |
| 自述、工具调用、结果 | 活动条目 `say`、`call`、`result` | 结果另带 `size`（新增）；全文在执行留档里 |
| 工具耗时 | 活动条目的 `t`（新增）：结果的 t − 调用的 t | 回放时没有 t，耗时显示“—” |
| 命令与输出 | `exec` 的结果带 ArtifactId → 执行留档（命令、退出码、stdout/stderr、哈希） | 已有（炼档 001） |
| 授权、指导、追问、叫停、预算、判定、交付 | 对应事件 | 已有 |

`t` 是本机墙钟：只在实时流与会话目录里，不进链哈希、不进入账段。这样“实时所见可回放”的结构读数不变，同一剧本跑两遍入账段仍逐字节相同（`activity.chained` 给出进链的那部分）。

### 2.1 概要条（新增）

标题下一行数字：会话数（在途几个）、模型调用次数、工具调用次数（其中失败几次）、输入/输出 token、花费。每个数字可点，点了跳到“过程”并套上对应的筛选。

### 2.2 过程：全链路追踪

- **分组**：会话 → 轮次。会话头写种类、模型、起止、花费、结束原因、接力自哪个会话；轮次头写这一轮的模型调用数、工具调用数、耗时。可折叠，在途的那一组默认展开。
- **条目**（按时间）：
  - 思考：灰底小字，默认折成一行，点开看全文；已遮蔽的写明“上游遮蔽了这段思考”。
  - 模型调用：模型名、输入/输出/缓存 token、停止原因（`tool_use` 写“要调工具”，`end_turn` 写“这一轮说完了”，`max_tokens` 写“输出到上限被截断”并标黄）、这次的花费。
  - 自述：叙述语域（与证据区分），原样排版。
  - 工具调用：工具名、参数摘要、状态（进行中 / 成功 / 出错）、耗时、输出大小；点开看输出前 400 字；exec 有“看执行记录”打开完整留档（命令、退出码、输出、哈希）。
  - 编排与人的事件：会话起止、接力、访问申请与批复、指导、追问、叫停、预算标记、交付、复核、判定，用不同的左侧标记与颜色（等你=琥珀、交付=绿、在做=蓝）。
  - 访问申请还没批时，就在这一行给出“批准 / 拒绝 / 看详情”。
- **工具栏**：类型筛选（全部、思考、模型调用、工具、命令、出错、编排、人的操作，带计数）；搜索（命令、输出、自述、思考全文）；会话下拉；概要/详细切换；“跟随最新”开关（在途时默认开，往上翻自动关，回到底部再开）。
- **键盘**：`j`/`k` 上下一条，`Enter` 展开，`/` 搜索，`f` 切跟随，`H` 插话。
- **空态与错误**：会话还没起来写“正在起会话”；活动端点读不到写原因，并保留事件账那部分；回放到会话开始前写“这一刻还没有活动”。

### 2.3 结构：实时执行图

- **执行图**（缺省）：一行一个会话（泳道），从左到右是时间顺序。每轮先是一个“模型调用”节点，后面挂它发起的工具调用节点（形状区分：命令为方角、读写文件为圆角、交付为实心）；exec 节点下面挂它登记的文件。会话之间用接力箭头连；任务起点在最左，交付与复核在发生处。人的操作（指导、授权、追问、叫停）画在单独的“你”泳道上，竖线连到它影响的那一轮。
- **实时**：轮询带来新条目时图向右生长，在做的节点蓝色闪动，视图自动滚到最新（可关）。
- **回放**：时间轴拨到某一刻，只画那一刻已入账的部分。
- **检视**：点节点，右侧检视面板给出与“过程”里同一条目的完整详情，并有“在过程里定位”。
- **缩放**：紧凑（只画模型调用与工具调用）与完整（加思考、自述、文件）两档；图大时横向滚动，左上角有小地图式的进度条。
- **推理图**：严格判定任务另有一个页签，沿用原来的“前沿 / 图”与节点检视。严格判定任务的“结构”缺省打开推理图（它是这类任务的主结构），一键切到执行图；开放道只有执行图。

### 2.4 结果

- 交付版本切换：第 1 次、追问后的第 2 次……各自的答案、主张、自检、没核实的、要你补的；默认最新一次。
- 每条主张的依据：点 exec 依据打开执行记录；“在过程里定位”跳到产出它的那次命令。
- 交付对比：和上一次交付相比新增、去掉了哪些主张（按文字比对，只是排版）。
- 严格判定任务沿用结构化报告。

### 2.5 文件

- 两栏：左边按来源分组的列表（执行输出、会话写的、你给的材料、判定输出、引用的资料），每行写产出它的会话与命令、大小、时刻；右边是预览（文本按行号排版，JSON 缩进，超长截断并提示）。
- 搜索文件名与命令；只看某个会话的；按时间或大小排序。
- 每个文件写明哈希与“由执行层登记，模型改不了”或“会话写的，不能作依据”。

### 2.6 交互

（实现备注：判定会话在判定箱里跑，没有 CLI 活动，追踪不去读它们的活动端点；单个任务最多读最近 60 个会话的活动。）


- 底部输入框：执行中是“插话”（作为指导下发，下一次派工起生效），交付后是“追问”（可附追加预算）。旁边是叫停（先收尾交付再停）。
- 访问申请：卡片出现在过程的那一行与页头的“等你处理”里，二者是同一张卡。
- 所有写操作在回放、断线、任务已关时禁用，并写出原因。

### 2.7 右栏

花费、用时、钱花在哪个会话（已有）之外，新增“模型调用”：调用次数、输入/输出 token、缓存命中率（缓存读 ÷（输入 + 缓存读），CLI 的 input_tokens 不含缓存读）、用到的模型；会话行显示每个会话的调用次数与工具调用次数。

## 3. 实时与性能

- 活动按会话分别轮询（3 秒，按游标取增量），只轮询在途的会话；结束的会话取一次。
- 事件账已经由任务页的长连接推送；追踪把两路数据按时间合并，合并是纯函数（`model/trace.ts`），有单测。
- 条目多时只渲染可见的那一段之外的折叠组；单个会话超过 2000 条时提示用命令行看全量。
