# 03 设置层

> 回答三件事：模型、端点、密钥、预算上限这些配置放在哪；全局设置页与任务级覆盖是什么关系；密钥怎么按“人的令牌”同级管理。
> 一句话开题要求在全局设置页留三样：风险表、练习道信封、单题硬顶。它们都在 §2 的表里。

## 1. 三层，越往下越窄

```
全局设置（S0）            人在设置页写，带版本号与摘要；改动只追加进设置日志
   │  只许收窄
   ▼
任务级覆盖（S4、S5）      人在确认卡或高级编辑里选；随 open_problem 写进事件体，之后不可改
   │  只许收窄
   ▼
运行期执行（S6）          端点代理、执行层、图服务按上面两层的交集执行；智能体只能申请，不能改
```

一条规则管住整层：**下一层的任何值都必须落在上一层给出的范围之内**，由确定性代码在写入时检查（图服务的 `validate` 或端点代理），而不是由界面“不给选”来保证。

## 2. 全局设置页

设置页沿用 v4 原型的两组导航（“个人”“系统”）。“个人”一组只存在本机浏览器，不发到服务端；“系统”一组存在服务端的设置存储里，只有人的令牌能写。

| 节 | 项 | 存在哪 | 谁能写 | 何时生效 | 进不进题目事件 |
| --- | --- | --- | --- | --- | --- |
| 个人·外观 | 主题、密度、纸纹 | 本机 `localStorage` | 人 | 立即 | 否 |
| 个人·快捷键 | 按键表 | 本机 | 人 | 立即 | 否 |
| 个人·访问令牌 | 人的令牌（已有：本标签页 `sessionStorage`，8 小时到期） | 本标签页 | 人 | 立即 | 否 |
| 系统·模型与端点 | 模型档案：名称、端点（`api_base`）、模型 id、家族（`family`）、档位（强 / 中 / 轻）、价目表条目 | 设置存储 | 人 | 新会话起 | 以 `settings_digest` 间接进 |
| 系统·角色路由 | bootstrap、reason、explore、verify、起草 各用哪个档案（即今天的 `routing.yaml`） | 设置存储 | 人 | 新会话起（会话中途不换模型，HMI §12.3） | 同上 |
| 系统·密钥 | 每个端点一个密钥槽；页面只显示“已设 / 未设”、指纹与设置时间 | **端点代理进程内存**，见 §4 | 人 | 立即 | **否，永不** |
| 系统·预算与硬顶 | 全局硬顶 `global_cap_usd_milli`；单题硬顶 `open_cap_usd_milli`、`open_cap_wall_s`；练习预算上限（= 练习道信封的金额） | 设置存储 | 人 | 下调立即，上调只对新开题（D6） | 以摘要进 |
| 系统·风险表 | 资源种类与模式 → 风险等级；未命中按 r2 | 设置存储 | 人 | 新开题起 | 以摘要进；每条 scope 的风险照旧写进 `open_problem` |
| 系统·练习道信封 | 一句话开题 §4.4 的 `allow`、`judge`、`budget`、`goal` | 设置存储（取代 `kaiti.d/practice.yaml` 的手工编辑） | 人 | 新开题起 | 信封版本与摘要进 `origin.draft.policy` |
| 系统·预算先验 | 先验源的名称、版本、档位表（只读显示） | 外部注入，见 §6 | 部署方 | 起草服务启动时加载 | 版本进出处账 |
| 系统·判定器 | 已注册判官（只读，注册表由配置目录给出，Worker 不可写） | `judgebox/judges.d/` | 人（在仓库或部署里） | 重启 | `judge_snapshot` |
| 系统·运行环境 | 执行容器基础规格（只读） | `config.yaml` 的 `executor.bases` | 部署方 | 重启 | `env.base` |

“系统·成员与权限”在 v4 原型里有位置，留给 HMI §13.3 的多用户演进，本图不展开。

## 3. 任务级覆盖

### 3.1 允许覆盖什么

| 项 | 怎么覆盖 | 上限 | 记在哪 |
| --- | --- | --- | --- |
| 预算金额、墙钟 | 确认卡上改数，或高级编辑第四步 | 单题硬顶；练习道还受练习上限 | `Problem.budget`（已有） |
| 每条授权的风险 | 确认卡上把风险往上调（r0 → r1 → r2） | 只许往上调（更谨慎）；往下调要进高级编辑，并在卡上标“人改过” | `Problem.scope[].risk`（已有） |
| 模型档案 | 确认卡上从已登记档案里选 | 只能选设置页里已有的档案；不能在任务里填端点或密钥 | `Problem.prefs.model`（工作台设计 C13，可选字段，不进等级、消费门与画像） |
| 验收清单 | 确认卡上增删条目（B2） | 只许原文区间或人写 | `goal.acceptance`（D3） |

**不许在任务级覆盖的**：端点、密钥、全局硬顶、风险表、信封、判官注册表、先验源。这些改了会让所有任务的上限一起变，只能在全局设置页改，改动留痕。

### 3.2 取值公式

```
task.budget       := min(人填的值 或 默认值, open_cap, 练习道 ? 练习上限 : ∞)    // vet 先裁剪，validate 再拒绝
运行期可花       := min(task.budget 余额, global_cap 余额)                       // 端点代理执行（I6）
task.model        := task.prefs.model ∈ 已登记档案 ? 它 : 全局路由
会话的模型        := 开会话时按 task.model 解析一次，会话中途不变
```

### 3.3 设置快照进开题事件

每次 `open_problem` 的事件体带 `settings_digest`（设置存储当时版本的 sha256）与 `settings_version`（D5）。作用只有两个：审计时知道这道题开在哪一版设置之下；评测把“设置变了”识别为条件变化，开新题组（HMI §12.4）。它不进等级函数、消费门与画像，重放不读设置存储。

## 4. 密钥：按“人的令牌”同级管理

### 4.1 规则

密钥与人的令牌同级，只活在本机这一次运行的会话里：

1. **只在内存。** 密钥只存在端点代理进程的钥匙环里（槽名 → 密钥）。进程退出即消失，下次启动重新注入。
2. **不入库。** 不进 SQLite 日志、Blob 仓库、设置存储、`config.yaml`。
3. **不入日志。** 不进事件体、运行日志（`logs/stack.log`）、访问日志、会话转录、任务包、错误信息。日志层加一道按已注入密钥逐字匹配的遮盖（只显示指纹）。
4. **不出导出物。** `backup.sh` 的备份、`pd report`、`eval` 的运行记录与 `docs/m1/readings/` 的收集、Blob 导出、截图与错误报告里都没有它。
5. **不进容器。** 模型容器与执行容器只拿到任务令牌（规格 3.4.2，已有）。
6. **不回显。** 读端点只返回 `{slot, set, fingerprint, set_at}`，`fingerprint` 是加盐 sha256 的前 8 位加密钥末 4 位。没有任何端点能把密钥读回来。

### 4.2 注入的两条路

| 路 | 形态 | 适合 |
| --- | --- | --- |
| 设置页 | 密码框输入 → `PUT /v1/keys/{slot}`（人的令牌，只在本机回环地址）→ 代理钥匙环；提交后输入框清空，浏览器不在任何存储里留它 | 日常使用 |
| 环境变量 | 启动时读 `api_key_env` 指定的变量（已有），读完写进钥匙环 | 无界面的部署、评测台 |

设置页的“密钥”一节常显一行（裁决附加 2）：**“密钥重启后失效，可用环境变量持久注入”**，并写出该槽对应的环境变量名。还有两个按钮：“清除”（`DELETE /v1/keys/{slot}`，立即生效，在途请求按 401 失败）与“全部锁定”（清空钥匙环）。

### 4.3 与现状的冲突（D4）

2026-11-18 cz 同意了“配置文件里直接写 `backend.api_key`”（`scripts/stack.py`）。这与“不入库”冲突：配置文件会被备份、被复制、被误提交。提议退役它，过渡一个版本：读到 `backend.api_key` 时启动照常，但记告警、在设置页的密钥一节标“密钥来自配置文件，请改为在此处输入”；下一版拒绝启动。

### 4.4 证明它做到了

金丝雀测试（进 CI；裁决附加 2：**纳入每一期的验收标准**，见 05 的 AC-M5）：以一个形如真密钥的随机串注入钥匙环，跑一遍全栈端到端（开题、会话、判定、关题、备份、`pd report`、`eval collect`），然后在数据目录、日志、备份包、导出文件、容器环境变量、会话转录里逐字搜这个串，命中即失败。另有一条：杀掉进程再起，钥匙环为空，真实后端拒绝开会话并在设置页提示“密钥未设”。

## 5. 预算：三道硬顶

与一句话开题 §5.3 一致，这里只补“在设置页怎么呈现”：

| 顶 | 设置页的项 | 执行点 | 今天 |
| --- | --- | --- | --- |
| 练习上限 | 练习预算上限（金额、墙钟），与信封的 `budget.*_max` 同一个数 | 图服务 `validate`（只对练习道） | 无 |
| 单题硬顶 | 单题上限（金额、墙钟） | 图服务 `validate`（所有开题，向导也受限） | 无 |
| 全局硬顶 | 累计上限，旁边显示已花与余额 | 端点代理（I6） | 有，写死 500 美元 |

页面上三道顶从下到上画成一把刻度尺（v4 的刻度语言），练习上限 ≤ 单题硬顶 ≤ 全局硬顶，设置存储在写入时校验这个次序，不满足拒绝保存。起草本身的花费记在“开题”账户下，显示“开题起草累计”。

## 6. 预算先验：可插拔数据源

- 接口是一句话开题定义的 `PriorSource.lookup(tier, signature) → Prior | None` 与 `version()`。本图不改接口。
- 数据是外部注入的“档位 → 默认预算”表。设计与测试阶段只用占位表（`source: placeholder`）。**系统不读取、也不推导任何本机题库或校准目录。**
- 设置页的“预算先验”一节只读：显示来源、版本、档位表；占位表时整节加一条朱批“占位表：数字没有读数依据”。换表是部署动作（放一份新文件并重启起草服务），不在页面上完成，免得先验表变成又一个人随手改的旋钮。
- 先验是估值（I8）：它只决定确认卡上的默认值，不驱动任何按钮，不进等级与消费门。

## 7. 设置存储

- **形态**：`<home>/settings/` 下一份当前快照 `settings.json` 加一份只追加的变更日志 `settings.log`（每行一次变更：旧摘要、新摘要、改了哪些键、人的令牌标识、时间）。它不是题目日志，不进任何任务包。
- **端点**：`GET /v1/settings`（读，不含密钥）、`PUT /v1/settings`（写，人的令牌，带 `base_digest` 做乐观并发，不等即 409）、`GET /v1/settings/log`。
- **与 `config.yaml` 的关系**：`config.yaml` 留给部署项（端口、执行层、数据目录、日志、先验表路径、判官目录）；“系统”一组的业务项第一次启动时从 `config.yaml` 迁入设置存储，之后以设置存储为准，`config.yaml` 里的同名项告警并忽略。
- **`pd` 对等命令**：`pd settings show`、`pd settings set <键> <值>`、`pd keys set <槽>`（从标准输入读，不进 shell 历史）、`pd keys clear <槽>`。
