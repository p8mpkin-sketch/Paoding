# 02 默认路径：开放道为默认，严格道可选

> **v0.9 修订（开放道裁决之后）。** [开放道](../open-lane/README.md)裁决（cz 2026-11-19，PR #106、#109）把本文原来的“两类任务、两条默认路径”改为：**默认开放道，严格道可选，B 道并入开放道**。本文按地图线的修订规程改写；§2、§3 保留严格道与人工验收的原文，只在开头标出它们今天的位置。
> 三条道按“开题时登记了什么”分：开放道什么判据都不登记；严格道登记判据（答案键、检查命令、外部平台回执）；开放道的“带清单”变体登记一份验收清单。道别由一句话开题的 `vet` 给出（`lane`：`open`、`practice`、`confirm`、`refuse`）。
> “零配置”的意思是：人除了说出那段话，什么都不填。每个字段的默认值从哪来见 §5。

## 1. 三条道

| 道 | 什么时候走 | 开题前人看不看 | 判据形态 | 终态上限 | 本文简称 |
| --- | --- | --- | --- | --- | --- |
| **开放道**（默认） | 一句话进来，人没有明确选严格判定 | 不看，回车即开（运行时扩权关着时退到一步确认，`open_needs_confirm`） | 不登记判据；原文里的检查命令变成必做自检项（有外发形状的除外） | `delivered`（已交付，未经判定） | O 道 |
| 开放道 · 带清单 | 人在创建时写了验收清单（原 B2，D3） | 一步确认（清单要人看一眼） | 验收清单 `goal.acceptance[]` + 结构检查类 advisory 判官 | `accepted`（不呈现为“已证明”） | O+ 道（原 B2） |
| 严格道 · 练习 | 人明确选严格判定，且有答案键（练习、评测、平台导入） | 练习道信封内零确认（开关在测试方，今天休眠），否则一步确认 | `exact_match`，答案在保密库 | `solved` | A 道 |
| 严格道 · 命令 | 人明确选严格判定，原文里有检查命令 | 一步确认 | `replay`，检查命令逐字存为 input 类 Blob | `solved` | B1 |
| 严格道 · 外部 | 原文认出已登记平台且有任务号（#94） | 一步确认 | 外部平台回执 | `solved` | X 道 |

- **严格道的用途是度量智能体，不是使用智能体**（开放道 §0 第 4 条）。评测台与 G1 读数只跑严格道；开放道的读数与终态永不进严格道统计（开放道裁决附加 1，断言在 `graph/tests/test_open_lane.py::test_readings_*`、`eval/tests/test_open_lane_isolation.py`）。
- **拒绝只剩输入本身坏了**：原文为空、答案栏与答案行冲突、答案泄漏、平台任务号缺失或不唯一。判据表达不出来不再是拒绝理由（`no_criterion` 只在严格判定或 `lanes.open=false` 回滚时出现）。起草不可用时，会进开放道的题按原话直开（[04](./04-gaps-roadmap.md) Q38，体质修炼 004），只有要草案结构的题仍拒（`bad_draft`）。
- **十二站不增不减**，在开放道上换的是四站的内容（[01](./01-journey-map.md)）：S3 校验不拒题、S4 确认跳过、S7 判定换成“交付与可选复核”、S10 验收换成“人看结果”。

### 1.1 开放道路径

```
S1 人贴原话（没有答案，也不用写怎么算做完）
S2 起草：Draft 指认目标、交付、入口与原文里的检查命令；凭据按形状认出、遮盖（adapter creds.py）
S3 vet：accept=open；scope 恒为 workspace（零出站）；命令 → self_checks；预算 = 先验表档位，夹到单题硬顶
    └─ lane=open（运行时扩权关着 → lane=confirm）
S4 （跳过）界面直接进任务页
S5 open_problem{goal.accept=open}
S6 执行：一个 solve 会话做到底，未交付而会话结束就接力（至多 5 个）；要连外部就 request_access，人批
S7 交付：deliver{answer, outcome, claims[refs], self_check, unverified, needs}；内核只查“引用是真的”
    ＋ 复核（可选，默认开，花验证份额）：独立会话核对主张与引用，只给读数
S10 人看结果：答案 / 结局 / 主张与证据 / 自检 / 未验证 / 花费；追问、采纳、不采纳，或不理
S9 关题：人采纳或不采纳时关；闲置 7 天自动关（不记反馈）；墙钟或预算耗尽由哮天犬关
S11 读数单列（by_authority 的 self 行）；采纳的结果可一键转存为严格道练习题
```

注意 S10 在 S9 之前：开放道的交付不关题，人看结果、可能追问回到 S6，最后由人的采纳或不采纳触发关题。终态是 `delivered`（至少一次 `answered` 或 `partial`）或 `unsolved`（没有交付或只有 `blocked`）；采纳与否是 `delivered` 上的附加属性 `feedback`，不是终态（开放道 §12 第 6 条）。

### 1.2 开放道上的停止信号

按优先级（开放道 §3.3）：智能体交付（正常出口）→ 预算或墙钟到收尾线（90%，哮天犬叫会话立即交付当前最好的结果）→ 人叫停（同样触发一次收尾交付，[04](./04-gaps-roadmap.md) Q20）→ 停滞（接力用完仍未交付，转人）。没有判官，就没有“判错了重试”，`max_attempts` 不适用。

## 2. A 道：有标准答案，零确认

> v0.9：A 道是严格道的一种，只在人明确选严格判定时走（`pd kaiti --strict`、新建页的“严格判定”）。下文原样保留。

### 2.1 路径

```
S1 人贴原文（含答案行，或答案单独贴在答案栏）
S2 起草：答案先剪出进保密库，模型看不到答案；Draft 只指认入口、交付位置、时限
S3 vet：判据 = exact_match(sealed)；scope = 抽出的入口，逐条查风险表，全部 r0；预算 = 先验表最低档，被练习上限夹住
    └─ 六条放行条件全满足 → lane=practice
S4 （跳过）界面给开题回执：题名、判据徽章、授权条数、预算、“预算默认值来自占位表”
S5 open_problem{origin.draft.lane=practice, policy=信封版本与摘要}；图服务按信封逐条复核
S6 执行 → S7 判定 → Goal 到 E3 → S9 自动关题（四顾以空清单通过）→ S10 人只读核对 → S11 封存判例
```

人在这条路上的第一个动作，是在“今日”或任务库里看到它已经 solved。

### 2.2 零确认的放行条件

条件全部来自一句话开题的练习道信封（kaiti §4.4），这里只列出来对齐，以它为准：

1. Goal 判官是 `exact_match`，且答案在保密库里（`sealed` 非空）。`replay` 同样是判定性判官，但检查命令是否真的检验了目标要人看一眼，所以走确认道。
2. scope 的每条规则都在信封的白名单内，风险全部是 r0（风险由风险表确定性查出，查不到按 r2）。
3. `usd_milli` 与 `wall_s` 都不超过练习上限；练习上限与 v1.5 设置页的“练习预算上限”是同一个数。
4. `max_attempts` 不超过信封的上限。
5. 出处账里没有任何权威字段来自模型猜测（出处只能是“摘”“表”“人”，不能是“起草”“估”）。
6. 校验层没有报告任何“收窄”或“拒绝”。被收窄过的草案说明原文与默认值有冲突，要人看一眼。**这一条是本文补的**，一句话开题的五条里没有；它只在校验层判别，不进内核信封。

任一条不满足：自动转确认道，确认卡上写明是哪一条（例如“预算超出练习上限，已夹到 $0.50”）。不是拒绝。

### 2.3 A 道上仍然必须有人的点位

零确认只管开题。开题之后，下列点位照样会出现，且不能被设置关掉：

| 点位 | 触发 | 为什么不能省 |
| --- | --- | --- |
| 扩权 | 智能体的 Intent 带 `needs_scope`（开题时不存在，只在执行中出现） | 智能体不得自行扩大授权；`gate()` 只认人的 `approve` |
| r2 每次执行 | Intent 的风险为 r2 | A 道的 scope 全是 r0，Intent 的风险不能高于授权，所以只有先经过“扩权”才会出现 |
| 续期门 | 越过 80% 预算而 50% 以来没有进展 | 练习道用最低档预算起步，不够时由人 `extend`，而不是系统自己加钱 |
| 停滞 | 无在途、无可做、无未决判官请求 | 只有人能给 Hint 或关题 |

### 2.4 评测是 A 道的批量形态

评测（`eval/` 的 baseline、full、Bk、Bn 各臂）用同一套 Problem 契约，区别只在两处：

- **一次确认管一个题组。** 评测阈值与题集按规格 8.3 规则 7 预登记，人确认的是“这一组题、这些臂、这组阈值”，确认之后组内逐题零确认开题。题组的预登记本身就是 I4 在评测层的形态。
- **练习化。** 导入的标准案例（v1.5 的“练习化”）先开练习题复现，才产出资产；练习题走 A 道，花费受设置页的练习预算上限约束。

## 3. B 道：自由任务，一步确认

> v0.9：B1 是严格道的一种（人明确选严格判定）；B2 并入开放道，成为“开放道 · 带清单”（O+ 道），清单仍须执行前登记、只许原文区间或人写、创建后不可改。拒绝页上“补一份清单才能继续”这条路取消：没有清单的自由任务直接进开放道。下文保留作 O+ 道与 B1 的定义。

### 3.1 路径

```
S1 人贴原文（目标、交付、约束、时限；没有答案）
S2 起草：Draft 指认目标、交付清单、检查命令（若有）、入口
S3 vet：B1 判据 = replay(检查命令逐字存为 input 类 Blob)；B2 判据 = 结构检查（advisory）+ accept=human + 验收清单
    scope = 抽出的入口，查风险表；预算 = 先验表档位（可用模型的档位猜测作默认），被单题硬顶夹住
    └─ lane=confirm
S4 一步确认卡：一屏看完 目标 / 判据或验收清单 / 授权逐条 / 预算与模型档案；人只改风险与金额两样（其余进高级编辑）；回车开题
S5 open_problem{origin.draft.lane=confirm}
S6 执行 ⇄ S7 判定 ⇄ S8 人介入
S9 关题：B1 由判官给 solved；B2 由人发起
S10 验收：B1 只读核对；B2 按验收清单逐条勾选
S11 封存判例
```

### 3.2 一步确认卡上必须有的东西

确认卡是人对这件任务唯一的一次事前判断，所以只放“开题之后不可改”的东西：

| 区块 | 内容 | 为什么在这里 |
| --- | --- | --- |
| 01 目标 | 目标陈述，原文区间逐段标号 | I4：之后不可改 |
| 02 判据 | B1：检查命令全文（等宽、证据语域）、`expect`、对照输入（空时标“无对照”）；B2：验收清单逐条 + 结构检查项，卡头写“终态最多为人工验收” | 判据先行 |
| 03 授权 | 每条规则：资源、模式、动作、风险（来自风险表，可改）；被默认拒绝删掉的入口列在下面，灰色 | 最小权限；人逐条看风险 |
| 04 预算 | 金额、墙钟；与全局默认的差异高亮；三道顶的当前值；“默认值来自占位表” | 预算硬顶；先验是估值 |
| 05 模型 | 本任务使用的模型档案（缺省为全局路由），只能从已登记的档案里选 | 任务级覆盖只许在全局之内 |
| 页脚 | “开始”（回车）、“编辑草案”（进 `/new/advanced`） | |

### 3.3 验收清单：B2 的判据先行

没有判官的任务，“怎样算做完”仍然必须在动手之前写下来，否则人工验收就退化成“看着差不多”。所以 B2 在 `Problem.goal` 上加一个可选字段（D3，不进等级函数、消费门与画像）：

```ts
goal.acceptance?: { id: string,             // a1、a2…，开题时由图服务按序号分配
                    text: string,           // 一条可以被人判断的陈述，≤ 200 字符
                    src: "span" | "human",  // 只许原文区间或人写的；模型起草的条目不进清单
                    needs?: "artifact" | "note" }[]   // 验收这一条时要附的依据
```

- **来源**（裁决附加 1，与一句话开题同规则）：原文里“交付”“要求”一类的句子由模型指认区间（出处“摘”），人也可以在确认卡上增删。模型不得自己写条目，理由与“模型不写检查脚本”相同（kaiti §3.1）：那等于干活的一方给自己出验收题。
- **登记与不可改**：清单随 `open_problem` 写入，之后不可改。要改清单，只能关掉这道题，重新开一道（克隆进高级模式）。
- **结构检查**：清单里 `needs: artifact` 的条目，附带一个 advisory 判官（交付物存在、格式合法），它只给读数，不让 Goal 到 E3。
- **验收操作**：`accept` 的事件体带 `{ checks: [{ id, verdict: "pass"|"fail", ref?: ArtifactId, note? }], seen: { seq, card_hash } }`。`validate` 要求清单里每条都有一项、`needs: artifact` 的条目 `ref` 指向本题的 exec 类或 input 类 Artifact、四顾清单（`closeout` 卡）里的非空项已逐条确认。任何一条 `fail` 时只能 `reject`，回到 S8（写 Hint 继续）或以 unsolved 关闭。
- **终态**：全部 pass 才是 `accepted`。报告首行写“人工验收（accepted），根结论等级上限 E0”。
- **只经 B 道**（裁决附加 1）：`accepted` 只能出现在 `goal.accept = human` 的题上；A 道与 B1 的题没有 `accept` 操作，终态只有 solved 与 unsolved。
- **永远分开呈现**（裁决附加 1）：今日、任务库、读数页、`pd` 与评测记录里，accepted 与 solved 各自计数；“成功率”“每解成本”一类读数的分子只取 solved，accepted 另列一行，不合并。

## 5. 零配置默认值的来源

> v0.9：开放道的默认值与 B 道一列相同，区别只有三处：没有 Goal 判官（`accept: open`）、原文里的检查命令进 `self_checks`、预算留 10% 作收尾保留。
