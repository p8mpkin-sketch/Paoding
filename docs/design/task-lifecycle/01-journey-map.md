# 01 端到端旅程地图

> 每站的格式固定：**责任方**（人 / 系统 / 智能体，只写一个主责；“系统”专指确定性代码）、**进与出**、**现有组件**（仓库里的路径）、**缺口**（Q# 对应 [04](./04-gaps-roadmap.md)）、**验收**（AC# 对应 [05](./05-acceptance.md)）。
> 状态记号：● 完整　◐ 部分　○ 无。

## 1. 十二站

### S0 设置就绪

一次性的前置站，不属于某一件任务，但每件任务都从这里取默认值和上限。

- **责任方**：人（一次配置，之后少改）。
- **进与出**：进的是模型档案、端点、密钥、全局硬顶、练习预算上限、预算先验源；出的是一份带版本号与摘要的设置快照，供 S3 校验与 S6 执行读取。
- **现有组件**：设置存储 `scripts/settings_hub.py`（`/v1/settings`、`/v1/keys`，#87）、钥匙环 `adapter/keyring.py`、`adapter/config/prices.yaml`（价目表）、`adapter/proxy.py`（换密钥、计量、超额拒绝）、网页 `/settings`（#87）、`qicao/policy.py` 的 `PriorSource` 与练习道信封（#88）。
- **缺口**：Q1 设置存储 ●、Q2 钥匙环 ●、Q3 三道硬顶 ●、Q5 先验占位表 ●（已记为 K21–K24）；Q4 练习道信封 ◐（文件与 `vet` 判定有，设置页呈现与内核按道检查没有）；Q6 设置页“系统”分组 ●（K28）；Q28 起草模型接设置层 ●（K32）。
- **验收**：AC0.1–AC0.6。
- 详见 [03](./03-settings.md)。

### S1 说出来

- **责任方**：人。
- **进与出**：人粘贴一段自然语言（入口、目标、交付、约束、时限）；出一份原文，登记前只存在本机草稿里。
- **入口的三种形态**：一句话输入框（主入口，**由「一句话开题」设计定义**，`docs/design/kaiti/README.md`，PR #83；路由 `/new`）；导入（批量，`web/src/pages/Import.tsx`，JSON 与 CSV 逐题成草稿）；克隆（`/new?from=<pid>`）。三种形态都只产出“草稿”，汇入同一个 S2/S3。
- **现有组件**：`Import.tsx`、`app/draft.ts`（草稿存本机 `paoding.wizard_draft`）、`Wizard.tsx` 的第一步。
- **缺口**：Q7 一句话输入框 ●（#88，K25）。
- **验收**：AC1.1。

### S2 起草

- **责任方**：智能体（起草模型）。
- **进与出**：进原文（答案先剪出、进保密库，起草模型看不到）与设置快照里的可选项（已登记的判官、模板）；出 **`Draft`**：模型只指认“原文的哪一段是什么”（字节区间加角色），有权威的字段的值必须是原文逐字子串或查表所得，模型自己写的只有题名。`Draft` **不是事件**，也不落盘为事实。
- **边界**：起草模型跑在图服务之外，与工作台前端也分开（前端仍不调模型，HMI §2 禁令 1）；它只看得到原文和公开的设置项，看不到密钥、保密库和其它任务的日志。起草失败或模型不可用时，人直接进 S4 的高级编辑，路径照样走得通。
- **现有组件**：无。一句话开题设计了独立进程 `qicao/`（`extract`、`draft`、`vet`、`service`，端点 `POST /v1/drafts`），它不持有人的令牌，不写图服务。
- **授权不在这里**：开题默认零出站，起草只在原文里标出提到的地址（`mentions`，供人看），不生成授权；授权在执行时按需申请（S6、S8）。
- **缺口**：Q8 起草服务 `qicao/` ●（#88，K26）。
- **验收**：AC2.1、AC2.2。

### S3 校验

- **责任方**：系统。这是地图上第一道确定性闸门。
- **进与出**：进 `Draft`（或高级编辑里人改过的草案）加设置快照；出 `Vetted`：每个字段的值、出处与“通过 / 收窄 / 拒绝”的理由码，画像预览，以及道别 `lane`：`practice`（练习道，零确认）、`confirm`（确认道，一步确认）、`refuse`（判据表达不出，给三条降级路）。
- **四条校验**（即一句话开题的 `vet() → Vetted`，带逐字段的出处账：摘、表、估、起草、人五种来源；本图只规定它们存在且是纯函数）：
  1. 判据可表达：判据草案必须能被已注册判官表达（例如对答案文件的 `exact_match`）；不能表达的，A 道拒绝、转 B 道的人工验收。
  2. 开题零出站：`scope` 恒为 `workspace`；原文里提到的地址只作 `mentions` 高亮。执行时要连外部，由智能体用 `request_scope` 申请，人在扩权卡上批，练习道按信封白名单确定性自动批（运行时扩权设计，#91）。
  3. 预算夹紧：按“原文写的数 > 花费画像 > 先验表档位 > 配置缺省”取默认值，再被练习上限（只在练习道）、单题硬顶、全局余量三道顶裁剪。
  4. Schema：与 `open_problem` 的 `validate` 同一套规则，profile 字段不接受（HT-2）。
- **现有组件**：`graph` 的 `open_problem` 校验（`graph/src/paoding_graph/reducer/problem.py`）、`GET /v1/profile/preview`（画像预览）、`GET /v1/judges`、`GET /v1/templates`。
- **缺口**：Q9 校验层 `vet` ●（#88，K27；切到零出站是运行时扩权第四步）。
- **最后一道墙在内核**：校验层跑在客户端一侧，可能有缺陷；零确认开题能做的上限由图服务在 `validate` 里按练习道信封检查（Q4）。所以校验层的缺陷最坏只能开出一道信封之内的练习题。
- **验收**：AC3.1–AC3.4。

### S4 确认

- **责任方**：人（`lane = practice` 时这一站由系统按规则跳过，放行条件见 [02 §2.2](./02-default-paths.md#22-零确认的放行条件)，界面只给一张开题回执）。
- **进与出**：进校验报告；出人的确认（或 A 道的自动放行记录）。
- **两种形态**：
  - **一步确认卡**（B 道默认）：一屏看完目标、验收清单、授权（逐条带风险）、预算（与全局默认的差异高亮）、模型档案；一个“开始”按钮。卡的样式见 [06](./06-frontend.md) 的 `confirm`。
  - **高级编辑**：即现在的四步向导（`Wizard.tsx`：要做什么 / 怎么算做完 / 能动用什么 / 花多少），路由移到 `/new/advanced`，可以从任何草案（确认卡上的“编辑草案”、拒绝页的第三条路、克隆）带着出处记号进入；向导里改过的字段，出处记为“人”。它同时是 `kaiti=off` 的对照臂。
- **现有组件**：`web/src/pages/Wizard.tsx`、`model/wizard.ts`、`app/submit.ts`（向导与导入共用的提交路径）。
- **缺口**：Q10 一步确认卡 ◐（卡、拒绝页、模型一块已有；缺验收清单块，L2；零出站后风险控件移到扩权卡）；Q11 高级编辑 ●（K29）。
- **验收**：AC4.1–AC4.3。

### S5 登记开题

- **责任方**：系统。
- **进与出**：进确认后的草案；出 `open_problem` 事件（判据、授权、预算、材料一并登记，画像由图服务推出），材料先 `PUT /v1/blobs` 登记为 input 类；初始提示作为第一条 Hint；有记忆召回时召回清单 `recall` 与开题同批登记（v1.5）。
- **现有组件**：`POST /v1/problems`、`app/submit.ts`、`tongjian/`（召回清单）、`graph` 的 Blob 仓库。
- **缺口**：Q12 设置摘要与任务级模型偏好写进开题事件体 ◐（摘要已有，#87；`prefs.model` 没有）；Q13 B 道所需的 `accept: human`（一句话开题的增量 16）与本文提出的验收清单 `goal.acceptance[]` ●（L2 第一批，K34）。
- **验收**：AC5.1–AC5.3。

### S6 执行

- **责任方**：智能体（会话里的模型）在系统的约束里干活。
- **进与出**：进 `/work` 派生的可做事项；出 Fact、Intent、exec 类 Artifact 与花费事件。
- **现有组件**：`sinan/`（读 `/work`、申请租约、按租约起会话）、`adapter/`（任务包、会话运行器、三个代理工具、端点代理计量）、`executor/`（沙箱、按租约编译授权、逐主机出站闸门）、`watchdog/`（过期回收、超预算终止）、`reducer/intent.py` 的 `touches` 校验。
- **阻塞原因多一种“等扩权”**：会话用 `request_access` 申请一条 `host:port`，`/work` 出现扩权卡（确认道）或由图服务按白名单当场批准（练习道）；批准后闸门热加，撤销后热撤，下一次连接即失败。
- **缺口**：Q14 按任务选模型档案（C13）○；Q15 按租约花费（C1）与花费序列（C2）◐（已有 `/budget` 总量）；Q29 运行时扩权（`request_scope`、`grant_scope`、`revoke_scope`，热加闸门，`needs_scope` 编进容器）◐（第一至三步已合入，第四步零出站开题在 #101）。
- **验收**：AC6.1–AC6.3。

### S7 判定

- **责任方**：系统（判官）。
- **进与出**：进判官请求；出 `judge_verdict`，等级由图服务重算（E0 / E3 / X）。
- **现有组件**：`judgebox/`（注册表、保密库、`exact_match`、`replay`、判官运行器），`graph/levels.py`。
- **缺口**：Q16 B 道的结构检查类判官（advisory：交付物存在、格式合法）○；Q17 召回复核的墙钟上限 60 秒 ◐（2026-11-19 cz 记的 follow-up，现在只有条数限界）。
- **验收**：AC7.1、AC7.2。

### S8 人介入

- **责任方**：人。地图上唯一可以在执行中途出现的人的站，所有入口都来自 `/work` 的 human 项。
- **五种介入**：r2 审批（每次租约一批）、扩权申请（运行时 `request_scope`，以及 Intent 的 `needs_scope`）、Hint（指导）、续期门（越过 80% 且 50% 以来无进展）、停滞处理。练习道白名单内的扩权由图服务确定性自动批准，不进人的待办。
- **现有组件**：`web/src/pages/Inbox.tsx`（待办）、`ui/ApprovalCard.tsx`（审批卡，带 `seen.card_hash`）、`ui/Hints.tsx`、`ui/ExtensionDialog.tsx`（续期门对话，读图服务的续期卡）、`pd approve|deny|hint|extend|budget add`。
- **缺口**：Q18 续期门 ●（K39：续期卡、`extend` 与 `budget_add`，门关着时停新的 explore）；Q19 扩权卡（开题授权 vs 申请的那一条、风险、批 / 拒 / 撤销）●（K30，#99）；Q20 人主动终止会话（C14）○。
- **验收**：AC8.1–AC8.4。

### S9 关题

- **责任方**：系统（A 道 Goal 到 E3 自动关题）；B 道由人发起，系统校验。
- **固定三步**（HMI §3.7）：四顾（影响面清单）→ 满志（终态三值）→ 藏刀（销毁容器、作废令牌、归档会话、判例封存）。
- **现有组件**：`reducer/close.py`（终态三值）、`cards.py` 的 `closeout` 卡、`watchdog`（预算或墙钟耗尽以 unsolved 关闭）。
- **缺口**：Q21 关题三步的交互界面 ●（K38：四顾逐条确认，没确认完不能验收）。
- **验收**：AC9.1、AC9.2。

### S10 验收

- **责任方**：人。任务的终点：人判断“这件事做好了没有”。
- **两种形态**：
  - A 道 solved：人只读核对。从结果页三次点击到证据根（HT-6），本机校验哈希；不需要任何按钮。
  - B 道 accepted：人按开题时登记的验收清单逐条勾选，每条附依据（交付物 Artifact 或说明），四顾清单非空项逐条确认之后才能点“验收”。拒收是合法输出，回到 S8 写 Hint 或以 unsolved 关闭。
- **现有组件**：`Cockpit.tsx` 的检视与下钻、`Problems.tsx`（任务库，按终态三值筛选）、`pd report`。
- **缺口**：Q22 结果页（结构化报告 C6，与 `pd report` 同源）●（K36）；Q23 验收清单的勾选界面 ●（K37）。
- **验收**：AC10.1–AC10.3。

### S11 沉淀

- **责任方**：系统（投影与封存）；复盘的文字由智能体起草、人审核。
- **进与出**：进已关闭的题；出判例封存（`case_seal`）、通鉴记忆条目、投影资产（判据模板、切口先验、花费画像），以及读数（归因表、折损账、复做节省率）。
- **现有组件**：`tongjian/`（记忆最小版，PR #81）、`web/src/pages/Readings.tsx`（读数页）、`eval/`（对照臂）、`docs/m1/readings/`。
- **缺口**：Q24 投影资产 ○（M2 后半）；Q25 记忆的人工纠偏入口（`mem_pin`、`mem_forget`）◐（服务方法已有，缺写端点与 `pd memory`）；Q26 读数页补齐“暂不可用”的量 ◐（工作台第四期）。
- **验收**：AC11.1–AC11.3。

## 4. 外部组件站位

> 裁决附加 3（2026-11-19）：题库服务与评测台在图外，只经命名的端口接进来，不另画第二张图。它们自己的内部流程（出题、跑臂、收集）不是站；凡是要进入题目日志的东西，都经下表的端口走某一站，按那一站的规则处理。

| 外部组件 | 是什么 | 接哪一站 | 方向与端口 | 它给地图什么 | 它永远不做 |
| --- | --- | --- | --- | --- | --- |
| 题库服务 | 测试方维护的题目与答案集，可能在本机或别处；**系统不读取、不推导任何本机题库或校准目录** | S1 说出来 | 推入：经导入（JSON、CSV，K1）或 `pd kaiti` 逐题成草稿；答案经 `PUT /v1/vault` 写进保密库 | **练习题来源**：A 道（练习道）的题从这里来；v1.5 的“练习化”标准案例也从这里来 | 不直接写图服务；不绕过 S3 校验与练习道信封；不让起草模型看到答案 |
| 题库服务的校准读数 | 测试方按档位整理的花费读数 | S0 设置（预算先验） | 推入：一份“档位 → 默认预算”表，经 `PriorSource` 注入（一句话开题 §5.2） | 确认卡与回执上的默认预算 | 不进等级、消费门与画像（I8）；不越过三道硬顶 |
| 评测台 `eval/` | 对照实验运行器：baseline、full、Bk、Bn 各臂 | full 臂接 S5；读数接 S11 | full 臂经 `POST /v1/problems` 开题，与人的开题同一条路（题组一次预登记，见 02 §2.4）；baseline、Bk、Bn 臂不经图服务，在执行层同款沙箱里跑 | **对照读数来源**：`docs/m1/readings/` 的原始记录与 `meta.json`，读数页（S11）与评分报告读它 | 不往题目日志写 baseline 臂的任何东西；不把对照读数当作某道题的证据；不改判官或判据 |

两条边界规则：

1. **只经端口进图。** 外部组件的产出要么成为某一站的输入（草稿、先验表、开题请求），要么成为 S11 的读数；不存在“外部组件直接改某道题状态”的路径。新外部组件接入时，按宪章 §3 的修订规程在本表加一行，写清它接哪一站、经哪个端口、永远不做什么。
2. **读数分开。** 评测台的读数按臂、按终态分列；accepted 与 solved 永远分开计数（裁决附加 1）。
