# 06 关键页面交互稿

> 视觉语言延续第四版定稿（`ui-redesign/v4/`）：宣纸底、墨字、朱红只标“需要你”、十二栏界栏、01/02 编号、刻度尺、等宽状态行、形状记号加文字（不靠颜色区分）。
> 交互稿是叠在 v4 原型上的静态 HTML：`wireframes/lifecycle.js` 接在 M2 设计用的 `base.js` 之后，只用 `kit.css`、`screens.css` 的令牌和已有类，新增样式写在文件开头的 `LCSS` 里。全套原型（含 `base.js` 等）与二倍图在项目共享文件夹 `task-lifecycle/`，入口 `prototype/index.html?s=<屏>`。仓库里的截图是一倍、降到 96 色的版本。
> 一句话开题自己的五张稿（`docs/design/kaiti/wireframes/kt-*.png`：输入框、练习道回执、确认卡、拒绝页、高级模式）不在这里重画。本文的 `confirm` 只画本图在确认卡上补的两块（验收清单、模型），版式以 kt-confirm 为准。

## 屏一 地图总览 `map`（`wireframes/map.png`）

- **位置**：今日 / 任务怎样走完。替代 v4 的“初见”页成为新手第一屏，也从 ⌘K 输入“地图”到达。
- **内容**：十二站分“开题之前”“开题之后”两段，每段三条泳道（人、系统、智能体），每站一张卡：站号、站名、主要组件、完整度记号（● ◐ ○ 加文字）。人的站左边一道朱红；智能体的站用虚线框。两段下面各有两条道的轨迹：虚线表示该道跳过此站，朱点表示该道在此站必须有人。
- **交互**：点一张站卡，右侧抽屉列出这一站的组件、缺口（Q#）和验收（AC#），与 01、04、05 同源；“新建任务”仍在顶栏。
- **数据**：完整度来自本目录 04 的表，构建时作为静态数据打包，不是运行时读数（它描述的是产品，不是某一道题）。

## 屏二 设置·模型与密钥 `set-models`

- **三节**：01 模型档案（名称、端点、模型、家族、档位、价目）；02 角色路由（起草、Bootstrap · Reason、Explore、Verify 各用哪个档案，注明“新会话起生效，会话中途不换模型”）；03 密钥（每个端点一个槽）。
- **密钥槽的三种状态**：已设（形状记号“设”+ 指纹 + 设置时间 +“清除”）；未设（密码框 +“设置”）；来自配置文件（朱框提示迁移，D4 过渡期）。没有“显示密钥”的按钮，读端点也读不回来。
- **页头**右侧常显设置版本与摘要；“变更记录”在左侧导航最后一项。

## 屏三 设置·预算与硬顶 `set-budget`

- **三道顶画成三根刻度条**（对数长度），从上到下递增：练习上限（与练习道信封同数，图服务校验）、单题硬顶（所有开题，向导也受限）、全局硬顶（端点代理执行，条上叠已花）。保存时校验次序。
- **风险表**：资源与模式 → 风险，形状记号与文字并排；最后一行永远是“其它 · 任意 · r2”，不能删。
- **预算先验**：只读表格；占位表时节头有朱批“占位表 · 数字没有读数依据”。说明行写明“系统不读取任何本机题库或校准目录”。

## 屏四 确认道·自由任务 `confirm`

- **顶部站位条**停在 S4，“确认 · 等你”为朱红；右上的印章写“终态最多：人工验收”。
- **五块**：01 目标、02 验收清单（每条带出处记号“摘 ¶n”或“人”，以及验收时要附的依据；“加一条”旁写明模型不起草验收条目）、03 授权（风险可往上调；被默认拒绝删掉的入口灰色列出）、04 预算（显示单题硬顶与全局余额；“预算默认值来自占位表”）、05 模型（下拉只列已登记档案）。
- **页脚**：改原文 / 编辑草案（高级）/ 开始（回车）。

## 屏五 工作区站位条与扩权差异卡 `ws-stations`（另有墨色 `ws-stations-ink.png`）

- **站位条**放在主区顶部，十二格，当前站墨底反白，等人的站朱红下划线并写数量。它是 `status`、`active`、`human_todo`、终态的纯函数，不推断进度（工作台设计的既有约束）。
- **扩权差异卡**（Q19）在右栏：上半是“开题时的授权”，下半是“申请之后”，多出的那条朱底并写风险等级；按钮是“批准这一条”与“拒绝并写理由”，卡底显示 `card_hash` 的前缀（H2）。
- **“此题的点位”**一节列出本题的人的点位与状态（开题确认、扩权、续期门、验收），与 02 §4 的表对应。

## 屏六 验收 `accept`

- **站位条**停在 S10，“验收 · 等你”。
- **关题三步**横排：四顾（已完成）→ 满志（当前）→ 藏刀。
- **验收清单**：开题时登记的条目逐条一行，每行“通过 / 不通过”二选一，下面一行是依据（exec 类 Artifact 的路径、哈希与本机校验结果，或人写的说明）。未判的条目以朱红写“待判 · 需要附说明”。
- **终态预览**卡：终态“人工验收（accepted）”、根结论等级上限 E0、“报告首行不写已证明”。验收按钮在有未判条目时不可用，并写明原因；另两个按钮是“退回”（写指导继续）与“以未解出关闭”。

## 可访问性与一致性

- 所有状态都有形状记号加文字（完整度 ● ◐ ○，风险 r0 / r1 / r2 带框文字，待办“待”字印），颜色只是第三重编码。
- 站位条是 `role="list"`，每格的无障碍名称以可见文字开头（WCAG 2.5.3），当前站与等人的站另加 `aria-current` 与“等你”文字。
- 实现时这六屏都进 `e2e/a11y.spec.ts` 的三主题 axe 检查。
