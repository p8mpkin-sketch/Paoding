## 0. 读完应能回答的三个问题

### ① 每项能力的最小版本是什么样

| 能力 | 最小版本 | 一句话 |
| --- | --- | --- |
| 一 跨任务记忆 | 通鉴日志 + 关题即封存判例（从 M3 提前，纯投影）+ 开题时召回同环境的已判定事实，由不含模型的召回任务交给新题判官重跑，通过的成为新题的 E3 节点；另带走不通的路（只作提醒）与花费画像 | 旧事须重验，方可为据 |
| 二 经验沉淀 | 判据模板、切口先验、花费画像三种由判例确定性投影的资产（零模型）；标准案例导入后先开练习题让系统自己解出，解出才产资产；"第二次比第一次省多少"按配对反事实度量 | 资产只从被判官复现过的解题链里来 |
| 三 多会话协同 | 授权规则级的资源占用（守门官）；按会话的分账与工具台账（量具）；并行宽度与"退回串行"作为 `/work` 的派生量 | 拆分归 Reason、汇合归图，内耗过线就收拢 |

### ② 拿什么读数证明它有增量

| 能力 | 主读数 | 对照臂 | 关键消融 | 过关线（预登记） |
| --- | --- | --- | --- | --- |
| 一 | 复做节省率 S_tok、S_wall（同一第二实例，记忆开对记忆关） | `memory=off`；诚实基线"B1 + 贴上次笔记" | `recall_noverify`（漂移变体上测污染率） | S_tok ≥ 25%、S_wall ≥ 15%，解题率不降；须赢"贴笔记"；不复核时污染率显著更高 |
| 二 | 换环境的同类题上的 S_tok、S_wall；导入标准案例后同签名新题的 S_tok | `assets=off`；未导入 | 三种资产各关一个；"导入即资产"（跳过练习）+ 注入错误案例 | S_tok ≥ 15%、S_wall ≥ 10%；单资产贡献 < 3 个百分点即删 |
| 三 | 可分解组的墙钟比、成本倍数；强耦合组的成本 | `parallel=fixed1`（串行）、`fixed3`（现状） | `fallback=off`；`claims=off`（只测冲突） | 可分解组墙钟 ≤ 0.7×、成本 ≤ 1.2×；强耦合组成本 ≤ 1.05×；写冲突为 0 |

全部臂与阈值见 [04](./04-proof-plan.md)。样本只有 12 对时结论标"方向性"，M3 扩到 30 对复核。

### ③ 先做哪个、后做哪个、为什么

```
M1 收尾（前置）  G1 四臂读数（Bk、Bn）· 复做题组与实例生成器 · 按会话分账 C1 · 题组预登记
      │
M2 前半   ┌─ 能力一 最小版（通鉴日志、判例投影、召回复核）
          └─ 能力三 的守门部分：资源占用 touches（不等任何读数）
      │      判例开始积累
M2 后半   能力二 最小版（三种投影资产、标准案例导入与练习、复做读数）
      │      ← G1 达标 且 50 题集里有可分解组
M2 末/M3  能力三 其余：并行宽度派生、退回串行
M3        一 的扩展（封存摘录作出处、seal_revoked 联动）· 三 的工作区写时复制
M4        二 的扩展（Playbook 蒸馏、人审、复演门；与规格"通鉴管线先行"同序）
M5        三 的扩展（子题与托管、题组内跨题资源占用）
```

理由按分量排：

1. **证据先行（红线 5）。** 对等重跑之后，q1 上单 CLI 5/5、$0.0118、25.5 秒，全栈 3/3、$0.016、30.7 秒：易题上厚路径贵 36%、慢 20%，G1 还没有读数。并行放大的是厚路径，厚路径的价值没证明之前做并行优化，等于给可能被删的编队加速。所以能力三的优化部分排在 G1 之后，并且 G1 不达标就不做（[04](./04-proof-plan.md) Q5）。记忆则同时服务薄路径（召回在 Bootstrap 之前），不论 G1 结果如何都有用，适合先做。
2. **依赖。** 资产是判例的投影，判例要先开始积累；记忆的通鉴日志与判例投影正是资产的原料。所以一先于二。
3. **验证成本。** 能力一的复核不耗 token，复做题组上跑一轮很便宜；能力二要等判例积累到同签名 ≥ 2 道 solved；能力三要专门的可分解题组（未证明清单第 20 条）。
4. **正确性缺口要立刻补。** 司南今天已经有 `max_sessions=3`，而租约只按 Intent 互斥，不按资源互斥：两个不同 Intent 同时写同一目标的风险现在就在。资源占用是守门官，不需要读数证明，所以从能力三里单独提前。
5. **与既有路线图对齐。** 规格 M3 的判例自动封存被提前到 M2（它是纯投影，不依赖 M3 的摘录规则）；M4 的通鉴管线、M5 的子题保持原位，本设计只在它们前面垫了最小版本。

## 3. 硬约束核对

**五条红线。** 红线 1：新状态全部是事件日志或其确定性投影，召回与资产投影不调用模型，Playbook 蒸馏（扩展版）只产候选、经确定性检查与人审才发布。红线 2：记忆与资产过界的身份只有叙述与 input 类判据，证据仍只来自新题判官的重放。红线 3：环境键与签名键是不透明字符串，判据模板与锦囊是唯一含领域词的地方。红线 4：上表。红线 5：每项能力都有诚实基线与证伪线，不达标就删（[04](./04-proof-plan.md) 的"不达标的动作"一列）。

**八条不变量。** I1 写入无模型：同上。I2：召回节点没有判官通过就不是可采信前提（[01](./01-memory.md) 验收第 3 条）。I3：等级照旧派生；记忆状态与并行度也按同一原则派生、不可写。I4：召回清单与资产索引在开题事件里登记、之后不可改。I5：`touches` 只能收窄能力，校验与风险同一处。I6：不涉及。I7：记忆从不携带等级过界。I8：切口先验、花费画像、节省率都是估值或读数，不进等级函数与消费门。

**六契约只扩展。** 内核增量见 §4，全部是可选字段、新角色、读侧派生；既有操作的语义与事件形状不变，旧日志重放逐字节不变。已合入资产（代码、规格、读数）一律不改；本设计提出的规格变更待 cz 裁决后另开 PR 并入规格。

**工程约束。** 单文件 500 行：新组件按"通鉴服务 / 召回运行器 / 投影 / 端点"拆模块，参照 `graph/reducer/` 按事件族拆分的做法。确定性 reducer：通鉴日志有自己的 reducer，复用 `eventlog.py` 与 JCS。长时间运行（复做题组、并行题组）推分支交给 GitHub CI。

## 6. 开放问题

1. **环境键的缺省推导粒度。** 推得太细，同一目标换个端口就召回不到；太粗，会召回不相干的事实（复核会挡住，但浪费判官时间）。本文取"执行规格名 + 授权目标"，并允许开题人显式给 `labels.env`。复做题组的读数出来后再定。
2. **排除路径要不要复核。** 最小版本只作提醒。复核它需要把"已证伪"在新题重新判两次（等级函数的 X 要两次一致失败），成本翻倍，收益未知。
3. **跨题实时共享。** 同一题组里运行中的题互相订阅进行中封存（能力一扩展版）能让并行从题内扩到题间，但它让题与题之间出现了运行时耦合；等能力三的题内读数再说。
4. **练习题组的预算由谁出。** 本文让它单列、不占生产预算；如果标准案例很多，需要一个人可见的练习预算上限，放在设置页。
