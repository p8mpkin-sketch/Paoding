# 能力三：多会话与多工具协同

> 上位文档：[README](./README.md)。依据规格 4.1（司南与八仙规则表）、4.6（子题与多节点）、`sinan/SPEC.md`（并发，审计 P1-3）。

## 0. 现状与缺口

现状比"单会话串行"略多一点：司南已有线程池（`max_sessions` 默认 3），不同 Intent 的 Explore 会话可以同时在途；内核用租约保证同一目标只有一个会话、Reason 每题互斥（`sinan/SPEC.md`）。缺的是五样东西：

1. **资源冲突没有建模。** 两个会话的 Intent 不同，却可能同时改同一个目标（同一条 r1 授权规则）。租约只按 Intent 互斥，不按资源互斥。这是现在就存在的正确性缺口，不是优化。
2. **工具调用跨会话不可见。** 谁在用哪条授权规则、跑了什么命令、产出被谁引用，日志里都有，但没有投影，人和 Reason 都看不到。
3. **成本不按会话分账。** 预算账本按题汇总，没有按租约与按 Intent 的分项（工作台设计 C1）。
4. **并行收益没有读数。** 不知道并行是在省墙钟还是在烧钱。
5. **没有退回串行的条件。** `max_sessions` 是配置值，不随读数变化。

## 1. 一页结论

1. **拆分仍归 Reason，汇合仍归图。** 不让会话派生会话、不让会话之间直接交接：决策单线程是多智能体有效形态的前提，自然语言交接是失配的主要来源（规格 4.6 引 [证据 S43][S44][Z32]）。并行的单位是互不依赖的带判据 Intent，会话之间唯一的接口是图上的论断与判据。
2. **新增一个守门官：资源占用。** Intent 可声明 `touches`（它要用哪几条授权规则、读还是写）；图服务派生资源冲突，同一条写规则同时只给一个在途租约；执行层按 `touches` 收窄能力，顺带把最小权限做实。
3. **新增一组量具：会话分账与工具台账。** 按租约、按 Intent、按授权规则归集花费、命令与产出，全部是日志投影。
4. **并行度是派生量，不是配置。** `/work` 给出 `parallel {mode, width, reason}`：宽度取互不依赖且无资源冲突的 open Intent 数、剩余可预留预算、配置上限三者的最小值；滚动窗口里并行折损率过高或同伴冲突过多时派生为串行，带滞回地恢复。规则可重放，司南只照做。
5. **最小版本**：资源占用 + 分账与工具台账 + 并行度派生与退回串行。用评测台在"可分解"与"强耦合"两组题上对比串行、固定 3、自适应三条臂。并行收益的前提是厚路径本身有价值（G1，未证明清单第 1 条），所以这项能力里只有资源占用不等 G1，其余排在 G1 的读数之后（README §4）。

## 2. 宪法审查（入库四问）

| 机制 | 弥补模型缺陷还是世界性质 | 被相信还是被测量 | 官 | 启用条件 | 退役信号或长存依据 | 对照臂 |
| --- | --- | --- | --- | --- | --- | --- |
| 资源占用与冲突派生 | 世界：共享的可变资源存在，并发写会互相覆盖 | 被相信 | 守门官 T-0 | 有 r1 及以上规则且并行宽度 > 1 | 长存 | 无（只在评测里跑 `claims=off` 计冲突数，不作生产形态） |
| 按 `touches` 收窄能力 | 世界：对抗面（最小权限） | 被相信 | 守门官 T-0 | 同上 | 长存 | 无 |
| 并行度派生（含 C2） | 模型缺陷：模型不会自行分配并行探索（八仙的同一条） | 被测量 | 感知官 T-1 | M2 起；互不依赖的 open Intent ≥ 2 | 模型自带并行搜索且预算自管，`parallel=fixed1` 消融不劣（与八仙同一信号）；或单个 Reason 能管的并发翻倍而切口命中率不降（规格 4.6） | `parallel=fixed1`、`parallel=fixed3` |
| 退回串行规则 | 模型缺陷的同一条（并行收益为负时止损） | 被测量 | 感知官 T-1，随并行度派生 | 同上 | 随并行度派生一起退役 | `fallback=off` |
| 会话分账、工具台账、并行折损 | 都不是 | 被测量 | 量具 T-0 | 常开 | 永不退役 | 无 |

典故的对应：手肩足膝"莫不中音"，节奏来自共同的对象而不是指挥家，这是图作为汇合点；"每至于族，怵然为戒，视为止，行为迟"，这是退回串行，与 knot 的"收拢优于加宽"同一个方向。

## 3. 任务怎么拆、怎么分工

```
Reason（每题唯一）──add_intent{premises, done, touches?}──▶ 图
图 ──/work：open Intent − 有未达成前提的 − 带 knot 的 − 资源冲突的 ──▶ 可并行集合 P
图 ──parallel{mode, width}──▶ 司南：按估值排序（零级），取前 width 个申请租约
司南 ──租约──▶ Adapter ×width：每个会话一个 Intent、一对容器、一份任务包
会话 ──submit──▶ 图（单写者排序）；会话之间不直接通信
```

- **互不依赖**沿用规格 4.1 的 C2：两个 Intent 没有直接或传递的前提关系。新增一条：它们的 `touches` 里没有同一条写规则。
- **同一 `as_of_seq` 的一批会话**按规格 4.1 错峰启动（首个会话出模型输出后再起其余），以复用前缀缓存。
- **分工按角色而不是按人设。** Explore 之间没有"前端专家""后端专家"的分工，差别只在 Intent。规格 4.2 的模型分层（M2）决定每个会话用哪一档，是另一条消融，不在本文。

### 3.1 资源占用

```ts
Intent.touches?: { rule: number,                 // Problem.scope 的下标；必须 ≤ Intent 风险（I5 的同一校验）
                   mode: "read" | "write" }[]     // write：该规则 risk ≥ r1 时才允许；r0 规则一律按 read
// 缺省：等于"全部 risk ≤ Intent.risk 的规则"，r1 以上按 write。保守，所以不声明也正确，只是并行度低
```

派生规则（`/work`，确定性）：

```
holds(lease)     := 该租约 Intent 的 touches（缺省按上式展开）
conflict(i, j)   := ∃ rule: (i 写 rule ∧ j 碰 rule) ∨ (j 写 rule ∧ i 碰 rule)
可开(i)          := ¬∃ 在途租约 l: conflict(i, intent(l))
```

执行层按租约编译能力时只放行 `touches` 里的规则（I5 的强制点不变，只是集合更小）。会话越界访问别的规则仍是 `scope_violation`，记进折损账。

**跨题的同一资源**（扩展版）：同一题组里不同的题碰同一 `env_key` 的同一写规则时，题组层派生同样的冲突。最小版本只做题内。

## 4. 怎么汇合、冲突怎么裁决

| 冲突 | 例子 | 裁决 | 机制归属 |
| --- | --- | --- | --- |
| 论断冲突 | 会话 A 观察到 8081 开着，会话 B 观察到关着 | 争议，由判官重放裁决；模型反证只产生争议，X 只来自判官或人 | 规格 3.1.3，已有 |
| 结果冲突 | 两条竞速路线都提交了同一 Intent 的候选 | 先过判官者胜（按裁决事件的 seq），其余租约取消；落败花费记在"八仙的竞速"名下 | 规格 4.1，已有 |
| 资源冲突 | 两个 Intent 都要改同一份配置 | 不让它发生：§3.1 的派生串行化 | 本文新增 |
| 预算冲突 | 宽度 3 时剩余预算只够两个预留 | 预留原子，第三个租约 `over_budget` 是等待不是停机 | `sinan/SPEC.md`，已有 |
| 前提被同伴证伪 | A 在用的前提被 B 的反证打成 X | A 的 Intent 被放弃，释放预留；花费记为 `sibling_pruned`（§5 的并行折损之一） | 规格 3.1.3 的放弃机制，新增分类 |

汇合点只有一个：Reason 下一轮读到的图。多个会话的产出不需要"合并"，因为它们本来就写在同一条日志里；需要组合多个结果时，Reason 加一条以它们为前提、带判据的 Intent，由判官判组合是否成立。工作区类资源（规格 3.6.2 的 `workspace`，M3）在扩展版里给每个租约一份写时复制的快照，产物以 Artifact 形式回到图里，组合同样走带判据的 Intent，不做自动合并。

## 5. 成本怎么分账

全部是日志投影，不调用模型（工作台 C1、C2 的落地）：

```ts
type LeaseSpend = { lease: string, role: string, intent?: string, tier: string,
                    spend: Budget,                       // 端点代理的 cost 事件按租约归集
                    rules: { rule: number, execs: number, write: boolean }[],   // 工具台账
                    artifacts: string[],                 // 本租约登记的 exec 类 Artifact
                    consumed_by: { fact?: string, intent?: string }[],          // 产出被谁引用
                    outcome: "cut" | BreakKind }         // 折损账的割或折（规格 8.4）
type ParallelReading = { window: string[],               // 最近 W 个并行租约
                         spend: Budget, overhead: Budget,
                         overhead_by: { race_lost, sibling_pruned, dup_exec, reserve_idle }: Budget,
                         sibling_conflicts: number }
```

**并行折损**是规格 8.4 折损账的四个新子类，只在并行宽度 > 1 时计：

| 子类 | 含义 |
| --- | --- |
| `race_lost` | 竞速落败路线的花费（已有，归到这里汇总） |
| `sibling_pruned` | 因同伴的反证而放弃的 Intent 的花费 |
| `dup_exec` | 同一命令（`sha256(cmd ‖ rule)`）在两个并发租约里各跑一次，后一次的花费按回合比例估算 [观点] |
| `reserve_idle` | 因预留被同伴占着而等待的租约数 × 等待事件数（不计钱，只计次数，用于解释墙钟） |

## 6. 并行度控制与退回串行

### 6.1 宽度

```
width := min( cfg.max_sessions,
              |P|,                                    // §3 的可并行集合
              ⌊剩余可预留预算 ÷ median(P 中 Intent 的预算)⌋,
              1 若 mode = serial )
```

规格 4.1 的既有规则（剩余预算低于 20% 时并发 1、r2 并发 1、knot 不认领）照旧优先。

### 6.2 退回串行（派生，可回放）

最近 W = 6 个"在并行宽度 > 1 时启动"的 Explore 租约结束后，以下任一成立，`mode` 派生为 `serial`，`reason` 写明是哪一条：

| 信号 | 阈值 | 含义 |
| --- | --- | --- |
| 并行折损率 `overhead ÷ spend` | ≥ 35% | 多开的会话大半在内耗 |
| 同伴冲突数 `sibling_conflicts`（同伴之间的争议 + `sibling_pruned` 次数） | ≥ 2 | 切口不是真独立，前提在打架 |
| 并行会话的割率 | < 串行会话割率的一半，且串行样本 ≥ 3 | 并行会话在白跑 |

恢复（滞回）：`serial` 之后至少完成 3 个串行租约，且 `|P| ≥ 2`，且这 3 个租约没有新的争议，才回到 `parallel`。同一题内第二次退回串行之后不再恢复。

全部输入都是日志里的事件计数与预算投影，不读时钟，所以同一 `as_of` 两次计算结果相同，人可以在时间轴上看到它在哪个序号、因为哪条信号切换。

**题外的退回**（评测层，红线 5）：M2 的 50 题集上，如果自适应臂在可分解组上的墙钟没有比串行快 30%，或在任一组上解题率低于串行，`max_sessions` 的默认值改为 1，并行只在人显式开启时用。

### 6.3 失败兜底

| 失败 | 兜底 | 已有还是新增 |
| --- | --- | --- |
| 会话崩溃、卡死 | 租约过期，Intent 回到 `/work`；哮天犬清孤儿容器 | 已有 |
| 同一 Intent 连续失败 | knot：不认领、不竞速，等 Reason 看清或换缝 | 已有（M1） |
| 模型后端不可用 | `routing.yaml` 按序回退；整档不可用则该角色的租约不发 | 已有（4.2） |
| 并行内耗 | §6.2 退回串行 | 新增 |
| 资源冲突 | §3.1 串行化 | 新增 |
| 同伴证伪前提 | 放弃 Intent、释放预留，Reason 下一轮重切 | 已有机制，新增计账 |

## 8. 度量与证明（摘要；完整计划见 [04-proof-plan](./04-proof-plan.md) §4）

题集分两组，M2 扩题时按结构挑：**可分解组**（Goal 至少要 3 个互不依赖的子判据，例如三个服务各自的检查）与**强耦合组**（每一步都依赖上一步的发现）。未证明清单第 20 条（可分解工作负载占比）由这个划分顺带读出。

| 臂 | 说明 |
| --- | --- |
| `parallel=fixed1` | 串行，对照 |
| `parallel=fixed3` | 现状（`max_sessions=3`，无资源占用） |
| `parallel=adaptive` | 最小版本：资源占用 + 宽度派生 + 退回串行 |
| `fallback=off`（消融） | 自适应但不退回串行 |
| `claims=off`（安全消融，只在含 r1 写规则的题上跑） | 计资源冲突导致的判官失败与 `scope_violation` |

预登记阈值：可分解组上 adaptive 对 fixed1 墙钟 ≤ 0.7×、成本 ≤ 1.2×、解题率不降；强耦合组上 adaptive 的成本 ≤ fixed1 的 1.05×（退回串行确实生效），而 `fallback=off` 的成本更高；`claims=off` 出现的写冲突在 adaptive 下为 0。

## 9. 最小版本与扩展版

| | 最小版本（M2） | 扩展版 |
| --- | --- | --- |
| 冲突 | 题内资源占用 | 题组内跨题资源占用（同 `env_key` 的写规则） |
| 隔离 | 共享执行容器内的规则级互斥 | 工作区写时复制快照（M3 的 `workspace` 资源种类） |
| 工具协同 | 工具台账（只读投影）、`dup_exec` 计数 | r0 命令结果缓存：同一规则在两次写之间，相同命令直接返回上次的 Artifact（资源版本号由写租约的结束事件推出） |
| 并行度 | 宽度派生、退回串行 | 与模型分层联动：宽度 > 1 时非关键路径的 Intent 走中档 |
| 规模 | 单题、`max_sessions ≤ 5` | 子题与托管（规格 4.6，M5）：单题 open 的 Intent 超过 Reason 一轮的处理量时拆子题 |
| 跨题实时 | 不做 | 同一题组里运行中的题订阅彼此的进行中封存（能力一扩展版） |

**验收**（最小版本）：

1. 不声明 `touches` 时，派生出的冲突集合等于"同风险等级以上的写规则全部互斥"，既有测试不变。
2. 任意两个在途租约的 `touches` 之间没有写冲突（参考模型加一条性质测试，随机生成 Intent 与租约序列）。
3. `parallel` 的派生在任一 `as_of` 重放结果相同，切换序号与原因逐条一致。
4. `LeaseSpend` 之和等于 `/budget` 的已花，逐事件一致。
