# 能力一：跨任务记忆

> 上位文档：[README](./README.md)。术语以[基座规格 v1.4](../base-layer-spec-v1.md)（下称"规格"）为准。
> 本文只出设计。标注沿用规格：`[观点]`、`[假设 M#]`；官类按[官知止总纲](../paoding-allegory-mapping.md)的三类制。

## 0. 一页结论

1. **记忆不是新的器官，是通鉴的一个读法。** 规格已经有通鉴日志（2.4）、判例 `Case`（4.3）与"等级不出题"（I7）。本文不另建记忆库，只回答规格没回答的五件事：记什么、忘什么、怎么检索、怎么防过时、怎么退役。
2. **记忆分两层："知此牛"与"知牛"。** 此牛层记某一个环境的事实（目标上有什么、哪条路走不通），按环境键 `env_key` 归档，与模型无关，换代不失效；类牛层记一类题的做法（切口骨架、判据、花费画像），按结构签名归档，随 `model_epoch` 重新挣位置。两层的失效规则不同，混在一起就会出现"换了模型把环境事实也清掉"或"环境变了还在用旧切口"两种错。
3. **带进新题的方式只有一条：先复核，再采信。** 此牛层的每条记忆都带着它当初的判据。新题开题后，一个不含模型的召回任务把这些判据在新题里重新提交、由新题的判官在洁净容器里重跑：通过的，成为新题自己的 E3 节点；不通过的，记一次过期。记忆从来不以等级的身份过界（I7），也从来不以模型自述的身份成为前提（红线 2）。复核不耗 token，只耗判官容器的秒数。
4. **记忆状态不存储、不可写，是通鉴日志的派生量**，与等级同构（I3 的同族）：活跃、休眠、过期、退役四态由事件推出，人能做的只有"钉住"与"遗忘"两个带留痕的操作。
5. **最小版本**：通鉴日志 + 判例投影（从 M3 提前，纯投影）+ 召回复核，只做此牛层的环境事实与排除路径，以及类牛层的花费画像。内核增量三处，全部可选、带开关 `memory=off`。用评测台的"复做题组"独立验证（§7）。

## 1. 宪法审查（入库四问）

| 机制 | 弥补模型缺陷还是世界性质 | 被相信还是被测量 | 官 | 启用条件 | 退役信号或长存依据 | 对照臂 |
| --- | --- | --- | --- | --- | --- | --- |
| 通鉴日志与判例投影 | 世界：会话必死，跨任务持久是系统的定义（薪火相传） | 被相信（作为事实记录：发生过什么） | 守门官 T-0 | 每题关闭时 | 长存：审计的延伸 | 无 |
| 召回（挑哪些记忆带进新题） | 模型缺陷：模型没有跨会话记忆，也读不完全部判例 | 被测量（召回是否省钱） | 感知官 T-1 | 通鉴里有同 `env_key` 或同签名的活跃条目 | 原生长期记忆的模型在 `memory=off` 下复做不比 `memory=recall` 贵（§7 的 S_tok 置信下界 ≤ 0），连续两个里程碑成立 | `memory=off` |
| 复核（召回的判据在新题重跑） | 世界：环境会变，上次为真的观察这次未必为真 | 被相信（复核的结论就是新题判官的裁决） | 守门官 T-0 | 召回开启时常开 | 长存：环境漂移是世界的性质 | `memory=recall_noverify`（只作消融，测污染，不作生产形态） |
| 记忆状态派生与退役规则 | 世界：记忆会过时、出处会被撤销 | 被相信 | 守门官 T-0 | 常开 | 长存 | 无 |
| 记忆读数（召回命中率、在链率、污染率） | 都不是 | 被测量 | 量具 T-0 | 常开 | 永不退役 | 无 |

退役动作：召回退役时 `memory=off` 常态化，通鉴日志与判例照常封存（它们是守门官），只是不再自动带进新题。

## 2. 记什么

### 2.1 来源：只从封存的判例里取

关题时规格 4.3 的第 1 步追加 `case_sealed`，这是纯投影，不调用模型。本文把它从 M3 提前到 M2（它不依赖 M3 的摘录登记规则，只用到链头的 `Seal` 结构）。记忆条目是判例的二次投影，同样不调用模型。

```ts
type MemKind = "env_fact" | "excluded" | "cut_prior" | "check_tpl" | "spend_profile"
type MemItem = {
  id: string,                    // sha256(JCS({kind, scope, check_hash | content_hash}))：同一条判据在同一作用域只有一条
  kind: MemKind,
  scope: { env_key?: string, sig_key?: string },        // 此牛层用 env_key，类牛层用 sig_key
  source: { case: string, problem: string, node?: string, seal_head: string },
  title: string,                 // 叙述语域：照抄来源节点的 title（authored），不改写
  check?: { judge_id: string, judge_version: string,     // 此牛层必有：来源节点登记的判据
            spec_blob: string, expect: object,           // spec 的 sha256；expect 原样
            control?: object, ttl_s?: number },          // 对照与有效期随判据带走
  model_epoch?: string,          // 只有类牛层带
  body?: object                  // 只有 cut_prior、spend_profile 有，是判例字段的确定性摘取
}
```

| 类 | 层 | 取自判例的什么 | 进入条件（确定性） | 新题怎么用 |
| --- | --- | --- | --- | --- |
| `env_fact` 环境事实 | 此牛 | 解题链上、等级 E3、claim_type 为 observation 的节点及其判据 | 判据带 `control` 且对照不通过（N1），或判官 grade 为 decisive 且谓词引用了被观察对象（8.5 第 3 项的恒真筛） | 召回复核（§4），通过即成为新题的 E3 节点 |
| `excluded` 排除路径 | 此牛 | 等级 X 的节点；因前提被证伪而放弃的 Intent 及其被证伪的前提 | X 来自判定性判官或人的裁决（不收模型反证造成的争议） | 列进任务包第③段，叙述语域，标"上次在该环境排除，未在本题复核" |
| `cut_prior` 切口骨架 | 类牛 | `Case.cuts`：带判据 Intent 的序列、是否在链、尝试次数、是否碰过 knot | 判例终态为 solved | 列进 Reason 任务包第③段（见[能力二](./02-experience.md) §3） |
| `check_tpl` 判据模板 | 类牛 | 在链且达成的带判据 Intent 的 `done` 判据 | 同 `env_fact` 的对照条件 | 见能力二 §3 |
| `spend_profile` 花费画像 | 类牛 | 归因行的分角色花费、回合数、薄厚路径 | 任何终态 | 司南的预留与 Bootstrap 份额（估值语域，I8） |

最小版本只做 `env_fact`、`excluded`、`spend_profile` 三类，另两类属于能力二。

### 2.2 环境键与签名键

```
sig_key := sha256(JCS(Signature))          // 规格 4.3 的 Signature：画像、判官集合、资源种类、tags
env_key := Problem.labels.env               // 开题人给的不透明字符串，优先
         | sha256(JCS({base: env.base, targets: sort(scope[].pattern)}))   // 缺省由执行规格与授权目标推出
```

`labels` 即工作台设计 C3 提出的 Problem 字段，本文把 `env` 加进去（内核增量第 10 条，§6）。环境键给错的后果是"召回了不相干的事实"，复核会把它们挡下来记成过期，不会污染；所以缺省推导宁可粗一点 [观点]。

### 2.3 不记什么（封存时的过滤，确定性）

| 不记 | 理由 |
| --- | --- |
| 会话的推理正文、transcript、任务包 | 叙述，且量大；规格 4.3 的复盘会话可以读封存日志，记忆层不需要 |
| E0 到 E2 的论断，不论在不在链 | 没有被判官确认；把它们带进新题等于把猜想升格为记忆 |
| Goal 的候选答案、`exact_match` 的期望、一切 `vault:` 引用 | 判官保密资产不出题界；也防止评测退化为"背答案"（§7 的复做题组要求换答案） |
| 不带对照、又判不出是否恒真的观察 | 恒真谓词在新题里也会"通过"，复核挡不住它 |
| Hint | 人的判断属于那一次；人想让它跨题，用"钉住"（§5.1）显式做 |
| 判官版本已被撤销的裁决所支持的节点 | 出处已失效 |

## 3. 记忆怎么组织

通鉴日志是规格 2.4 所说"与题日志同种的基质实例"：同一套事件信封、JCS、哈希链与 SQLite 实现（`graph/eventlog.py` 可直接复用），单写者是通鉴服务。它有自己的 reducer，不碰题日志的 reducer。

| 事件 | 谁写 | 体 |
| --- | --- | --- |
| `case_sealed` | 通鉴服务，订阅题目关闭 | `Case`（规格 4.3），另加本题的召回结果 `recall_outcomes[]`（§4.3） |
| `mem_derived` | 通鉴服务，`case_sealed` 的同批派生 | 新增或命中的 `MemItem` |
| `mem_pin`、`mem_forget` | 人 | `{item, reason}`，带 `seen`（HMI H2 同一机制） |
| `seal_revoked`、`judge_revoke` | 通鉴服务转录来源题的同名事件 | 规格已有 |

**派生状态**（不存储，每次由事件重算，与等级同构）：

```
state(m) :=
  retired   若 m 被人遗忘；或其来源判例的封存被撤销；或其判官版本被撤销
  stale     否则若最近一次复核结果为 fail；或有 ttl_s 且距最近一次复核通过的封存超过 ttl_s
            （按封存里的事件 ts 计，不读本机时钟）
  dormant   否则若最近 N=10 次被召回且复核通过，却一次都不在新题的解题链上
  active    其它
  pinned    叠加标记：人钉住的条目在 dormant 时仍按 active 召回，不影响 stale 与 retired
```

`stale` 不是终态：条目下一次被召回并复核通过就回到 `active`。同一 `env_key` 下连续两次复核失败才视为该环境已变，条目转 `retired`。

## 4. 怎么检索、怎么带进新题

### 4.1 匹配（开题之前，确定性）

```
GET /v1/memory/match?env_key=&sig_key=&q=<题面词法>
  1. 此牛层：scope.env_key 精确相等，state ∈ {active, pinned}，kind ∈ {env_fact}；
     按（在链次数降序，最近复核通过的封存序降序，id）排序，取前 R 条（R 默认 8）
  2. 排除路径：同 env_key 的 excluded，取前 5 条，按同样的键排序
  3. 类牛层：规格 4.3 第 5 步的签名包含匹配 + BM25（确定性），取前 5 个判例
  4. 花费画像：同 sig_key、同 model_epoch 的中位数；不足 3 题则不给
```

匹配只是字符串运算与排序，不调用模型，不进内核。向导与 `pd problem open` 调用同一个端点。

### 4.2 召回清单写进开题事件

人可以在向导里逐条去掉某条记忆（[05 前端](./05-frontend.md) §2.1），然后开题批次里多两样东西：每条被召回判据的 spec 作为 input 类 Artifact 登记（复用裁决 004-2 的开题批次：若干 `register_artifact` 加最后一条 `open_problem`），以及 `open_problem` 的可选字段：

```ts
Problem.recall?: { items: { mem: string, title: string,
                            check: Check }[],          // spec_ref 指向同批登记的 input 类 Artifact
                   excluded_by_human: string[],        // 人去掉的条目，留痕
                   match_digest: string }              // 匹配结果的哈希：重放时可以核对"当时看到的是哪一批"
```

召回清单因此在动手之前登记、之后不可改，与判据先行（I4）一致；重放不依赖通鉴的当前状态。常设留出（规格 8.6）把"记忆召回"当作留出表里的一个感知官：被留出的题，`recall` 为空，开题事件的 `holdout` 写明。

### 4.3 召回任务：不含模型的复核

`/work` 在 `Problem.recall` 非空时派生一项 `recall`，先于 bootstrap。它由一个确定性的召回运行器领走（与判官运行器同构，不起模型容器），租约角色为 `recall`，操作白名单只有两种：

```
add_fact { claim_type: "observation", title: "[忆] " + item.title, summary: 出处说明,
           check: item.check, premises: [], grounds: [item.check.spec_ref] }   // grounds 是 input 类
request_judge { target: 上一条 }
```

判官按新题的环境在洁净容器里重放：

- 通过：节点在新题里是 E3，出现在任务包第④段的列表与第⑤段的状态里。Bootstrap、Reason、Explore 不需要任何新代码就能看到并引用它。
- 失败或不确定：节点按规格的等级函数处理（一次失败回到 E0，两次为 X），不会成为任何人的可采信前提。
- 召回预算：判官运行总墙钟上限 60 秒、并发 4，超出的条目不提交，列进第③段作"未复核的记忆"。召回占用的判官花费计入验证池，名下花费归"记忆召回"一列（归因表新增，§6）。

关题时，`case_sealed` 带上 `recall_outcomes`：每条召回的 `{mem, verdict, on_chain}`。这是记忆状态更新的唯一入口，所以跨日志的数据流仍是规格 2.4 的四条，没有第五条。

**召回在 Bootstrap 之前，所以薄路径同样受益。** 这一点对证据现状很重要：q1 上对等之后的单 CLI 是 5/5、均 $0.0118、25.5 秒，全栈是 3/3、$0.016、30.7 秒（PR #75、`docs/m1/readings/`）。易题上最省的"第二次"很可能是"薄路径加记忆"，设计必须让它可行，评测也必须单独量它（§7 的 B1+记忆臂）。

## 5. 怎么防止过时记忆污染新任务

五层，前三层是机械保证，后两层是读数：

1. **等级不出题（I7）。** 记忆过界的身份只有叙述与 input 类判据，没有等级。
2. **先复核，再采信。** 只有新题判官重跑通过的召回节点能作前提；没通过的就是普通的 E0 或 X。没有判据的记忆（排除路径、切口骨架）永远只在第③段作叙述，不进图。
3. **语域隔离。** 召回节点的标题带"[忆]"前缀并按叙述渲染；网页与 `pd` 显示出处（来源题、封存序、上次复核）。人不会把"上次是这样"读成"这次是这样"。
4. **过期读数。** 污染率 := 解题链上出现"引用了过期记忆的 E0 或 X 节点作前提的 Intent"的题占比（这种 Intent 只能在复核失败前被 Reason 加出来，或基于第③段的叙述）。按 `env_key` 滚动统计，超过 10% 时把该 `env_key` 的排除路径改为不展示 [观点]。
5. **换代不清此牛层。** `model_epoch` 变化只让类牛层另起一行累计；环境事实与模型无关，靠复核失效，不靠代际失效。

### 5.1 人的两个操作

| 操作 | 效果 | 语域 |
| --- | --- | --- |
| 钉住 `mem_pin` | 条目在 dormant 时仍被召回；对 stale、retired 无效（钉不住已过时的事实） | 人 |
| 遗忘 `mem_forget` | 条目退役；已开题的召回清单不受影响（它在开题事件里） | 人 |

另有"把这条 Hint 记下来"：在关题四顾时，人可以把本题的某条 Hint 钉成跨题记忆，它以 `kind: "env_fact"` 之外的第六种 `human_note` 进入通鉴，只在第③段作人的判断语域展示，不召回、不复核 [观点：最小版本不做，扩展版再定]。

## 6. 契约与接口草图

**内核增量**（接规格 §7 的台账，编号见 README 的总表）：

| # | 增量 | 性质 | 开关 |
| --- | --- | --- | --- |
| 8 | 租约角色 `recall` 及其白名单（只许带判据的观察与 `request_judge`）；`/work` 派生 `recall` 项 | 角色表扩展，reducer 只多一行白名单 | `memory=off` 时不派生 |
| 9 | `Problem.recall` 可选字段 | Schema 扩展；不进等级函数、消费门、画像 | 同上 |
| 10 | `Problem.labels {tags[], env?}`（工作台 C3 加 `env`） | Schema 扩展；不进等级与画像 | 无 |

三处都不改已有操作的语义，也不改已有事件的形状；旧日志重放结果逐字节不变（验收第 1 条）。

**非内核**：通鉴服务（新进程或图服务进程里的第二个日志实例）、召回运行器（与判官运行器同构）、归因表加"记忆召回"一列、折损账不加类别。

**读写端点**（都在图服务的 HTTP 绑定之下，前缀 `/v1/memory`）：

| 端点 | 读写 | 说明 |
| --- | --- | --- |
| `GET /v1/memory?env_key=&sig_key=&state=&kind=` | 读 | 条目列表与派生状态，支持 `as_of`（通鉴日志的序号） |
| `GET /v1/memory/{id}` | 读 | 条目、出处链（判例 → 来源节点 → 判官裁决）、历次召回结果 |
| `GET /v1/memory/match?…` | 读 | §4.1 |
| `POST /v1/memory/proposals` | 写 | 人的 `mem_pin`、`mem_forget`，带 `seen` |
| `GET /v1/cases`、`GET /v1/cases/{id}` | 读 | 判例（规格 4.3 已有类型，首次暴露端点） |

`pd` 对应：`pd memory list|show|pin|forget`、`pd problem open --no-recall`、`pd problem open --drop-mem <id>`。

## 7. 度量与证明（摘要；完整计划见 [04-proof-plan](./04-proof-plan.md) §2）

**复做题组**：每个题模板出两个实例 A、B，同环境键、换答案与随机参数；B 另有"漂移"变体，把 A 时为真的 30% 环境事实改掉（端口换了、目录挪了）。A 先跑并关题，B 再跑。

| 臂 | B 实例怎么跑 | 隔离的是什么 |
| --- | --- | --- |
| `memory=off` | 冷启动 | 对照：第二次不靠记忆有多贵 |
| `memory=recall`（最小版本） | 召回复核 | 记忆的增量 |
| B1+笔记 | 单 CLI，把 A 的最后一段输出原文放进提示 | 诚实基线：赢不过"把上次的笔记贴进去"就删召回（红线 5，同 Bn 的逻辑） |
| `memory=recall_noverify`（消融） | 召回但不复核，直接作为第③段叙述 | 复核这道守门官挡住了多少污染 |

读数：节省率 S_tok := 1 − tok(B | recall) ÷ tok(B | off)，S_wall 同理，按实例配对、每臂 3 次、报中位数与配对自助法区间；解题率；召回命中率（复核通过 ÷ 召回）；召回在链率；污染率（只在漂移变体上有意义）。

预登记阈值（最小版本过关）：非漂移变体上 S_tok ≥ 25% 且 S_wall ≥ 15%，解题率不低于 `memory=off` 一题以上；漂移变体上 `recall` 的污染率 ≤ `memory=off`，而 `recall_noverify` 的污染率显著更高（否则复核只是成本，降为扩展版再议）；`recall` 至少在 S_tok 或污染率之一上优于 B1+笔记。

## 8. 最小版本与扩展版

| | 最小版本（M2） | 扩展版 |
| --- | --- | --- |
| 记忆类 | `env_fact`、`excluded`（只展示）、`spend_profile` | 加 `human_note`；排除路径也可复核（判据重跑仍失败才展示）；`cut_prior` 与 `check_tpl` 在能力二 |

**验收**（最小版本，供实现线程照做）：

1. `memory=off` 时全部既有测试与录制夹具逐字节不变。
2. 同一通鉴日志在任一序号重放，`state(m)` 对全部条目相同。
3. 召回节点没有判官通过就不能出现在任何 Intent 的可采信前提里（参考模型加一条性质测试：任意改动召回清单，消费门的结论只随新题判官的裁决变）。
4. 封存过滤：构造含 Goal 候选、`vault:` 引用、无对照恒真谓词的判例，`mem_derived` 一条也不产生。
5. 召回超时：判官总墙钟超过 60 秒时，剩余条目进入第③段，题目照常开始。
