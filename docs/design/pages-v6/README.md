# 今日、任务库、读数 v6：按任务详情页的深度重做

> 起因：cz 2026-11-21 验收 #124（任务详情 v6）后点名“按同样的深度做其他几页（今日/任务库/读数）”。本稿是设计，也是同一 PR 里实现的依据。
>
> 硬约束照旧：页面只排版服务端给的字段，不内嵌 reducer；视图不读本机时钟（now 由外层注入）；不读本机题库与校准目录；界面用常规技术词，品牌叫焚决。

## 0. 一页结论

1. **今日 = 实时指挥台。** 不再只是“几个数字 + 列表”。每个在跑的任务直接写出它的智能体此刻在做什么（正在执行的命令或工具、最近一句自述、在途会话、模型调用次数），和任务页“过程”同一来源；等你处理的事按种类（审批、访问申请、验收、交付待看……）列出，能一键进到那张卡；右栏加“今天花了多少”、近七日的完成与花费两张图。
2. **任务库 = 可钻取的表。** 在原有的搜索、分组、选择、归档/回收站之外：判定方式、时间范围两组筛选；更多排序（花费、用时、最近、名字）；当前筛选的合计条（个数、花费、解决率）；右侧预览面板（点一行不离开列表就能看状态、花费、会话、待办与最近几步过程）；导出 CSV；键盘 j/k/Enter/x/p。
3. **读数 = 运营看板。** 时间范围切换（7 天/30 天/全部）；顶部指标（任务数、解决率、每解成本、总花费、token、平均用时）；花费随时间（来自 #123 的花费序列端点）；结局按判定来源；钱花在哪（按会话种类、按模型、最贵的十个任务）；用时分布；可排序、可搜的逐任务明细；“还没有读端点”的读数收在一处，不编数字。所有图都有表格视图与悬停读数。

## 1. 数据来源（只排版，不推断）

| 要显示的 | 来源 |
| --- | --- |
| 任务列表、终态、花费、上限、用时、在途会话种类、待办数、判定来源、置顶/归档 | `GET /v1/problems`（每 5 秒） |
| 每件待办的种类与目标 | `GET /v1/problems/{pid}/work` 的 human 项（只为有待办的任务读） |
| 在跑任务的会话（id、种类） | `GET /v1/problems/{pid}/status` 的 leases（只为在跑的任务读） |
| 智能体此刻在做什么 | `GET /v1/leases/{id}/activity` 的 `now`、`last_say`、`turns`、`calls`（只读在途会话，取 after=total 的增量即可） |
| 花费随时间 | `GET /v1/problems/{pid}/budget/series`（#123，点上带 ts） |
| 钱花在哪个会话种类、哪个模型 | `GET /v1/problems/{pid}/budget` 的 `by_kind`、`by_lease[].model` |

“今天花了多少”= 各任务花费序列在今天 0 点之前最后一个点与末点之差，纯算术；没有 ts 的点不计入并在旁边注明。

## 2. 今日

```
┌ 11 月 21 日 · 星期六 ───────────────────────────────────────────┐
│ 三件事等你拍板                                                   │
│ 导语                                                             │
├ 等你处理（按种类：审批 1 · 访问申请 1 · 交付待看 1）──────────┐ ┌ 今天 ────────┐
│ 审批  任务标题 · i_12               [去处理]                    │ │ 花费 $1.84    │
│ ……                                                              │ │ 完成 3 · 解决 2│
├ 正在跑（2）──────────────────────────────────────────────────┤ │ 在途会话 3    │
│ ● 任务标题        求解 ×1 · 模型调用 14 · 工具 9   $0.84 / $2   │ ├ 近七日 ───────┤
│   正在做  exec  python -m pytest -q                              │ │ 完成/解决 柱图 │
│   “两个失败都在 test_dates.py……”                                 │ │ 花费 柱图      │
├ 最近完成 ───────────────────────────────────────────────────┤ └───────────────┘
```

- 等你处理：每一项写种类（审批、访问申请、续期、争议、验收、交付待看、停滞）与目标，“去处理”直达任务页并打开那张卡；顶上一行按种类计数。
- 正在跑：每个任务一块，写在途会话种类与个数、模型调用与工具调用次数、花费/上限与用时；下面一行“正在做”（在途会话的 `now`，没有就写“在想下一步”），再下一行最近自述（叙述语域，截断两行）。数字每 5 秒刷新，在做的那一行有闪动的点。
- 右栏：今天（花费、完成、解决、在途会话）、近七日两张小柱图（完成与解决；每天花费），都有表格视图。
- 键盘：`j`/`k` 在等你处理与正在跑之间上下，`Enter` 打开。

## 3. 任务库

- 工具条：搜索（标题、编号）、视图页签（全部/进行中/已结束/归档/回收站，带计数）、判定方式（全部/判定器/外部判定/人工验收/开放道）、时间范围（全部/今天/7 天/30 天，按开始时刻或结束时刻）、排序（按状态分组、最近、花费、用时、名字）、选择、导出 CSV、刷新。
- 合计条：当前筛选下的个数、总花费、已结束里的解决率（判定通过 + 已验收 + 已交付 ÷ 已结束），点“清除筛选”回到全部。
- 预览面板：点行（不是标题链接）在右侧打开预览：状态、判定方式、花费条、用时、在途会话、待办（种类与“去处理”）、最近 6 步过程（与任务页同一份轨迹）、“打开任务”。窄屏时预览在下方。
- 键盘：`j`/`k` 移动当前行，`Enter` 打开任务，`Space`/`p` 预览，`x` 选择（选择模式下），`/` 搜索。
- 导出：当前筛选下的行导出成 CSV（编号、标题、状态、判定方式、花费、上限、用时、开始与结束时刻），文件在本机生成，不经服务端。

## 4. 读数

- 时间范围：7 天 / 30 天 / 全部（按任务的开始时刻筛；花费随时间按计量时刻）。
- 指标行：任务数（在跑几个）、解决率、每解成本（服务端给的口径，旁注分子分母）、总花费、token 总量、平均用时（已结束的）。
- 花费随时间：按天合计的花费柱图（来自花费序列）；悬停看当天花费与当天有花费的任务数；表格视图。
- 结局按判定来源：每个来源一行横向分段条（解决/验收/交付/没做成/在跑），带数字与表格。
- 钱花在哪：按会话种类（求解、推理、探索、判定……）与按模型两张横向条；最贵的十个任务（可点进任务页）。
- 用时分布：已结束任务的用时分桶（<1 分、1–5 分、5–15 分、15–60 分、>1 时）。
- 明细表：每个任务一行，列出终态、判定方式、各会话种类的花费、验证池、已花/上限、用时；可按任意列排序、可搜索。
- 还没有读端点的读数（评测台四臂、归因、校准、留出……）收在一个折叠区，写“暂不可用”，不编数字；本机界面使用读数保留。

## 5. 实时与性能

- 列表每 5 秒轮询（已有）。今日为在跑的任务读 status 与在途会话的 activity（一次请求只取增量），任务数多时只读前 12 个在跑的任务。
- 读数的 budget 与 series 按任务读一次，列表的链头变了才重读；任务多于 200 个时只读最近 200 个，并在页上写明。
