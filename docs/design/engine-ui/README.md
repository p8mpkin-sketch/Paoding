## 0. 一页结论

1. **放在“能力配置”里**，加两栏：**方案分析**（每次分析一行）与**候选方案**（异火榜）。现有的“演进读数”不变，分析交接出的做法导入后在那里成为集成记录。不加侧栏一级入口（E-U1）。
2. **一次分析就是一个任务**：它是分析实例里的开放任务（EN1），所以详情页的“过程”“文件”两栏直接复用任务页 v6 的全链路追踪；新加的只有顶部的十步进度条与“待你确认”一栏。
3. **三次待你确认是三张专门的卡**，不让人手写决定块：第 1 次勾候选、改名、排除带理由；第 2 次逐个看核心机制，确认、改一句、退回或放弃；第 3 次看集成顺序与映射方案，逐个交实现线、搁置或排除。界面照 09 §2.4 的格式生成决定块，折叠显示“记进事件日志的原文”，人点“确认”时作为追问提交（内核既有的 `follow_up`，可带追加预算）。
4. **每张卡都把“为什么”摆出来**：候选的优先级拆成价值、置信、难度、风险，展开看逐维差距、痛点依据与观察编号；核心机制卡按“它怎么运作、依赖的前提、代价、和现有模块的关系、冲突与化解、融合假设与新增指标、两种以上实现思路、自检 K1–K8”排；映射卡给新模块、替换谁、对照组、预登记指标、实现步骤（内核改动恒为 0 行）、冲突。
5. **异常照实显示在最上面**：校验未过（带“未过”交付）、决定块有行没读懂、预算用完（带检查点，追加即续或缩小范围）、等你批准联网（抓快照的扩权卡）、叫停。
6. **预评估**单独一页：可能的结局（有望新增能力 / 至多全面提升 / 可能无增益）、正式走一遍的预估，一键“正式走一遍”复用已读内容。
7. **候选方案**页按优先级排；每条有状态、最近一次分析、分析记录（失败的也留）与状态史；“找点什么分析”从这里取前 3 个，复算后直接进第 1 次确认。
8. **用词全部是常规技术词**（§6）；引擎产物里的枚举由界面映射，自由文本目前混着内部名词，界面暂按对照表替换，长期请引擎线把 V5 禁词扩到所有给人看的栏（E-U4）。
9. **后端几乎不用新东西**：分析实例上的 `/v1/problems`、`/status`、`/events`、活动、`/budget`、`/artifacts` 与 `follow_up` 都已存在；只差三件：前端连第二个实例的地址、读 `run.json` 的端点、读候选方案（`yihuobang.json`）的端点（§7）。

## 1. 放在哪

| 位置 | 加什么 | 为什么 |
| --- | --- | --- |
| 侧栏“能力配置” | 角标 = 在等你的分析数（第 N 次确认、联网授权、预算用完） | 和“待你处理”同一口径，人不必点进去才知道有事 |
| 能力配置 › 方案分析 | 分析列表、新建分析、分析详情 | 分析的产物最终改的是能力配置，放一起最好找 |
| 能力配置 › 候选方案 | 异火榜 | 09 §12：异火榜→候选方案；原“集成记录”页里的候选表移到这里 |
| 待你处理 | 新分组“方案分析”，每件直达对应分析的“待你确认” | 确认是人的点位，和其他待办同一处出现（同 U2/U7 的思路） |
| 任务列表、今日 | **不出现**分析 | 分析在分析实例里，和真实任务隔离（EN1）；混在一起会让读数、花费口径变脏 |

分析实例是另一个栈（EN1 a）。前端在设置里登记“分析实例地址”，能力配置的这两栏读它；侧栏底部显示“分析实例 · 已连接”。没登记时两栏显示一句说明和设置入口，其余页面不受影响。

## 2. 方案分析列表

一行一个分析：标题（原话的前一句）、方式（正式 / 预评估 / 从候选方案取 / 重新映射）、来源一句、状态、走到哪一步、花费与上限（量条，用完变琥珀）、开始时间。顶上一条琥珀提示列出所有在等你的分析与各自要你做什么。按钮“新建分析”“从候选方案里挑”。

状态色照 v5：蓝 = 在跑，琥珀 = 等你，绿 = 已交接或报告已出。

## 3. 新建分析

右侧抽屉，对应立项单 `intake`（10 §7）：

- **想看这个系统的什么**：原话，原样进事件日志。
- **来源**（1–8 个）：上传归档 / 资料库已有 / 仓库地址 / 服务地址 / 文档地址 / 写在描述里。
  - 仓库必须填固定的提交或标签，填分支名当场提示“不抓会变的默认分支”；
  - 服务地址要写探测计划；
  - 地址类注明“抓取前要你批准联网”。
  - 命中拒收表（本机题库、校准目录）当场显示“按规定不会读取，已拒收”。界面不提供本机文件夹选择。
- **方式**：正式（三次确认）或预评估（不停，约一半预算，结果不能直接交实现线）。
- **范围**（可选，折叠）：只看哪几个模块槽、最多几个候选。
- **预计花费**：大小档要勘察后才知道，所以按 S/M/L/XL 四档列 token、机器时间与预算上限。数取自预算先验数据源（`GET /v1/settings/sources`，键“方案分析 / 模式 / 大小分档”），原型用 09 §5.2 的占位表，标〔占位〕。
- **查重**：同一快照已有分析时提示，可以继续，并说明已读内容会复用。

## 4. 分析详情

顶部：标题、状态、方式、来源、许可证（GPL 类标琥珀“只借思路”）、“来源含疑似指令 N 处 · 已忽略”、题号。下面是**十步进度条**：立项 · 快照 · 勘察 · 发现 ◆ 待你确认 · 抽象 ◆ 待你确认 · 映射 ◆ 待你确认 · 交接。三个确认点画成菱形与虚线段，走到时变琥珀。

四栏：**待你确认**（或“当前”）/ **报告**（每次交付的人读报告，按交付顺序）/ **过程**（复用任务页 v6 的全链路追踪，同一份事件与活动）/ **文件**（快照、勘察单、观察库、候选清单、核心机制、映射方案、交接包、`run.json`，标出“你给的材料 / 执行输出 / 分析写的”三类，提醒“分析写的只能当说明，不能当依据”）。

右栏：
- **预算**：整题与发现 45% / 抽象 35% / 映射 20% 三段的已花与软上限，最后 10% 留给收尾交付。
- **进度**：发现阶段的 8 个模块槽 × 广度、深度两轮共 16 格；抽象、映射按候选显示。接力会话 x / 8；最近检查点。
- **模型配置**：读取模型、主模型、抽取、盲审、映射各用哪一档，并说明“原文只交给读取模型，主模型只看结构化观察”。
- **依据**：能力配置版本与摘要、能力剖面、快照、大小档。依据变了就标“需复算”。

### 4.1 第 1 次确认：发现

- 顶部一段 `plain_summary`。
- **候选做法表**：勾选、编号、标题（点击改名，改过的标浅蓝）、现象一句、标记（许可证受限、来源含疑似指令……），以及“已在候选方案 Y-003”或“新登记”。
  - 列出模块槽与兼及的模块槽。
  - 优先级量条下一行是 `V4 · C1.0 · D1 · R0`。
  - 建议（推荐 / 可选 / 不推荐）。
  - “依据”展开：推荐理由、差距一句、逐维差距表（我们 / 外部 / 类型 / 权重 / 痛点 / 痛点依据 / 观察编号）和公式说明，并写明“推荐不是决定”。
  - “排除”要求写理由（会进候选方案，防反复）。
- **我们已有且不差**、**只是普通需求**、**覆盖情况**（每个模块槽读了几段、多少 token、为什么停）：这三块证明“看过了”，也是诱饵检验的可见面。
- 底部固定的**决定栏**：
  - 显示“第 1 次确认 · 选 N 个做抽象”，可填追加预算和备注；
  - 折叠的“记进事件日志的原文”实时显示生成的决定块；
  - 按钮“确认，继续下一步”，旁注“提交后无法撤回，但可以在下一次确认时退回”。

### 4.2 第 2 次确认：抽象

每个选中的候选一页（顶部切换），核心机制卡：

| 区块 | 来自 `essence.masked` | 呈现 |
| --- | --- | --- |
| 一句话 | `statement` | 大字；“改”就地编辑，保存后重跑 K1–K8 |
| 它怎么运作 | `mechanism[]` | 步骤卡：当〈触发〉→ 做〈变换〉，输入 → 输出，“始终保证”写不变量，底部是机制原语标签 |
| 依赖的前提 | `premises[]` | 成立 / 部分成立 / 不成立 + 理由 + “改用” |
| 代价 | `costs[]` | 代价、种类、在我们这里谁付 |
| 和现有模块的关系 | `overlaps[]` | 模块名（附 id）、重复 / 部分重叠 / 互补 |
| 冲突与化解 | `conflicts[]` | 冲突一句、与谁（内核项用中文名）、化解方式 |
| 融合假设 | `fusion` | 一段话 + 新增指标表（为什么基线做不到、为什么照搬也做不到、怎么量、门槛）；没有新增指标时写“最好的结局是全面提升” |
| 实现思路 | `implementations[]` | 至少两条，带原语 |
| 自检 | `drafts`、`checks` | 三稿一致度、分歧点；K1–K8 标签（K6 虚线，只作读数） |

每张卡右上是三选一：确认 / 退回重做（填理由）/ 放弃（填理由）。人改过的句子若没过 K2 等检验，卡内红条提示“可以再改，也可以坚持；坚持会记为‘人改，检验未过：K2’，一路带进集成记录”（09 §2.4）。

### 4.3 第 3 次确认：映射与集成顺序

- **集成顺序**：位次圈、候选、P 的算式与理由、“等 C2”；被搁置的圈画虚线并写原因。
- **映射卡**（`placement`）：
  - 新模块（名 + id，主槽与兼及）、模块组、替换谁（被替换的进 Holdout 对照）、内核改动（**0 行**，预判必须为空）、难度及拆项；
  - **对照组**：基线 / 外部方案移植 / 融合方案 / 基线复跑；
  - **预登记指标**：类别为新增 / 外部方案优势 / 基线保障 / 通用，必登的标出，并列出方向、门槛和测试名；
  - **实现步骤**：做什么、在哪、验收、内核行数；
  - **冲突**：模块、内核、候选之间。
- 每张卡三选一：交实现线 / 搁置（理由）/ 排除（理由）。
- 勾选“把这次的分析报告以你的身份存进资料库（只作参考，不作依据）”（EN12）。
- 提交后显示“接下来”：每个交实现线的做法排队，状态依次是“等实现线导入”“排队：等前一个定论”。同时列出候选方案的变化，这些变化由导入命令写入、随 PR 审。

### 4.4 异常

| 情况 | 依据 | 呈现 |
| --- | --- | --- |
| 校验未过 | 09 §7：重写两次仍不过，带“未过”交付 | 卡顶红条：哪条校验、为什么；仍可看内容，建议“退回重做” |
| 决定块有行没读懂 | 09 §2.4：进下一次交付的 `needs`，不猜 | 卡顶琥珀条，原样显示那一行和原因；其余行已照办 |
| 预算用完 | 09 §5.1：任何一级耗尽都部分交付带检查点 | “停在哪、哪些已完成”；追加预算并继续，或“只做完已完成的部分”（缩小范围）；已完成单元不重做 |
| 等你批准联网 | 09 §2.1 S1：地址类发扩权卡 | 与任务页同一种联网授权卡：地址、版本、抓完即撤；可改为“我来上传” |
| 叫停 | 既有 `halt` | 头部“叫停”按钮；停后显示部分交付，追问即续 |
| 失败 | `run.json` 的 `step = 失败` | 停在哪一步、最后一条错误、可重试的单元 |

## 5. 预评估报告与候选方案

**预评估**（10 §8）一页包括：
- `plain_summary` 与“正式走一遍”（复用同一快照的勘察与观察，从第 1 次确认开始）；
- 正式走一遍的预估：按轻量、标准、高性能三档列 token，以及机器时间；
- 每个自动取的候选：核心机制草稿一句、可能的结局标签及理由、替换谁、冲突、内核改动预判、难度、自检。

底部注明“预评估是单稿、不盲审、不写实现步骤；不能直接交实现线”。

**候选方案**（10 §11）的列表：
- 列：编号、做法、模块槽、状态、优先级、最近；
- 筛选：全部 / 可以分析 / 进行中 / 已集成 / 已排除与不采纳；
- 状态九种，照 09 §8.2 用常规词：已识别、预评估过、选中、已交实现线、已集成（vN）、不采纳、已排除、已并入、已回滚；
- 能力配置或剖面变了的条目写“需复算”。

点一行，右侧打开详情：
- 核心机制一句、融合假设、预计内核改动；
- **分析记录**：每次分析一行，失败的也留；
- **状态史**：只追加；
- 按钮“以它为起点分析”“排除…”。

页底说明“找点什么分析”的取法与防反复规则（09 §8.3–8.4）。

### 10.1 接上引擎第二期（#138 合入之后）

引擎第二期让一次分析能走到第 3 次确认、交接完成，或以预评估一口气走完。这一期仍只收第 1 次确认，但这三种停法都要能看懂：

| 停在哪 | “当前”一栏显示 | 读端点多给的 |
| --- | --- | --- |
