## 0. 一页结论

**建议把 1.0 定义为：吸收器自己走完一次完整炼化，结局由判定表算出，人只在闸点上做决定。** 它对应现行设计第 8 步的两场自炼验收过关。路上有一个更早的落点（里程碑 M4，手工炼档出结局），到那里就已经有第一份正式的同模型对比。这个定义是待定项 D1。

**路线是七个里程碑，M0 到 M6，沿用现行设计的第 0 到第 8 步，不另起一套。** 本文补的是三样：把三条支线（真实外部系统上的三个验收用例、方案分析界面二期、宿主机回环服务）排进去；给每个里程碑写清「怎样算完成」；写出 1.0 之后的总对比。

**与 Claude 的同题对比不是 1.0 之后才第一次做，它在路线上出现四次。** 起点对照用来选分支（cz 在量），M3 中期旗帜是系统自己跑的第一次，M4 的判定试火里原形臂就是 Claude，M6 是对 1.0 成品的总对比。四次用同一把尺子，M6 不另造量具。

**模型变量靠三条控制。** 各臂钉同一个模型与版本，模型由客户端自己钉，并从运行记录逐次调用读回核对，不符即作废；Claude 一侧用它的命令行程序，以最小模式在隔离环境里无人值守运行，经我们的端点代理计量；总对比先按三条臂做，只比本火模型这一对。「两边都换成那个程序的默认模型」的第二对是有条件追加，要等有了双方都够得着的端点。

**现在卡住路线的是 cz 手上的三件事：** 给端点额度、定盲判用的模型并跑通自检（P8）、出起点轮的新题。PR #158 已合并。十一条待定项已按推荐定下，见第 5 节。

本文只写设计，没有代码。本地运行的读数与现象没有写进来。文中的内部名词沿用现行设计；界面上仍用常规技术词。

## 2. 1.0 指什么

**1.0 是「第一次真正跑通的完整炼化」：系统自己把一个外部对象的做法吸收进来，全程过门，结局照实。** 「完整」有两种读法，差在实现由谁做，所以列为待定项 D1。

|  | 甲（推荐）：自炼跑通 | 乙：手工炼档出结局 |
| --- | --- | --- |
| 对应 | 现行设计第 8 步，本文 M5 | 现行设计第 6 步，本文 M4 |
| 谁做设计与实现 | 吸收器与系统自己的实现线。人写的设计与代码行数为零 | 人设计、人实现，试火与判定由系统做 |
| 人在哪里 | 只在三个闸点与最后的裁决 | 全程 |
| 说明了什么 | 「吞进一个做法」这件事系统自己会做了 | 门与量具可信，引擎的新架构有了第一个正式结局 |
| 不足 | 路远，实现线从没跑过，是全程最不确定的一段 | 炼档的出身是手工，按 N6 不计为一次成功的炼化 |

推荐甲，理由有两条。现行设计已经写明调查线是最后一次手工炼化，手工的不加品阶、不算成功，把它叫 1.0 与这条规矩打架。cz 的节奏是质量优先、不设时间线，没有理由把线画在近处。乙不丢：它就是 M4，可以叫 0.9，到那里已经有第一份正式对比。

**1.0 的完成标准（按甲），七条都满足才算：**

1. 自炼验收的两场都过关。第一场是重演（大分支）或首炼（小分支），第二场是 cz 选的没见过的对象。过关看的是流程自己走完、结局照实，不看结局是哪一种。
2. 试火台的三只金丝雀（安慰剂、退步、封顶）在最终版本上判对。
3. 至少一份炼档的原形门是「判了」的，不是「未判」。也就是 Claude 一侧的适配六条全部具备，同模型对照真的跑过。
4. 体质改动行数与量具改动行数，在每一份自炼的炼档里都是零。
5. 三个验收用例在真实外部系统上正式走完识别、提炼、映射三步，交付前的校验全过。
6. 界面上三次确认都能在卡片上完成，炼档与能力页显示结局与「原形门未判」「原形门未过」两个记号。
7. 全量测试与 CI 的全部检查在 `main` 上全绿，14 份旧录音原样回放。

不在 1.0 里的：部署管道；读仓库答题之外的吸收目标维；第三次及以后的自炼。

**1.0 说明的是什么。** 按这个定义，1.0 说明的是「系统自己会吞一个做法了，而且结局照实」，不是「焚决比通用智能体强」。强不强要看 M4 与 M6 的读数；自炼的结局是并火或不及原形，也算 1.0。

### 3.2 三条支线

| 支线 | 做什么 | 什么时候做 | 怎样算完成 |

### 3.3 贯穿全程的规矩

- 每个 PR 开分支前先更新到最新的 `main`，推之前全量测试，全量与长时间运行交给 GitHub 的检查去跑。
- 留出题的内容不进会话、不进仓库。本地运行的读数不写进仓库、提交说明、PR 描述与文档，cz 只在对话里发数字。
- 不读、不请求本机的题库与校准目录。
- 不设时间线。现行设计 10.5 给的是机器时间的估算，只用来排并行，不当期限。

## 4. 与 Claude 的同题对比

**对比复用试火台：Claude 就是原形臂，题、盲判、判法都与判定试火相同，只多出「换一个模型再比一对」。** 这里的 Claude 指通用编码智能体：一个模型加读文件、检索、写文件三类工具，没有流程约束，也就是仓库里参照材料记录的那一种。

### 4.1 要回答的三个问题

三个问题分开回答，不互相冒充。

| 问题 | 怎么比 | 结论的分量 |
| --- | --- | --- |
| 做法谁强：同一个模型下，焚决的架构比一个通用循环多出什么、少了什么 | 两边钉同一个模型与版本，成对比较 | 可以下结论，范围限于这一批题、这个模型 |
| 这个差距随模型变不变 | 换上 Claude 默认用的模型，两边再比一对 | 同上。两对的方向相反时，照实写「随模型而变」 |
| 实际用起来谁强：各用平时的配置 | 焚决用本火模型，Claude 用默认模型，直接对照 | 只作参考。模型不同，差距分不清来自模型还是做法 |

焚决独有的性质（可回放、零出站、证据分级、独立核对）Claude 没有，不比高低，只报告。能比的是它们的效果：回答里被原文否定的结论比例，两边用同一套抽样核对去量。

### 4.2 臂

| 臂 | 是什么 | 模型 | 用途 |
| --- | --- | --- | --- |
| 焚决 | 1.0 的成品，功法摘要钉住 | 本火模型 | 第一对的一方 |
| 焚决复跑 | 同上，再跑一遍 | 本火模型 | 估噪声底 |
| Claude 同模型 | Claude 经我们的端点代理，在隔离环境里运行 | 本火模型 | 第一对的另一方 |
| Claude 默认 | 同样的隔离环境，模型用它默认的那个 | Claude 的默认模型 | 第二对的一方；也是「实际用」的参考 |
| 焚决换模型 | 焚决成品，模型换成 Claude 的默认模型 | Claude 的默认模型 | 第二对的另一方 |

**M6 的计划先按前三条臂写**，它们已经能回答第一个问题。后两条是有条件追加：我们的端点不提供那个程序的默认模型，焚决要与它同模型就得另接一个端点，这要 cz 给密钥与额度。有了双方都够得着的端点再加；加的时候另起一份计划、另成一批。只跑「Claude 默认」而不跑「焚决换模型」得到的是一个没法解释的数，所以这两条要么一起加，要么都不加。

不同模型下的批次不放在一起比，也不进同一条曲线。两对各自成批，各有自己的噪声底；第二对的噪声底取「焚决换模型」的两次运行之间的不一致来估。

### 4.3 怎样把模型这个变量控制住

1. **逐臂登记，读回核对。** 计划里每条臂写明模型名与版本标识、端点、采样参数、计量来源、价表版本。运行记录里读回的模型标识与计划不符，这个题次作废重跑。
2. **Claude 一侧经我们的端点代理计量，模型由客户端自己钉。** 事实是：端点代理现在把请求里的模型原样转给上游，按那个模型计价，价表里没有的模型按最贵的一档估；它不拦模型。所以钉模型靠启动参数，核对靠读回。经代理得到的是同一个端点、同一本账，用量不必听那个程序自己导出的数。
3. **逐次调用都核模型，不只核主循环。** 代理的流水里，一个题次的每一次调用都带模型标识。有任何一次不是登记的那个，这个题次作废重跑；整条臂都不符，试火中止，结局记未判（合并版 6.4）。启动时把那个程序的主模型与它做杂事用的小模型都指到登记的那一个，使作废尽量不发生。「代理只放行登记的模型」这次不做：它落在体质路径里，要做就是另一次单独的体质改动、单独裁，不并进只动量具的第 1 步。
4. **采样参数能设成相同的就设成相同。** 温度、输出上限、推理档位。设不了的列进不对等项，跑之前就写明偏向哪一方。
5. **原形臂是那个通用编码智能体的命令行程序，不是对话里的 Claude。** 隔离环境就是它的启动方式，逐项对应原形适配的六条：
   - 无人值守的打印模式，一条命令启动，中途不提问。
   - 启动参数里指定模型。
   - 最小模式：不读配置、钩子、技能、插件，也不读项目说明与记忆。
   - 不加载任何额外的工具服务。
   - 不留会话，每个题次从干净状态开始，用一个全新的临时主目录。
   - 工具白名单只有三类：读文件、检索、写文件。
   - 工作目录是定版快照的一份副本，外加一个空的输出目录；容器除我们的模型端点代理外不出站。用的是现成的模型容器那一套隔离机制（`adapter/src/paoding_adapter/container.py`）：每次运行一张内部网络并且隔离网关，没有出站路由，也到不了宿主；网络上只放一个端点中继，只通模型端点代理，我们的工具端点不给它；真实密钥留在代理进程里。隔离网关建不出来时拒跑。冒烟时从容器里连外部地址与宿主地址，都必须连不上。细则只写在合并版 6.3 末段。
   - 输出取机器可读的格式，从里面读回用量与实际用的模型。

   各项的具体参数名以 1f 冒烟时那个版本的帮助为准，逐项写进适配，并把程序的版本号记进试火记录。
6. **给它的那句话固定，定稿如下。** 文字进计划哈希，跑之前定死，不带任何做法上的提示。尖括号里的两处由适配填。

   > 当前目录是一个代码仓库的快照。请阅读它，回答下面的问题。把完整的回答写进 〈输出文件〉，写完就结束，不要向我提问。
   >
   > 问题：〈题面〉

   题面与材料同焚决那条臂拿到的逐字相同。子问清单不给任何一条臂。
7. **盲判的模型要避开实际会出现的各臂模型。** 三条臂时只有本火模型一个要避开。追加第二对时，再加上那一对用的模型；那时如果盲判模型撞上了，第二对另选盲判并重跑自检，两批不混。
8. **对象版本钉住。** 那个程序自己的版本号写进记录。版本变了，旧读数按复用规则作废。

### 4.4 题

- 一套全新的留出题，没有用于任何一次判定，由题目生成器在 cz 的机器上出。建议 20 道，每条臂每道题跑 2 次，沿五条轴分散：语言、仓库大小、问法、前提是否成立、答案在代码还是在配置文档。
- 题的类型是「读一个外部仓库回答问题、给出值得集成的做法」，这是焚决现在唯一的吸收目标维。写代码、改代码这些 Claude 的其他能力不在范围里，对比结论也不外推到那里。
- 生成器的「不读仓库答不出」这一项校验对用到的每个模型各做一遍。否则更强的模型可能凭记忆答出知名仓库的题，第二对的读数就假了。
- 题面、仓库、回答的内容都留在 cz 的机器上。回到会话里的只有汇总数。

### 4.5 尺子与读数

尺子就是现行设计第 5 节的盲判，不加不减。一个题次过线要三条都成立：每个子问都答到；回到原文抽样核对，被抽到的结论没有被原文否定、没有找不到依据的；在每题花费上限内正常结束。盲判不看臂名、过程日志与各臂自己的标注。

每一对报这些读数：

| 读数 | 说明 |
| --- | --- |
| 成对四格计数 | 都过、都不过、只有焚决过、只有 Claude 过 |
| 噪声底 m | 2 倍的不一致题次数的平方根，向上取整，最小为 1 |
| 被原文否定的结论比例 | 两边同样的抽样量。它量的是证据分级与独立核对到底有没有用 |
| 花费 | 同一张价表折算。新增用量与账面用量分开报，因为两种架构在缓存上差别很大 |
| 用时 | 只是读数，不进过线 |
| 按轴分层 | 五条轴上各格的过线数，看差距集中在哪类题 |
| 发现的类别 | 归类器给出的类别编号与计数，每条臂一组，看两边各输在什么上 |
| 量具自检 | 换臂名测试、三份已知答案的样本、重判一致率 |

### 4.6 结论怎么读（跑之前就写定）

记净差为「只有 Claude 过的题次数」减「只有焚决过的题次数」。

| 净差 | 读作 | 接下来 |
| --- | --- | --- |
| 大于 m | 这批题、这个模型下，焚决不及 Claude | 看发现的类别与按轴分层，差在哪里就是下一次自炼的候选 |
| 在正负 m 之内 | 持平 | 比花费与被否定比例。过线持平而被否定比例更低，说明焚决的约束没有拖累答题，还换来了可信 |
| 小于负 m | 这批题、这个模型下，焚决胜过 Claude | 同样看类别，确认赢在做法上，不是赢在某一类题的巧合 |

三条读法上的约束：

- 20 道题时区间很宽，结论旁边照实报区间，不说超出样本的话。想要更窄的区间只能加题。
- 一份计划只判一次。看过失败细节并据此改过的题转为开发题，不能再用来对比。
- 「实际用」那一组（焚决用本火模型对 Claude 用默认模型）只列数，不写谁强谁弱。

## 6. 风险与不做的事

**最大的不确定在 M5：系统自己的实现线从没跑过一次完整的实现。**

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 实现线做不出合格的实现 | M5 第一场过不了，1.0 卡住 | M4 期间先拿一个小的、已有参考答案的改动让实现线试做，只看跑不跑得通，不进功法。过不了就照实记，结局是并火或不及原形也算流程过关 |
| 调查线的花费没有实测数 | 大分支的判定试火可能超额度 | 先在开发题上小范围实测。超出账就收紧上下文与轮数，账不动 |
| 20 道题的区间很宽 | 对比大概率读成「持平」，分不出小差距 | 照实报区间。想分辨更小的差距只能加题，生成器就是为这个准备的 |
