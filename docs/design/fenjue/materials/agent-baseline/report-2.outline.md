# 一页结论
## 0. 一页结论

1. **压缩不删历史。** 它的事件日志只追加；压缩本身是一条事件，记下“忘了哪些事件的编号、摘要是什么、插在哪、出自哪次模型回答”。给模型看的那份是日志重放出来的投影。`sdk/event/condenser.py:11-37, 83-96`；`sdk/context/view/view.py:112-145`。
2. **什么时候压，分软硬。** token 超限是硬的，事件条数超限是软的，显式请求是硬的；每一步调模型之前先问一次压缩器，要压就先把压缩事件写进日志、这一步不调主模型。`sdk/context/condenser/llm_summarizing_condenser.py:140-207`；`sdk/agent/agent.py:902-911`。
3. **压一半，保住开头，不拆原子单位。** 开头 `keep_first` 条和系统提示永远不动；切点不拆“动作与结果”“同一次回答里的多个工具调用”“带思考块的工具循环”；忘掉的不到视图的一成就不压。`llm_summarizing_condenser.py:67-76, 301-356, 427-438`；`sdk/context/view/properties/` 下四个文件。
4. **摘要有固定栏目、会续、有出处。** 另一路模型按固定栏目写；摘要本身也是视图里一条带编号的事件，下一次压缩会连上一次摘要一起再摘要；压缩事件带生成它的回答编号。`sdk/context/condenser/prompts/summarizing_system.j2:1-29`；`tests/sdk/context/view/test_view_multi_summary.py:536-605`；`sdk/event/condenser.py:31-35`。
5. **它的摘要先天有损。** 喂给摘要模型的是每个事件的字符串形式：工具调用只有名字没有参数，各段文字只留前 500 字，上一份摘要也只留前 500 字。`llm_summarizing_condenser.py:251-255`；`sdk/event/llm_convertible/action.py:176-194`；`sdk/event/base.py:18, 83-106`。这一条是读代码读出的。
6. **接外部智能体时不替它管上下文。** ACP 一路声明不支持压缩器，靠会话号续接；接不上就报错，绝不开一个新会话顶替。`sdk/agent/acp_agent.py:2339-2342, 2491-2495, 3484-3528`。这一路与庖丁的 CLI 形态最像。
7. **换会话接力靠“落盘加校验”。** 一事件一文件加一份 `base_state.json`；恢复时重建视图，校验“工具只许增不许减，其余配置随便换”；中断或重启时给悬空的工具调用补一条“被打断”的结果。`sdk/conversation/state.py:624-746`；`sdk/agent/base.py:706-772`；`server/event_service.py:1564-1610`。
8. **我们今天的样子。** H4 无压缩；接力是把上一个会话的工作区（连同模型自由写的 `NOTES.md`）拷进新会话；开放道设计自己写着“接力靠工作区笔记，信息会有损耗”。`docs/design/fenjue/06-migration.md:42`；`adapter/src/paoding_adapter/session.py:560-584`；`docs/design/open-lane/README.md:266`。
9. **建议（判断）。** 不照搬摘要式压缩器。把接力做成“可核的交棒”：上下文占用当作一条软线，到线收尾；接力包由宿主从事件账确定性生成事实层并带锚，会话只写思路层且每条带锚，宿主核对；切在完整的回合上；接不上就明说。全部落在适配层与功法（H4、H1），体质改动 0 行。“带锚压缩”已在异火榜第 2 位、状态是待写炼档（`docs/design/fenjue/05-cases.md:99`），本报告可以当作那份炼档的输入；收不收由项目负责人定。
