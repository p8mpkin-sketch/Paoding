# 一页结论
## 0. 一页结论

1. **压缩。** 上游的 agent 循环归它自己，所以压缩做在循环里面：每一步把历史交给模型之前先过压缩器，要压就调一次摘要模型，产出一条 `Condensation` 事件写进只追加的日志，这一步不调主模型；下一步重放日志，旧事件被这条事件“忘掉”、原位换成一条摘要，同一个会话继续做。
2. **接力。** 上游的“换会话”是同一个会话换进程（重启、空闲逐出后重载、外部 CLI 重启）：状态落盘，恢复等于重放日志，模型侧的上下文原样接回，压缩过的样子也原样接回。真正“活的上下文丢了、从落盘事件渲染一份开场白”的那个原语，快照里有定义、有单测，但没有接进生产路径。
3. **两个词对不上。** 我们的接力是换一个租约、换一个 CLI 进程，丢的恰好是模型侧的上下文；而上游 3.1–3.3、3.6 节的东西（落盘重放、崩溃修补、多实例、重连），我们大多已有，有的更严（哈希链、功法钉住）。对我们真正对口的是 3.5 节的原语，以及压缩那一套规矩：软线先于硬线、压不出来有梯子、只在原子边界上裁、摘要是新记录而不改旧的。
4. **建议。** 可以立炼档的三件：接力简报（A）、收尾的梯子（C）、失败分类（E），都是确定性代码、不调模型、体质改动 0 行。值得但要先有运行读数的两件：运行器软线（B）、固定栏目的接力笔记（D）。不做的十件见第 6 节。
5. **最要紧的一句。** 摘要器本体搬不进我们的 CLI 会话，因为 CLI 的循环和它发给模型的消息不归宿主管（第 6 节 F）。能搬的是它的触发纪律、失败纪律和渲染开场白的办法。
