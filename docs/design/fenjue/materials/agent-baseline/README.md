# 材料：通用智能体读仓库回答问题的做法记录

用途：吸收「按题读仓库、给出集成建议」这类做法时用的行为材料（识火的「行为」形态）。记录的是实际发生的动作，不是自述。

## 题目

看看这个仓库里上下文快满时怎么把较早的过程压缩成摘要继续做、换会话时怎么接力，有什么值得我们集成的做法

材料是一个外部代码仓库某个提交的完整快照（下称「上游」），外加我们自己的项目（下称「我们」）。

## 通用智能体甲是怎么做的

甲是一个通用智能体：一个强模型，带读文件、检索、写文件三类工具，没有任何流程约束。同一道题让它独立做了三遍，每遍从零开始。

| | 第 1 遍 | 第 2 遍 | 第 3 遍 |
| --- | --- | --- | --- |
| 用时 | 20.6 分钟 | 17.4 分钟 | 21.4 分钟 |
| 动作数 | 166 | 187 | 162 |
| 打开的文件 | 源码 69 个、说明文档 12 份 | 源码 73 个、说明文档 12 份 | 源码 89 个、说明文档 12 份 |
| 新增 token（没命中缓存的新输入加输出） | 59 万 | 57 万 | 61 万 |
| 账面 token（含每轮重发的上下文，98% 命中缓存） | 2677 万 | 2971 万 | 3090 万 |
| 报告字数 | 2.4 万 | 3.0 万 | 3.4 万 |
| 引用 | 312 条，带行号 219 条 | 366 条，带行号 226 条 | 371 条，带行号 224 条 |
| 带行号的引用越界 | 0 | 0 | 0 |

三遍的做法是同一个形状：

1. 第一分钟同时做两件事：读我们的架构说明；把题目里的词换成上游代码里的词去检索（「压缩」→ condens），半分钟内就打开了压缩器的源码，一分钟内打开会话持久化的源码。
2. 第 1 到 4 分钟顺着代码走：整文件读核心模块（44 到 59 次），按定义名、用法、事件名反复检索（36 到 40 次），读测试当规格，回头读我们自己的适配层看我们今天怎么做接力。
3. 之后边读边想，第 13 到 19 分钟写出初稿，再回头核对修改 10 到 17 次。

检索词是跟着读到的东西变的：先是题目里的词，然后是代码里的名字，最后是我们这边的概念。

## 文件

- `behavior.jsonl`：三遍共 515 个动作，一行一个：第几遍、第几秒、工具名、动作对象（路径相对快照根，`P/` 开头的是我们的项目）。从宿主的会话记录里还原，不是模型自己写的。
- `report-1/2/3.outline.md`：三份报告的标题结构各一份加「一页结论」，全文不在包里。
