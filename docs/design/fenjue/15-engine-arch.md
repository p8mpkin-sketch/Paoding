## 0. 一页结论与本文地位

**本文是分析引擎唯一的现行设计。** 它并入了三样东西：《分析引擎：换题就出点修的根因与架构方案》、《把对照接进焚决：试火成为每次炼化必过的门（补充设计）》，以及 cz 对它们的全部决定（Z1 到 Z10、N1 到 N13）。旧的两份已标明「已并入」，不再单独修订。以后任何改动只改本文。两份旧文与本文不一致的地方，以本文为准。

1. **根因是两个，都是从代码里读出来的。** 甲：引擎是一条开环的装配线。乙：判据不是共用的契约，语义判断被写成了词表、正则和门槛。它们不依赖与参照智能体的任何对比（第 2 节）。
2. **一条事实已更正。** 参照智能体与吸收器同机器属实，模型不同。差距里多少来自模型、多少来自架构，现在没有数。凡是拿「比参照智能体弱」当证据的表述、凡是默认两边模型相同的设计，都已逐处改掉（第 1 节）。
3. **方向不变：方向二，经由方向一到达。** 但方向二做多大，要等同模型对照的读数。迁移路径因此写成共用的步加两个分支，读数出来后 cz 只需选分支（第 10 节）。
4. **试火是每次炼化必过的门，原形是门的一部分。** 系统自己跑五条臂，计划预先登记，一份计划只判一次，人给的结局只能等于或低于系统判出的（第 4 节）。
5. **门可不可信取决于量具的三条性质。** 尺子只有一把：过线定义与臂无关，由试火台的盲判对所有臂用同一个定义判，并回到原文抽样核对（第 5 节）。每条臂钉住模型：模型必须相同，端点可以不同，花费各按自己的记录用同一张价表折算（第 6 节）。量具自己不靠人工：发现由系统记成结构化记录，归类与去重机械完成，留出题有可重复的产生办法（第 7 节）。
6. **墙钟不决定内容。** 时间只做看门狗和读数，做多少由预算账决定。按墙钟截断阅读与核对的两条线在第 2 步去掉（第 8 节）。
7. **调查线是最后一次手工炼化**，记为手工修订，照样过对照，不加品阶。之后的炼化由吸收器自己做，有专门的验收（第 9 节）。
8. **仍然空着、等 cz 填的只有三栏**：本火臂用哪个模型、走哪个分支、没见过的对象选谁，三栏的填法都已定（第 12.1 节）。试火的花费上限改由一条机械的规矩算出，不再手填（P9）。待定点 P1 到 P10 全部已定（第 12.3 节）。

本文是设计文字，没有代码。cz 本地运行的读数与现象没有写进来；文中的数字都出自公开仓库的代码与设计文档，或是按题数、臂数算出的估算。

## 1. 更正，以及受它影响的每一处

### 1.1 更正的内容

两份旧文的输入里都写过「参照智能体与吸收器同模型、同机器」。核对宿主记录之后：**同机器属实，模型不同。** 参照智能体用的是它默认配置的模型，吸收器用的是另一个更轻的模型。

由此有三条结论：

- 「参照智能体答到了、吸收器没答到」不是同模型对比。差距里多少来自模型、多少来自架构，现在没有数。
- 两个根因是从代码里读出来的，不依赖这条对比，仍然成立。
- 同模型对照的读数 cz 在量。本文在读数出来之前就定得下来：凡是取决于读数的地方，都写成了待填的栏或分支。

## 2. 两个根因

这一节的每条依据都是公开仓库里的代码，不引用任何与参照智能体的强弱对比。

### 2.1 根因甲：开环的装配线

流程里只有步骤，没有一个持有全局状态、并据此决定下一步的控制者。三个后果：

- **跨步的事没有主人。** 哪个子问还没答到、哪条缺陷还开着、预算还剩多少，都只是簿记里的字段。`qled.answer_phase` 把起草发现的问题放进 `problems`，把审读层次放进 `stats`，然后照常交付。
- **信息只往下游走，每一跳都有损。** 原文到细事实（每部分至多 24 条、每条至多 320 字），到答题稿，到核对（只看前 3 条引用、前后各 3 行），到改写（只看细事实文字，只许删），到审读（只看结论文字）。任何一跳都不能回头问上一跳。
- **压缩发生在需求明确之前。** 读原文的模型不知道写稿时会缺什么，就要先决定留下哪 24 条。

### 2.2 根因乙：判据不是共用的契约，语义判断被写成了枚举

- **契约有三份互相漂移的副本**：提示词里的散文、Schema、检验代码。漂移的地方模型只能猜。
- **该由看得到上下文的判断者做的事，被冻结成了词表、正则和门槛**：什么算问句、什么算源码、什么算命令句、什么算答到做法本身。每一张表都贴合见过的题，新题在表外。

两个根因相互独立。把装配线换成循环，K1 的规则模型照样看不到；把契约做对，写稿的模型照样看不到原文。所以方案里各有机制对应。

### 2.3 代码里的事实与它们各自的根因

| 现象 | 代码里的事实 | 根因 |
| --- | --- | --- |
| K1 反复不过 | 提示词写「取值见 Schema」；`essence.schema.json` 的 resolution 允许 6 个值；`checks._k1` 对体质类冲突只认 3 个。`cuiyi._payload` 只传特征的名字，不传 `probes.json` 里「特征到体质项」与「是否守门」两栏，K1 却要求冲突栏与拆分栏按这两栏填 | 乙。其中有两栏本可以由引擎查表填好，根本不必让模型写 |
| token 上限名实不符 | `Limits.token_cap` 注释是「整次运行」，全仓库只有 `read_phase` 用它算阅读份额；导出的过线判定里没有预算项 | 甲。预算是散在各个循环里的局部守卫，不是每次调用都要经过的一本账。现在实际有三本账，含义各不相同 |
| 问号错挂 | `dati.parse_draft` 发现「有可用的细事实却没有写出结论」，重来一次后留在 `problems`，印成一行附注 | 甲。检测有了，没有任何东西消费这个检测 |
| 审读过严 | `judge_depth` 只看结论文字，看不到原文；三档尺度都预设题面问的那件事在对方仓库里存在；判定只进 `stats` | 甲加乙。尺度照第一道题的形状定（乙），判错了没有申辩与重判的路（甲） |
| 两处特判 | `text.instruction_hits` 是子串匹配，词表里有日常用词；`survey.load_snapshot` 只排除六个目录名，其余按后缀认语言 | 乙 |
| 新问法在第一步掉出去 | `wenti.questions` 只认「怎么、如何、怎样、how」；子问上限 4 个 | 乙 |
| 新语言读不进 | `survey.LANGS` 映射十二个后缀（py、js、ts、md、toml、json、yaml、yml、txt、cfg、ini、sh，合十种语言），索引跳过其余文件；Go、Rust、Java 等仍然读不进 | 乙 |
| 子问一经确定不能改 | 前提不成立、一个子问其实是两件事，流程里都没有位置表达 | 甲 |
| 读完不能回头 | `read_phase` 的停止条件问的是「计划用完没有」，没有一处问「每个子问现在答得出来吗」；之后 `answer_phase` 里没有任何读原文的调用 | 甲 |
| 同一道题的结果取决于上游速度 | 阅读 8 分钟线与核对 20 分钟线按墙钟截断内容 | 甲。处理见第 8 节 |
| 验收题就是开发题 | `Limits` 的几条线取自同一道题的多次运行，提示词里的例子也用这道题 | 度量问题。处理见第 4、7 节 |

关于「判据在生成之后才出现」这一条，准确的说法是：多数规则在提示词里写了，不过后也带着错误重写；模型看不到的是三份副本对不上的地方。

### 2.4 为什么修完一批还有一批

每一轮验收后的修订都是往某一步里加规则，每一条都照着当时那道题的失败形状加。装配线不变，新题的失败形状就继续落在规则之外。同时，验收用的题就是调参用的题，新题按构造就是样本外。

还要说清一件事：按墙钟截断内容，会让同一个引擎在快慢不同的模型下读到不同的内容。所以根因甲的严重程度与所用模型有关，这正是要等同模型读数才能定范围的原因之一。

## 3. 目标架构

### 3.1 三个方向与取定的方向

|  | 方向一：装配线加闭环 | 方向二：索引加逐问调查（取定，Z1） | 方向三：单一通用循环 |
| --- | --- | --- | --- |
| 做法 | 步骤不变。加工单回路、契约单一来源、单一预算账 | 现有的并发阅读降级为建索引。每个子问一条调查线，写回答的模型带只读工具，能回到原文。含方向一的三个部件 | 一个上下文从头做到尾，流程约束只留在边界 |
| 写稿的模型能看到 | 细事实；可以请隔离的阅读者重读某一段 | 细事实当地图，原文按需打开 | 全部读过的原文 |
| 泛化（设计上的预期，有待试火去量） | 中 | 高 | 最高 |
| 可验证性 | 最高。每步输入输出形状固定 | 高。每个动作是一次固定模板的调用，可记录、可回放 | 低。一条长轨迹，难以分段回放与归因 |
| 成本 | 比现在略高 | 比方向一高，需要实测 | 最高，需要实测 |
| 迁移难度 | 低 | 中 | 高。现有步骤、检查点、录音大多作废 |

取方向二的理由是结构上的，不依赖强弱对比：方向一不解决「写的人看不到原文」，缺的一点在没读到的行里时，要经过发现、转述、派读、回填四跳；方向三放弃了分段可验证。方向一的三个部件方向二全部需要，所以先做方向一不是绕路。

**方向二比方向一多出来的那一段值多少，现在没有数。** 这是更正带来的变化：同模型对照之后剩下的差距，才是架构该负责的部分。迁移路径因此分成两个分支（第 10 节）。方向三不当引擎，它的最小实现用作试火里的异火单炼臂（N7）。

### 3.2 四个机制

**机制一，工单回路：发现即处理。** 系统里任何一处发现的问题都不许只写进记录，必须开成一张工单，工单必须有结局。

- 工单的形状是通用的：对象、缺什么（一句自然语言）、证据指针、谁发现的。没有「缺陷类型」这个枚举栏。
- 处理者只有一个通用的：把工单连同指针交还给产出那个对象的一方，它自己决定补读、改写、挪位置还是申辩。没有「某类缺陷对应某个动作」的映射表。
- 处理完由开单的那个检测重新判一次，通过就关单。产出方不能关自己的工单。
- 申辩：产出方认为发现是错的，就带着引用说明理由，交给一个隔离的、看得到被引原文的裁决调用。
- 结局只有三种：已关闭、申辩成立、未解决并写进交付。同一张工单两轮没关，按未解决上报。
- 一次运行只在两种情况下结束：工单清空，或预算账说停。

**机制二，契约单一来源：判据在生成时可得。** 每份产物只有一份契约，生成的输入、检验、错误信息都从它得出。

- 能由结构保证的，不让模型写。例如萃意里冲突栏指向哪个体质项、守门特征的拆分条目，由引擎查表填好。可选值按上下文收窄后再给。
- 不能由结构保证的规则，生成时原样给出编号、判法、用到的表。检验不过时的错误信息带同一个编号。
- 检验代码一行不动（Z4）。另写一份给生成用的契约描述，由 CI 里的一致性测试绑定：按描述生成的样本必须过检验，逐条破坏后必须不过。

**机制三，单一预算账：含义、约束、报告是同一个数。** 所有模型调用都经过同一本账，账在调用之前就拒绝，报告从账里打印。

- 位置在现有的 `Meter`：它已经包住了每一次调用，现在只计数，改成先预留再放行。
- 一本账一个单位：金额，与端点代理同一张价表（Z3）。上限的数值由 cz 给，不由引擎从自己的运行里推。token 数、调用次数、用时都是读数。
- 账内按用途分份额，后面的步骤有保底，前面的步骤借不走。
- 账说停时进入收尾：只交已核对的部分，未关的工单照实列出。
- 端点代理的硬顶（体质的预算上限）不动，它仍是最后一道。

**机制四，调查线：写的人能回到原文。** 这是方向二独有的一段。

- 题面解析交给模型，结构来保证不走样：每个子问必须逐字引用题面里的一段，引擎核对引用确实在题面里。任何问法都走这一步。
- 广读建索引：现有的检索、挑词、并发阅读保留，细事实的地位从「唯一依据」降为「地图」。
- 每个子问一条调查线，各线并发。每一轮模型输出一个动作，引擎确定地执行。动作只有固定的几种：看目录、检索、打开某文件的某段行区间；记一条结论（文字加引用的行区间）；改一条结论、提一个缺口、重新表述子问；收工。「前提不成立，对方实际是这样做的」是一种正式的回答。
- 上下文有界：记下结论之后，对应的原文从上下文里移出，只留结论与指针。轮数由预算账决定。
- 独立核对不变，输入补全：每条结论连同它引用的全部行区间交给隔离的核对调用。
- 引擎内的审计代替现在的审读：隔离的调用，能打开被引用的原文，尺度是「提问的人想知道的事答到了没有」（Z7），每条发现开成工单。「引到定义体内至少 2 条」降为只报告。
- 不依赖特定模型：每一轮仍是一问一答、输出一个 JSON 动作、过形状检查。

调查线上防护怎么落地（Z2 的五个限定条件）：只有只读动作；只在定版快照内；原文包在定界标记里；结论必须过独立核对才能进报告；它的输出不进萃意与归位。萃意与归位仍然只看不带名字的观察，不看原文。

### 3.3 体质五条原则各自怎么承接

| 原则 | 现在 | 目标架构里 |
| --- | --- | --- |
| 独立验证 | 结论由隔离的调用对着原文核对，标注只取核对结果 | 不变，并且核对看到结论引用的全部原文。审计与裁决也是隔离的调用 |
| 零外联 | 引擎不开网络，只读定版快照 | 不变。调查线的动作只在快照内，路径与行区间由引擎校验 |
| 预算上限 | 端点代理硬顶，加上引擎内三套局部的线 | 端点代理硬顶不动。引擎内合成一本账，在调用之前拒绝 |
| 证据分级 | 确认、推断、未核对分开标 | 不变。新增一类「未解决的工单」，单列，不混进回答 |
| 哈希链日志 | 步骤与产物经宿主工具登记 | 不变。调查线的每个动作、每张工单的开与关都是可记录的单元 |

### 3.4 机制覆盖得了什么，覆盖不了什么

三个没有出现过的情形，用来检查机制是否不加规则就能覆盖：

- **两条都通过了核对的结论互相矛盾**（一条引的是代码里的缺省值，一条引的是配置里的覆盖值）。审计看的是整份回答，提出一条自由形式的发现并指向两条结论；工单交给调查线，调查线打开两处原文后改写。全程没有用到任何与「矛盾」有关的规则。
- **仓库里有一份几万行的自动生成代码，检索词在里面命中最多。** 调查线打开一段，看到文件头的生成标记，转去找生成它的模板。成本是一次打开。压缩包附带的文件、第三方代码的副本是同一种情形。
- **一条检验规则本身错判了。** 命中开成工单，产出方申辩并给出上下文，隔离的裁决调用判定申辩成立。真的夹带指令时，裁决不支持申辩，条目照现在的严格做法丢掉并上报。

覆盖不了的一类：系统没有发现的问题。审计没有注意到的，工单回路帮不上忙。这一类只能靠试火里的盲判量出来（第 5 节），改进的对象是审计与调查的通用能力。某一轮的改动如果只能写成「遇到某种情况就怎样」，记为一次特判。

## 4. 试火：每次炼化必过的门

### 4.1 五条臂

| 臂 | 是什么 | 地位 |
| --- | --- | --- |
| B 本火 | 吸收之前的功法 | 必跑 |
| B′ 同火对照 | B 再跑一遍 | 必跑，用来估噪声底 |
| A′ 异火单炼 | 火意按原样装进我们的火位，过验体，不融合 | 必跑；做不出时结局最高合炼 |
| F 合火 | 融合后的新火 | 必跑 |
| A° 原形 | 被吸收对象按它本来的样子运行 | 必跑。条件对等时是门（原来「只作参考，不作门」） |

### 4.2 什么叫条件对等

对等声明在入位时预登记，随设计一起由 cz 裁决，跑之前就定死。对等要求四样相同：

1. **同一个模型**：名字与版本都相同，逐臂写进计划。端点可以不同（第 6 节）。
2. 同一台机器或同一类环境。
3. 同一批题、同一份定版材料。
4. **同一把尺子**：同一个过线定义，由同一套盲判来判（第 5 节）。

工具、流程、提示词不要求相同。它们正是被吸收的东西，原形就该用它自己的。

### 4.3 门管哪一维，判定表

门只管异火维，也就是我们想吸收它的原因。每份炼档至少登记一个异火维作为「吸收目标维」；对答题类的吸收，它就是留出题上的过线数，过线定义见第 5 节。本火维（可回放、零出站、证据分级、工单、核对）原形多半没有，不拿来比。花费是共有维，与 B 比，原形的花费照实报告。

记 m 为该维的噪声底（4.6）。

| 结局 | 条件 | 处置 |
| --- | --- | --- |
| 火莲 | 原有条件全部满足；并且每个异火维上 F 不低于 A° 减 m | 收，品阶加一 |
| 合炼 | 原有条件全部满足；并且每个异火维上 F 不低于 A° 减 m | 收，品阶加一 |
| 不及原形（新增，N1） | 体质全过，对 B 与 A′ 不退，本来够得上火莲或合炼；但某个异火维上 F 低于 A° 减 m | 不收。炼档记下差在哪一维、差多少。可以带着新的萃意再炼 |
| 并火 | 不变：不退，但没有任何一维显著胜过 B 与 A′ | 不收 |
| 反噬 | 不变：验体不过，或本火维退步 | 不收 |

不及原形与并火分开记，因为诊断不同：并火说的是融合没有比照搬多出东西；不及原形说的是移植丢了东西，多半是萃意没有抓到核心。三个差值各有含义：A′ 减 B 是这个做法拿来就用值多少，F 减 A′ 是融合值多少，A° 减 F 是移植还欠原形多少。

**人不能越过门（N4）。** 人在裁决时给的结局只能等于或低于系统判出的结局，对等情形没有豁免。

### 4.4 条件不对等，以及两个记号

不对等的原因必须在入位时写明并归类，跑完之后不许改口（N3）。

| 情形 | 例子 | 处理 |
| --- | --- | --- |
| 原形自带专用工具，但能在我们的机器上用同一个模型运行 | 它有自己的检索工具、自己的循环 | 算对等，门照判 |
| 不对等对我们有利，或不偏向任何一方 | 原形只能用更弱的模型 | 门照判。输了照样不收，结局记不及原形。没输的话不算过门：原形门记「未判」，结局最高合炼，比较的结果只作旗帜。处置与 4.6 里样本不足时相同 |
| 不对等对原形有利，且无法消除 | 原形绑定一个我们用不了的更强模型；原形必须联网取数 | 门降为参考，结局最高合炼，并且需要 cz 在设计裁决时对这一份炼档单独写下豁免。没有豁免，门照判 |

原形需要出站才能运行时，它不在我们的信任边界内运行：在沙箱之外、经 cz 逐次批准，它的输出按外部数据对待。

两个记号分开用，都公开显示在炼档与能力页上：

- **原形门未判**：还没有一次在对等条件下判出来的结果。包括：原形臂还没法跑（原形适配的最小条件不具备）；属于上表第三种并有豁免；属于上表第二种而没输；读数少于预登记的样本量（4.6）；入位时没有登记吸收目标维或对等声明。结局最高合炼。条件具备后补判，补判输了就改挂下一个记号。对等声明只能在入位时写：入位时没写的炼档，设计裁决之后补不了，这一份永远是未判。
- **原形门未过**：判了，输了。只出现在按 N6 装入的手工修订上（第 9.1 节），只能由之后的一次过门摘掉。

### 4.5 谁跑，什么时候跑

**新增一个试火台，归量具。** 它不属于吸收器，吸收器的任何一次炼化都改不到它。人不再手填读数。试火台做五件事：

1. 读炼档里预登记的试火计划，核对它的哈希与设计裁决时记下的一致。
2. 按计划把每条臂在每道题上跑起来。B、B′、A′、F 是换上对应功法的我们自己的系统；A° 经「原形适配」启动被吸收对象本身（第 6.3 节）。
3. 把各臂的产出交给同一套盲判（第 5 节）。
4. 按 4.3 的判定表算出结局。
5. 写出试火记录，连同每条发现的记录（第 7 节）。

**核对发生在花钱之前。** 凡是登记批次时已经知道的，都在登记批次时核对，对不上就不登记：盲判三段的版本与抽样量是不是现在这把尺子的、花费上限有没有并且是正数、要跑的臂与计划里逐臂那一栏是否逐项相同、盲判的模型与各臂是否不同。计划里已经写了的东西，批次登记时从计划里取，不另抄一份。只有跑完才知道的（读回的模型标识、功法摘要、花费合计）才留到出记录时核。选盲判模型时还没有批次，同一道核对（自检是否全部判对并且在时限内、盲判是不是计划登记的那一个）也由机器判，不由人拿屏幕上的数去比。

留出题在 cz 那边，所以判定用的那一轮试火在 cz 的机器上由系统跑，一条命令。回到会话里的只有汇总数（第 13 节）。

试火在验体通过之后、裁决之前，分两段：

| 段 | 用什么题 | 作用 | 能不能重跑 |
| --- | --- | --- | --- |
| 试跑 | 开发题 | 确认各臂都跑得起来、计划写得对。结果只作旗帜 | 随便 |
| 判定 | 留出题 | 出结局 | 一份计划只判一次。想再判，得改设计、重新预登记 |

同一套留出题最多用于 3 次判定，之后轮换至少一半的题（N10）。中期旗帜不计次数，但一道题的失败细节一旦被拿来指导修改，它就转为开发题并换一道新的（Z6）。轮换用的新题从哪里来，见第 7.3 节。

### 4.6 样本、噪声底、花费、记录

**样本。** 每条臂每道题跑 2 次（N2）。计数的单位是「题次」：一道题的一次运行。20 道题就是每条臂 40 个题次。两条臂按「同一道题、同一个序号」配对。

**成对比较。** F 对 A°、F 对 B、F 对 A′、B 对 B′ 都报四格计数：都过、都不过、只有前者过、只有后者过。

**噪声底 m。** 记 d 为 B 与 B′ 结论不一致的题次数。两条完全相同的臂，它们的净差（只有甲过的减只有乙过的）的波动大小约为 d 的平方根。取 m 为 2 倍的 d 的平方根，向上取整，最小为 1。这比旧文二里「m 就是不一致的题数」更准：本火很不稳定时，旧算法会把门放得过宽。此处是对 N2 甲的细化，列在第 12 节请 cz 确认。

**门的判法（N2 甲）。** 「只有 A° 过」的题次数减去「只有 F 过」的题次数，不超过 m。旁边照实报区间。20 道题时区间很宽，这一点写在记录里，不粉饰。读数少于预登记的样本量时，结论只作旗帜：原形门记未判，结局最高合炼。

**花费。** 走单一预算账。试火有自己的上限，写在预登记的计划里，按一条机械的规矩算出，不手填（P9）：每题上限取试跑段里本火每题花费中位数的 3 倍，一次试火的总上限等于题数、臂数、次数与每题上限的乘积。试跑段在计划登记之前跑完，取第 2 步之后的本火（第 2 步之前的花费被两条时间线压低，用它定出的上限会偏紧）；算出的上限写进计划，登记之后不改。账说停时试火中止，结局记「未判」，不收。允许复用（N11）：B 与 B′ 的结果按「功法摘要、题集摘要、模型」三样复用，A° 的结果按「对象版本、题集摘要、模型」复用，三样里任何一样变了就作废重跑；复用要在试火记录里写明来源批次。

**记录。** 不新增任何事件种类，不动事件账的代码。

- 每条臂的每一次运行都是系统里一道普通的题，开题时钉住该臂的功法摘要，照常进哈希链事件账。
- 试火记录是一份产物：计划哈希、各臂的功法摘要或对象版本、各臂的模型与计量来源、题集代号与题集摘要、盲判版本、每臂每题次的结果、四格计数、花费、每次运行的题号与日志头哈希。炼档里记试火记录的哈希。
- 原形臂是例外：它不在我们的系统里运行，没有我们的事件账。它每次的产出与用量导出按输入材料登记并记哈希，启动它的命令与对象版本写进记录。
- 题集摘要只是一个哈希，题面与仓库不出现在记录里。

### 4.7 度量只有一套

旧文一的三套题就是炉题的三种用途，它的对照臂就是原形臂。数据只有一份：试火计划、试火记录、发现记录。按单份炼档看，得到结局；按时间把历次记录排起来看，得到新类别曲线、特判计数与表项计数的走势。

| 说法 | 在试火里的位置 |
| --- | --- |
| 开发题 | 炉题，用于试跑。失败细节可以看 |
| 回归题 | 验体与 CI 用的夹具和脚本化场景，不调真模型 |
| 留出题 | 炉题，用于判定。只回传汇总数 |
| 留出题上的过线数 | 异火维，也是吸收目标维，门就判在这一维上 |
| 每题花费、用时、表项计数 | 共有维 |
| 未解决工单数、各检验首次通过率、引擎内核对的结果 | 本火维，只报告，不进门 |
| 注入服从数、凭据泄漏数 | 本火维，门槛为零 |
| 特判计数 | 炼档的度量栏，与「体质改动行数」并列 |
| 新类别曲线 | 进化页上的跨炼档读数，由发现记录算出（第 7 节） |

**「点修趋于零」的三个判据。** 新类别曲线走平：每道没用过的题带来的新失败类别数趋于零。连续两份炼档的特判计数为零，表项计数不增长。修复能迁移：一次改机制的修订在没有触发它的题上不退步。

**「实战能力」的定义。** 两边模型相同、原形门可判时，吸收器的实战能力是它在留出题上相对于原形臂的结果：过线的成对比较，加上花费。原形门未判时，只报绝对过线数与花费，并在读数旁标明：这个数分不清题难还是引擎弱，不能据此说强弱。

### 4.8 由什么强制

「对照不过就不能入位、不能散火」的读法（N5）：不能入位，指不能把火装进功法。主动撤掉一团火或删简功法算一次改动，要过对照。紧急回退到上一团已经过门的火不需要对照，但要进记录，并在事后补一次试火。

强制点有三处，都在量具里：

| 强制点 | 今天 | 改后 |
| --- | --- | --- |
| 读数从哪来 | `ronghuo` 接受命令行手填 | 运行读数只从试火记录读入，手填的入口关掉 |
| 谁能改功法 | `jue` 接受人给的任何结局，结局是火莲或合炼就装进功法；`judge` 完全不读原形臂 | `jue` 在装进功法之前核三样：试火记录存在且哈希对得上；记录里的计划哈希等于设计裁决时记下的；按记录重算的结局允许装入。人给的结局只能等于或低于重算的结局 |
| 绕过去怎么办 | 手改功法文件没有人拦 | CI 里已有的炼档核对与功法存档核对各加一条：功法品阶史里每一行都要指向一份带合格试火记录的炼档；功法摘要的每次变化都要对得上一次裁决或一次散火 |

试火的盲判与引擎内的审计分成两份（N9）：引擎内的审计是功法，吸收器可以改进它；试火的盲判是量具，固定版本，改动单独提、单独裁，引擎内的审计不得读它的结论。

两份旧炼档：炼档 001 是新规则之前的，按档号划线豁免，不追溯。炼档 002（按题读仓库）停在「设计已裁」，登记的臂只有 B 与 F，当时没有原形臂，它与原形孰强孰弱无从判断。按 N8 甲，用第 0 步起点轮的读数按新规则照实判一次，判成什么记什么；原形臂补跑之前，它挂「原形门未判」。

试火计划与试火记录同样按档号划线，从炼档 003 起：003 及以后的炼档在设计裁决之前登记计划，运行读数只从记录读入，定阶时核记录。002 在划线之前，它没有预登记的计划，起点轮的读数照旧由人按汇总数填；「人给的结局只能等于或低于系统判出的」对它同样生效。

## 5. 量具性质一：尺子只有一把

### 5.1 原则

门所判的那一维，由试火台的盲判用同一个定义判所有臂。一条臂没有的机制，不能出现在门的条件里。吸收器内部的读数（引擎内的核对、工单、各检验的通过率）只作共有维或本火维报告。

### 5.2 盲判看什么，不看什么

对每条臂的每个题次，盲判拿到的东西完全相同：

- 题面。
- 这道题的子问清单。清单随题目一起定下，由出题的一方给出（第 7.3 节），不由任何一条臂拆出来。这样拆问拆得好不好也在被度量的范围里。
- 该臂最终交出的回答文本。
- 定版快照，只读。

盲判不看：臂名、过程日志、引擎内的核对标注、工单、细事实、该臂自己拆的子问。

### 5.3 吸收目标维的过线定义

一个题次过线，当且仅当下面三条都成立。三条对任何一条臂都有意义。

| 条件 | 判法 | 谁判 |
| --- | --- | --- |
| 答到 | 每个子问都被判为答到。尺度是「提问的人想知道的事答到了没有」（Z7）。前提不成立，且用证据说清了实际情况，算答到 | 盲判的判读 |
| 属实 | 回到原文抽样核对，被抽到的结论里没有一条被原文否定，也没有一条找不到依据 | 盲判的抽样核对 |
| 在预算内完成 | 这个题次折算后的花费不超过计划里每题的上限，并且运行正常结束。被看门狗终止、崩溃、没有交出回答，都算没完成 | 花费记录与运行状态，机械判 |

旧文二 12.3 里的另外两条（核对通过、没有未解决的工单）退出过线定义，改为本火维的报告。由此多出一个有用的读数：引擎自己标为「已核对」的结论，被盲判抽样否定的比例。它量的是引擎内核对本身靠不靠得住。

### 5.4 盲判怎么做：三段

1. **整理。** 一次调用把回答整理成统一的清单：每个子问下面列出回答里承重的结论，每条带它在回答原文里的逐字片段，以及回答给的引用（如果有）。整理只许摘，不许补：每条的逐字片段由程序核对确实在回答里。这一段的作用是抹掉各臂在篇幅与排版上的差别，让后两段看不出是哪条臂写的。
2. **判读。** 只看题面、子问清单与整理出的清单。对每个子问判答到、部分答到、没答到，并写一句理由。
3. **回原文抽样核对。** 从清单里抽结论，每条交给一个带只读工具的核对调用，对着定版快照判：成立、被原文否定、找不到依据。回答没有给引用的结论照样查，由核对者自己去找；这样引用习惯不同的臂受到同样的对待。

**要抽，抽多少。** 要抽：不回原文，尺子量的就只是回答读起来像不像，而这正是现在审读的毛病。建议的量：每个子问抽 2 条承重结论，一份回答至多 8 条；某个子问不足 2 条就全查。抽样量对每条臂相同。抽哪几条由随机种子决定，种子由计划哈希与题号派生，跑之前就定死。这个量是新增的待定点 P1，另两个选项是全查承重结论（更贵，篇幅长的臂吃亏）与每份回答固定抽 3 条（更省，对多子问的题覆盖不到每个子问）。

盲判用的模型与版本写在计划里，单独登记，对所有臂是同一个。用哪个模型按一条规矩选（P8），本文不点名：

- **与实际出现的各臂所用的模型都不同。** 理由：各臂钉在同一个模型上时，盲判若也用它，评的是同一家模型的文字，偏松，并且与各臂有同样的盲点。
- **候选按强到弱排，取第一个同时满足两条的。** 一，5.5 的三份已知答案的自检样本全部判对。二，判得完：自检时每个题次的盲判用时不超过计划里登记的每题次盲判时限。要强的，是因为回原文抽样核对要在大仓库里自己找依据；要判得完，是因为一个题次的盲判是很多次调用，太慢的候选跑不完一轮。
- **每题次的盲判时限**取试跑段里本火一遍用时的中位数，意思是判一个题次不该比答一个题次更久。它在计划登记之前算出，写进计划，登记之后不改，对所有臂是同一个数。

具体是哪个模型由 cz 跑自检时填。自检记录里记每个题次的用时；没有「全部判对并且在时限内」的自检记录时盲判拒绝启动。之后追加的臂如果用了与盲判相同的模型，那一批另选盲判并重跑自检，两批不混。三段的提示词是量具，固定版本。

### 5.5 尺子自己准不准，怎么查

- **换臂名测试。** 同一份回答标成不同的臂送进去，结果必须逐项相同。
- **盲判的金丝雀。** 三份已知答案的样本：故意漏掉一个子问的回答、故意写错一条承重结论的回答、前提不成立且说清了实际情况的回答。分别应当判出没答到、不属实、答到。任何一份判错，这一批盲判不作数。自检记录里带每个题次的用时与样本自己的版本；启动前核对的是「全部判对、每个题次都在计划登记的时限内、样本与提示词都是现在这一版」。样本的版本只由自检真读的文件决定。自检的用时不能当真实题次用时的上界读：样本题次比真实题次小得多；真实的用时由汇总里正式判每题次用时的中位数与最大值报出，每个批次都报。
- **重判一致率。** 每批抽五分之一的题次重判一遍，报两遍结论一致的比例。盲判自己的抖动也已经包在 B 对 B′ 量出的噪声底里。
- **门的输入清单测试。** 判定函数在吸收目标维上只读盲判的产出与花费记录。它读任何一条臂内部的字段，测试就不过。

一个照实说明的局限：整理这一段看得到回答原文，理论上可能对不同文风摘得不一样。缓解办法是「只许摘、逐字可核」，以及金丝雀里用两种文风各做一份。它不能完全消除。

## 6. 量具性质二：每条臂钉住模型

### 6.1 计划里逐臂登记什么

预登记的试火计划里，每条臂各有一组必填的栏：

- 模型名与版本标识。
- 端点：经我们的端点代理，还是直接连服务商。
- 能设置的采样参数：温度、输出上限、推理档位等。能设成相同的就设成相同，设不了的列进不对等项。
- 计量来源：我们的预算账，或该臂自己导出的用量。
- 价表版本。

**本火臂用哪个模型是一个待填的栏，由 cz 在读数出来之后定。** 本文不默认任何一个模型。这一栏填上之后，其余四条臂用同一个模型。这一栏空着的时候，试火台拒绝登记计划。

每个批次的汇总都带着模型名与版本。不同模型下的批次不放在一起比，也不进同一条曲线。

### 6.2 两边经不了同一个端点代理时

cz 的理解是：模型必须相同，端点可以不同，花费各按自己的记录、用同一张价表折算。**确认，就这样定。** 补四条使它站得住：

1. **用量的口径要对齐。** 两边都报四个数：新输入、命中缓存的输入、输出、调用次数。折算时命中缓存的部分按价表里的缓存价算。新增用量与账面用量分开报，因为两种架构在缓存上的差别可以很大。
2. **用量不能只听一面之词。** 参照那一侧的用量是它自己导出的。做法是给每条臂一把专用的密钥，批次结束后拿导出的合计与服务商账单上这把密钥的合计对一遍，差异写进记录。
3. **上限怎么强制。** 我们这一侧由预算账在调用之前拒绝。参照那一侧如果不能事前设限，就事后按折算的花费判：超过每题上限的题次，按过线定义的第三条记为不过。两侧用的是同一个上限数。
4. **同名模型在不同端点上可能有细微差别**（缺省参数、上下文长度、服务商侧的版本切换）。所以 6.1 要求逐臂登记版本标识与采样参数，运行记录里读回的模型标识要与计划一致。能让两边走同一个服务商端点时就走同一个。

### 6.3 原形适配的最小条件

原形臂要能进门，参照那一侧至少要做到六件事：

1. **能指定模型**，并且能从运行记录里读回实际用的模型标识。
2. **能导出每次运行的产出**：最终回答的文本，机器可读。
3. **能导出每次运行的用量**：6.2 第 1 条的四个数。
4. **能无人值守地启动**：一条命令，输入是题面与快照的位置，中途不需要人回答问题。
5. **能只对着定版快照工作**：除模型端点外不联网。做不到的话按 4.4 的不对等处理。
6. **每次运行从干净状态开始**：不带上一次的记忆与缓存文件。

**这六条具备之前，原形臂只作参考，相关的炼档标「原形门未判」。** 具备之后补判，补判不改计划里其他任何栏。

**原形臂经我们的端点代理（P10，取「配」）。** 参照那一侧配置成直接用我们的端点代理。这样原形臂与本火臂是同一个端点、同一本账计量，用量不必听那个程序自己导出的数：六条里的第 3 条由代理满足。此时 6.2 里端点不同时的四条折算用不上，只作一般机制保留。

第 1 条要说清一个事实：**代理不拦模型。** 端点代理把请求里的模型原样转给上游并按它计价。所以模型钉在客户端（启动参数里指定），核对靠读回：代理的流水里每一次调用都带模型标识，按 6.4 逐次核对。「代理只放行登记的模型」不在这里做：它落在体质路径里，要做就是另一次体质改动，单独提、单独裁。

第 4、5、6 条需要一个隔离的工作环境：不带这个项目的记忆与工具、不能联网、每次从干净状态起。它用现成的模型容器那一套隔离机制起（`adapter/src/paoding_adapter/container.py`），经适配层的契约接口借用，不改适配层：

- 每次运行一张内部网络，并且隔离网关：容器没有出站路由，也到不了宿主在网桥上的地址。
- 网络上只放一个端点中继，原形臂够得着的只有模型端点代理。我们的工具端点不给它。
- 容器里只有任务令牌与中继的地址，真实密钥留在代理进程里。挂进去的只有定版快照的一份副本、一个空的输出目录与一个全新的主目录。
- 隔离网关建不出来时（老版本 Docker）不退回普通的内部网络，原形臂拒跑。
- 冒烟时从容器里各连一次外部地址与宿主地址，两次都必须连不上；连得上，第 5 条不打勾。

不直接用评测台里对照臂的沙箱：它借的是执行层的网络，那张网络的网关还没有隔离，宿主上监听全部接口的服务够得着；这个缺口另行单独修。

### 6.4 怎么测

- 计划里任何一条臂的模型栏空着，或各臂的模型名与版本不全相同而又没有登记为不对等：试火台拒跑。
- 读回逐次调用都做，不只核主循环：一个题次里有任何一次调用读回的模型标识与计划不符，那个题次作废重跑；整条臂都不符，试火中止，结局记未判。
- 折算的单元测试：同一份用量，从预算账的形状与从导出的形状各折算一次，结果相等。
- 适配的冒烟测试：一道开发题，原形臂跑通并导出产出与用量，六条逐条打勾。

## 7. 量具性质三：量具自己不靠人工

### 7.1 现在靠人的三处

失败类别由人起名；留出题由人出；cz 每一轮读失败、列出要修的点，也是人在归类。这三处都让人站在了计数的环节里，正是要去掉的做法。下面三节各解决一处。

### 7.2 发现由系统记成结构化的记录

盲判每给出一个不利的判断，就自动产生一条发现记录。不利的判断有五种：某个子问部分答到、没答到、某条结论被原文否定、找不到依据、运行没完成或超出预算。

一条发现记录的形状：

| 栏 | 内容 |
| --- | --- |
| 定位 | 批次、臂、题代号、题次序号、子问序号 |
| 来源 | 盲判的判读、盲判的抽样核对、运行状态，三选一 |
| 判定 | 上面五种之一 |
| 一句自由文字 | 说的是现象的机制，例如「问的是为什么这样设计，回答只描述了是什么」。不带题面与仓库里的专有名词，程序对照快照的标识符清单检查 |
| 证据指针 | 回答里的逐字片段位置，以及原文的路径与行区间 |
| 记录哈希 | 上面各栏的哈希 |

引擎内的审计与工单也产生同样形状的记录，来源栏另标。它们用来定位引擎里哪一步出的问题，属于本火维，不进新类别曲线。曲线只用盲判来源的记录，因为只有它对所有臂是同一把尺子。

留出题上的发现记录留在 cz 那边。回传的只有类别编号与计数。

### 7.3 归类与去重由系统机械完成

**类别登记簿。** 每个类别只有三样：编号、代表句（落进这一类的第一条发现的那句话）、至多三条例句。类别没有名字，不需要人来起。

**归类器。** 一次固定版本的模型调用：输入是新发现的那句话与登记簿，输出只有两种，「归入第几号」或「新类别」。发现按记录哈希的顺序逐条处理，所以同一批记录重算一遍得到同一个划分。同一个问题换一道题再出现时，自动落到已有的类别上。

这里的「机械」指三件事：没有人在环节里、版本固定、可以重放。它仍然是一次模型判断，不是词表或正则。「这两条发现是不是同一个问题」是语义判断，按根因乙的教训，不该写成枚举。

**人在哪里。** 人可以读，可以给类别贴标签。标签只用于显示，不进计数。人认为两类该合或一类该拆，只能提一次归类器的版本改动（量具改动，单独提、单独裁），然后全部记录按新版本重算；不能手改某一条的归属。cz 每轮「读失败、列要修的点」换成读系统给出的清单：类别、出现次数、证据指针（开发题上可以点开看细节）。

**新类别曲线由这些记录算出。** 横轴是累计跑过的新题数，纵轴是登记簿里的类别数。下一次失败属于没见过的类别的概率，约等于「只出现过一次的类别数」除以「发现总数」。每条臂各有一条曲线。

**怎么测归类器。**

| 测什么 | 做法 | 合格 |
| --- | --- | --- |
| 换题重现 | 一组成对的发现：同一个机制出现在两道不同的题上，来自开发题上的记录与专门写的换述。另一组是已知不同机制的对 | 同机制的对落进同一类、不同机制的对不落进同一类，两项的比例都不低于预登记的线（建议 90%，P3） |
| 顺序稳定 | 把处理顺序打乱重算 | 两次划分里「任意两条是否同类」的一致率不低于同一条线 |
| 重复稳定 | 同样的输入算两遍 | 划分相同 |
| 金丝雀 | 每批混入两条已知答案的记录：一条是已有类别的换述，一条是确实全新的 | 前者不增类，后者增类。判错则这一批的曲线点不作数 |

曲线旁边同时报归类器在换题重现集上的两个错误率。拆多了会让曲线偏高，并多了会让曲线偏低，读曲线的人要能看到这个范围。

### 7.4 留出题有可重复的产生办法

「用过就作废」加上「每 3 次判定轮换一半」，要求源源不断有新题。新增一个题目生成器，归量具，在引擎之外。

**与 Z6 的关系。** Z6 维持：cz 手出的第一套留出题照常用，并且充当锚。生成器负责轮换与扩充。生成的题集要先与锚对过一次才能当尺子用（见下面的「怎么测」）。这是对 Z6 的补充，列为 P2 请 cz 确认。

**四步。**

1. **取样仓库。** 按预登记的配额沿两条轴取：语言、仓库大小。候选来自公开仓库的检索结果，用固定的随机种子抽，钉住提交号。许可证不允许的、已经在开发题与回归夹具里用过的、之前任何一套题用过的，都排除。
2. **出题。** 一个固定版本的出题调用带只读工具读快照，按分配到的格子出一道题。格子由另外三条轴决定：问法（怎么做、为什么、是否、有什么区别、在哪里）、前提是否成立、答案在代码还是在配置文档。它交出四样：题面、子问清单、每个子问的答案要点、每个要点的证据指针。前提不成立的题，要交出「确实没有」的证据：查过哪些词、本该在哪里、那里实际是什么。
3. **自动校验。** 五项全过才入库，任何一项不过就丢弃重出。
   - 证据指针都在快照里，行区间不越界（程序判）。
   - 一个没看过出题过程的独立调用，只拿着题面与指针指向的原文，判这些原文是否支持每个答案要点。
   - 题面不泄底：不含文件路径，不含证据所在定义的确切名字（程序对照快照的标识符清单判）。
   - 不读仓库答不出：让同一个模型不给快照直接作答，用第 5 节的盲判来判，必须不过线。这一项滤掉靠常识就能答的题。
   - 与已有的题不重复：同一套题里一个仓库只出一道。
4. **入库与摘要。** 题集连同生成器版本、种子、配额一起算出题集摘要。回传的只有摘要与各格的题数。

**在哪里跑。** 留出题在 cz 的机器上生成，内容不进会话也不进仓库。取样仓库这一步要联网，联网的是生成器，不是引擎；快照钉住之后，各臂仍然只读快照，零外联不受影响。开发题可以用同一个生成器在任何地方生成，内容公开。

**出题的模型会不会偏向某条臂。** 所有臂用同一个模型，所以出题模型即使带有自己的偏好，对各臂也是一样的。它会影响绝对过线数，不影响臂与臂的比较。

**怎么测生成器。**

| 测什么 | 做法 | 合格 |
| --- | --- | --- |
| 校验拦得住坏题 | 四道故意做坏的题：指针越界、前提标错、题面泄底、不读仓库也能答 | 四道都被丢弃 |
| 可重复 | 同样的种子与配额跑两遍 | 抽到的仓库与各格的分配相同。题面文字允许不同，两遍各自记摘要 |
| 题目质量 | 用同一个生成器出一套开发题，人抽检其中一部分，看题面是否像人会问的、答案要点是否对 | 报抽检的符合率。这是校准，人不在计数的环节里 |
| 与人出的题是不是同一把尺子 | 第一次启用时，本火臂在 cz 手出的锚题集与生成的题集上各跑一轮 | 两边的过线比例之差在噪声底之内，生成的题集才能用于判定；否则只用于旗帜，并把差异当作生成器的缺陷去查 |

## 8. 墙钟不决定内容

### 8.1 原则

时间只做两件事：读数，和看门狗。一次运行做多少事，由预算账决定。

### 8.2 现状

代码里有两条按墙钟截断内容的线：阅读到 8 分钟停（`Limits.read_stop_s`），核对到 20 分钟停（`Limits.verify_stop_s`）。到线之后运行照常往下走，交付的是读得少、核得少的结果。模型慢一些或者端点挤一些，同一道题读到的内容就不同。换模型做对照时，这会让对照不公平。

### 8.3 改法，放在第 2 步

- **两条线不再截断内容。** 阅读的停止条件只剩下与内容和预算有关的几条：读满份数、连续两批没有新事实、没有可追的、预算份额用尽。核对把该核的核完，或者预算账说停。
- **时间改做看门狗。** 整次运行一个总时限，加上已有的无进展时限。看门狗触发时运行被终止，记为「未完成（超时）」，不交付截短的内容。按过线定义的第三条，这个题次不过线。
- **看门狗的时限写在试火计划里，对所有臂是同一个数，并且设得宽。** 建议取试跑段里该模型下最长一遍用时的 3 倍（P6）。它的用途是救挂死的运行，不是控制做多少。
- 用时照常记录，进汇总。

这样改之后，同一道题在快慢不同的模型下做的事相同。慢只表现为两种看得见的东西：用时读数更大，或者明确的「未完成（超时）」。不再有悄悄变短的内容。

去掉墙钟线不必等单一预算账做完：阅读本来就有份额与调用预留两条上限，核对的量由结论条数决定，都是有界的。所以它是第 2 步里的第一件事（2a），预算账是第二件（2b）。

### 8.4 第 2 步之前怎么办

第 0 步按 Z10 不改引擎行为，所以起点轮是带着墙钟线跑的。三条对策：

- 起点轮的并行度固定并写进批次头；本火与同火对照交替排队，使机器与端点的忙闲对两条臂相同。
- 汇总里加一个字段：因时间线停下的题次数。它直接说明起点轮的读数有多少是被墙钟决定的。
- 第 2 步完成后功法摘要变了，按复用规则本火的读数本来就要重跑。重跑的这一轮是以后各次试火用的本火读数。

由此有一个需要 cz 确认的取舍（P4）：调查线那份炼档里的本火臂，建议取「第 2 步之后的第 2 版引擎」，而不是原样的第 2 版。理由：原样的第 2 版读数随机器快慢而变，噪声底会被撑大，门也就跟着变宽；而且拿一个被墙钟截短的本火去比，「对本火不退」就太容易过。相应地，第 2 步单独记为一次修订（修缺陷），不并进调查线的手工炼档。

### 8.5 怎么测

- **拖慢不改内容。** 用假时钟把每次调用拖慢若干倍，回放同一份录音：产物逐字节相同，只有用时读数不同。
- **看门狗触发的场景。** 运行记为未完成，没有部分交付，事件账里有终止记录。
- **静态检查。** 引擎里读墙钟的调用点由 CI 列出清单，除看门狗与读数外不许有别的用途。

每一步要多少机器时间、哪些能并行，见第 10.5 节。

## 9. 出身、自炼验收、体质边界

### 9.1 出身：手工做的那一次怎么记

炼档的「出身」一栏必填，有三种取值，进化页按它分开计数：

| 出身 | 含义 | 加不加品阶 | 算不算一次成功的炼化 |
| --- | --- | --- | --- |
| 自炼 | 吸收器自己从外部对象提出候选，走完全程 | 结局是火莲或合炼时加 | 算 |
| 手工 | 人设计、人实现，吸收的是外部对象的做法 | 不加 | 不算，单列一栏「手工引导」 |
| 修订 | 修缺陷、删简，不引入外部对象的新做法 | 删简按现有规矩加；修缺陷不加 | 不算 |

契约单一来源、工单回路与调查线合在同一份手工炼档里。第 2 步（去掉墙钟线、单一预算账）单独记为一次修订（8.4，P4）。

手工不免除任何一条臂。调查线这份炼档里五条臂是：

| 臂 | 是什么 |
| --- | --- |
| B | 第 2 步之后的第 2 版引擎（P4） |
| B′ | 同上，再跑一遍 |
| A′ | 方向三的最小实现：一个上下文的通用循环，用同样的只读动作，过验体，不建索引、不分调查线、不带工单回路（N7） |
| F | 方向二 |
| A° | 参照智能体本身。模型按计划钉住；适配条件不具备时标「原形门未判」 |

结局与装入（N6）：

1. 结局一栏按 4.3 的判定表算，是什么就写什么，包括「不及原形」。
2. 无论结局是什么，出身是手工，不计入成功的炼化，品阶不加。
3. 它按「手工修订」装入功法，条件是验体全过、对 B 不退。装不装入只看这两条与「裁决人没有把结局往低里改」，不看结局是哪一种：火莲、合炼、并火、不及原形都装，只有反噬不装。判成并火的这一格要说清：并火说的是没有可量的增益，不是退步，所以手工的炼档判成并火也照样装入，不加品阶、不计成功。
4. 对 A° 判了没过，这团火挂「原形门未过」；还没法判，挂「原形门未判」。

**这是最后一次手工炼化。** 这份炼档裁决之后，凡是引入外部对象做法的改动，出身必须是自炼；手工的需要 cz 对那一份单独写下例外。自炼的炼档必须带吸收器运行的题号与日志头哈希，手工的拿不出来。

### 9.2 自炼的全程

| 步 | 谁做 | 人在哪里 |
| --- | --- | --- |
| 识火、萃意、入位 | 吸收器。入位时同时写出试火计划：臂、维、门槛、对等声明、各臂的模型、样本量、预算 | 三个闸点照旧由 cz 决定 |
| 实现 A′ 与 F | 系统自己的实现线：把入位方案当作一道题交给执行道去做，验收是验体加测试 | 不写设计，不写代码 |
| 验体 | 确定性测试 | 无 |
| 试火 | 试火台 | 无 |
| 结局 | 按判定表算出 | cz 裁决，只能等于或低于算出的结局 |
| 合入与入功法 | `jue` 在核过试火记录之后改功法 | cz 合并 |

### 9.3 自炼的验收：两场，加三只金丝雀

**第一场，重演（N13：对象用调查线本身）。** 让方向二落地后的吸收器，自己再吸收一次参照智能体的核心。给它的材料是参照智能体的行为材料，以及我们自己的仓库钉在手工炼化之前的那个提交；它看不到手工那一次的设计与代码。过关条件：它自己提出的候选里有与调查式做法对应的一个；它产出的合火在留出题上不比手工那一次的合火差（差值在噪声底内）；全程人写的设计与代码行数为零。小分支下这一场有调整，见第 10.4 节。

**第二场，没见过的对象（N13：由 cz 选，内容不进会话）。** 过关条件看的是流程是否自己走完、结局是否照实，不看结局是哪一种：炼档齐全，试火计划在跑之前预登记，各臂由试火台跑完，结局按判定表算出，人的介入只有闸点上的决定。结局是并火或不及原形也算过关。

**三只金丝雀，验的是试火台本身。** 每次改动试火台都要重跑，任何一只判错，试火台出的结局不作数。

| 金丝雀 | 做法 | 应当判出 |
| --- | --- | --- |
| 安慰剂 | 合火与本火完全相同 | 并火 |
| 退步 | 合火被故意削弱一项本火能力 | 反噬 |
| 封顶 | 合火被故意限制，在吸收目标维上明显弱于原形 | 不及原形 |

原形适配还没有的时候，封顶这一只用替身：拿本火充当原形臂。它验的是判定与流程，不依赖真的原形。

### 9.4 与「体质改动行数为零」的关系

吸收架构级能力，包括改变吸收器自己怎么运行，不算改内核。吸收器是功法里的火，代码在引擎目录、驱动程序与提示词里，不在体质路径里。仓库里每个文件归且只归一个区，各有一条可以机械检查的线：

| 区 | 包含什么 | 一次炼化能不能动 | 人提的改动 |
| --- | --- | --- | --- |
| 体质 | `KERNEL_PATHS` 列出的路径：判官、起草的校验、事件账与归约器、执行层与闸门、看门狗、端点代理与钥匙环 | 不能，零行。这是生死线 | 走体质修炼，单独裁。不与量具同一个改动 |
| 量具 | `MEASURE_PATHS` 列出的路径，逐项见下 | 不能，零行。与体质并列的线「量具改动行数」，过了划线的炼档这一项非零即验体不过 | 单独提、单独裁。碰了量具的改动，体质与被量的路径改动零行 |
| 量具（可随引擎） | 量具里单独列出的四样，各写了理由，见下 | 不能，零行。它们仍然在量具表里 | 允许与被量的同一个改动 |
| 被量 | 这一轮跑起来的系统本身：引擎（吸收器自己在内）、功法清单与火清单、适配层、提示词、其余组件、组装脚本 | 能。验体的静态检查：经脉不越出席位的权能上限，依赖方向不反 | 不与量具同一个改动 |
| 其他 | 文档、界面、测试、各组件的说明与打包文件、仓库的配置 | 不受这两条线约束 | 不受约束 |

**「量具」只有一个定义：`paoding_fenjue.lianhua.MEASURE_PATHS` 这一张表。** 验体时数「量具改动行数」用它；CI 那条检查（`ci/check_liangju.py`）不另列一份，从同一个文件里读同一张表。两处认的是同一批路径。表里有：

- 引擎之外的量具（`liangju/`）：盲判三段与它的提示词、汇总、表项计数与它的初值，以后的试火台、归类器、题目生成器。
- 判定函数、炼化六步与这张表本身（`lianhua.py`），进化读数，炼化命令。
- 检验代码、Schema、各张表、验收夹具与录音、黄金日志、体质试炼的清单、体质对功法的两张表。
- **评测台**（`eval/`）。按设计第一篇它是药鼎的一部分：四臂对照的台子、读数与记录都出自它。
- **价表**（`adapter/config/prices.yaml`）。过线定义里「在预算内完成」按它折算，改价就改了哪些题次算完成。
- **留出份额的规则**（`shapes.py`）。它决定一道题落进哪条臂。同一个文件里还有功法摘要的算法，开题钉的、记录里记的都是它算的数，所以整个文件归量具。
- **守这条线的检查脚本自己**（`ci/check_liangju.py`）。改它按改量具来审，不能和引擎同一个改动；否则可以在同一个改动里先把检查改松、再改引擎。

**允许与被量的同一个改动的量具只有四样**（`MEASURE_WITH_ENGINE`），理由与路径写在同一张表里。不在里面的量具一律不许，检验代码与 Schema 就不在里面。

| 哪一样 | 为什么允许 |
| --- | --- |
| 验收夹具与录音 | 录音是引擎输入输出的逐字节记录。被录的行为一变就得在同一个改动里重录，分开提必有一个提交回放不过 |
| 黄金日志（焚决的与适配层的两处） | 事件账与适配层输出的逐字节记录，理由同上 |
| 引擎读的各张表 | 表是引擎读的参数，换读法的那个改动里要一起增删，分开提必有一个提交里引擎读不到表或表没人读。表的增长另有表项计数那条线管着，它的初值在 `liangju/` 里，不在这四样之内 |

这四样只有一个身份：它们是量具。一次炼化对它们照样是零行；只碰了它们的人提改动，CI 那条检查不启动；碰了其余任何一样量具的改动，CI 查体质与被量的路径改动零行，并且功法清单、火清单与提示词的摘要逐项相等。另有一条测试列出每个顶层目录与单独列出的文件各在哪一区，新添的东西没归类就红。

被吸收的做法如果需要下面任何一样，那一部分就不是吸收，按现有规矩拆出去走体质修炼，由 cz 单独裁：新的席位权能或新的事件种类与字段；新的出站规则，或让模型容器拿到真实密钥；预算的强制点从容器之外搬到容器之内；新的证据类别，或让叙述进入依据。

调查线在线内：它的每个动作都是驱动程序执行的固定模板的只读操作，范围是定版快照；不新增席位权能，不出站。它改变的「主模型不看原文」是算法设计里的一条防护，不在体质五项里，Z2 已定了新的落地方式。

本文提出的原形门、新结局、试火台、盲判、归类器、生成器、`jue` 的核对，全部落在量具里。它们是对量具的改动，单独提、单独裁，不属于任何一次炼化。吸收器改自己时多一层保护：这次试火里的 B 臂是上一版吸收器，试火台与盲判用的是这次炼化开始之前的版本。

### 10.3 分支怎么选

同模型对照之后，吸收器与参照智能体之间剩下的差距，才是架构该负责的部分。

- **差距大，走大分支**：方向二照现在的范围做。
- **差距小，走小分支**：方向一做完，调查线不再由人手工做，推后成为吸收器自己的第一次自炼。

选分支是 cz 的决定，读数出来就可以选，最迟在第 6 步开始之前。第 0 到第 5 步不受影响，可以先做。

建议的判别办法（P5，供参考，不约束 cz）：在同一个模型、同一批题上，用第 5 节的尺子，取「只有原形过」的题次数减「只有本火过」的题次数。这个差大于噪声底 m 就算差距大，不大于就算差距小。第 5 步中期试火如果跑了原形臂，会再给一次同样口径的读数，可以用来复核：那时比的是方向一的成品与原形，差距已经不大于 m 的话，即使先前选了大分支也值得重新考虑。

### 10.5 机器时间估算

算法：遍数等于题数乘臂数乘每题次数；机器时间等于遍数乘一遍的用时 t。钉住模型、去掉墙钟线之后的 t 还没有数，要等第 2 步之后实测，所以下表给两档假设：t 为 20 分钟与 40 分钟。公开材料里能参考的只有两个数：对照材料记载参照智能体三遍各用 17 到 21 分钟；现在的引擎有 8 分钟与 20 分钟两条时间线。表里的数都是估算。

**哪些可以并行。**

- 一次试火里的各个题次互相独立，全部可以并行。第 2 步之后墙钟不再决定内容，并行只影响用时读数，不影响结果。并行路数受两样限制：机器的内存与处理器，端点的限速。
- 同一台机器上并行起多个实例，要先合入同号租约互撞的那个修复（PR #157）。
- 盲判可以随每个题次跑完立即开始，不必等整批跑完。
- 题目生成按题并行。
- 第 3 步与第 4 步的开发工作可以与第 2 步之后那一轮本火重跑同时进行。

**哪些必须串行。**

- 一次试火内部的顺序：计划预登记，然后跑，然后盲判，然后归类，然后判定。归类按固定顺序逐条处理，是串行的，但只要几分钟。
- 步与步之间：每一步验收之后才开下一步。第 1 步必须在第 2 步之前，判定试火必须在它要判的那一步完成之后。
- 第 0 步起点轮：墙钟线还在，并行路数要固定，本火与同火对照交替排队（8.4）。路数取多少由 cz 按端点的限速定，取了就不要中途改。
- 判定试火在 cz 的机器上跑，受那一台机器的并行能力限制。

合计（不含盲判与按轮的成本实测）：共用的第 0 到第 5 步约 460 到 500 遍；大分支的第 6 到第 8 步约 540 遍，小分支约 440 遍。t 为 20 分钟、4 路并行时，每 100 遍约合 8 小时墙钟。

### 10.6 两点说明

- 调查线的成本必须先实测。它让高性能档的输入变多，现在没有实测数据。先在开发题上小范围跑，超出账就收紧上下文与轮数，账不动。
- 萃意与归位的观察改由调查线引用的区间来派读，可以排在调查线之后单独做，不在必经之路上。

## 13. 汇总数的字段清单

留出题的内容不进会话也不进仓库，回传的只有下面这些数。起点轮、中期旗帜、判定都用这一份格式。所有字段由程序从试火记录与发现记录生成，没有需要人填的栏。

### 13.1 批次头

- 批次号、日期、用途（起点轮、中期旗帜、判定，三选一）。
- 试火计划的哈希。起点轮没有计划时写「无」。
- 题集代号、题集摘要、题集来源（手出，或生成器的版本与种子）、题数、每条臂每道题跑的次数。
- 引擎的提交号与配置摘要、功法摘要。
- 盲判三段的版本、盲判用的模型、每题次的盲判时限、抽样量、归类器的版本。没有计划的批次，时限一栏写「无」。
- 并行路数、看门狗的时限。

### 13.2 逐臂登记

- 每条臂：模型名、版本标识、端点、采样参数、计量来源、价表版本。
- 运行记录里读回的模型标识是否与登记的一致。
- 不对等的项，逐项列出，没有就写「无」。
- 原形门的状态：可判，或未判及原因。

### 13.3 每条臂一组

对所有臂都有的字段：

- 臂名，以及它的功法摘要或原形的版本号。
- 过线的题次数；两次都过线的题数。
- 过线定义的三条各自满足的题次数：答到、属实、在预算内完成。
- 子问一级的计数：答到、部分答到、没答到。前提不成立且有证据的算答到，另外单列一个数。
- 抽样核对：抽了多少条，成立、被原文否定、找不到依据各多少条。
- 花费（按同一张价表折算）：合计、每题次中位数、每题次最大值。用量的四个数：新输入、命中缓存的输入、输出、调用次数。
- 用时：每题次中位数、每题次最大值。
- 没完成的题次数，按原因分：看门狗超时、超出预算、模型调用失败、读不进仓库、其他。

只有我们自己的臂才有的字段，只报告，不进门：

- 因时间线停下的题次数（第 2 步之前才有意义，之后应为零）。
- 工单：开出数、关闭数、申辩成立数、未解决数。工单回路上线之前写「不适用」。
- 各项检验的首次通过率。
- 引擎自己标为已核对的结论，被盲判抽样否定的比例。
- 引用落在定义体内的条数分布。

### 13.4 成对比较

每一对给出四个格子的题次数：两边都过、只有前者过、只有后者过、两边都没过。

- 本火对同火对照，并给出不一致数 d 与噪声底 m。
- 合火对原形、合火对本火、合火对异火单炼。
- 本火对原形（用来选分支）。

只填这一批里存在的那几对。起点轮只有第一对。

### 13.5 按轴分层

五条轴（语言、仓库大小、问法、前提是否成立、答案在代码还是在配置文档）各给一张过线计数表，每条臂一行。某一格少于 3 道题就并进「其他」，免得从数字反推出是哪道题。

### 13.6 发现与类别

- 这一批的发现记录数，按五种判定分。
- 每个类别一行：类别编号、出现的题数、出现在哪几条臂、是不是这一批才第一次出现。标签是可选的显示文字，不进计数。
- 累计数：类别总数、只出现过一次的类别数、发现总数、累计跑过的新题数。
- 归类器在这一批的金丝雀结果，以及它在换题重现集上的两个错误率。

起点轮时归类器还没有，这一节只填第一行；发现记录先存着，第 1 步的归类器就位后补算。

### 13.7 量具自检

- 盲判的三份金丝雀各自判对没有。
- 重判一致率。
- 导出的用量与服务商账单的对账差异（按臂）。

### 13.8 完整性

- 运行期间代码与配置是否改动过（应为否）。
- 这一批里转成开发题的数量，以及补进来的新题数量。
- 这套题集已经用于判定的次数。
- 复用了哪些臂的结果，来源批次号。

### 13.9 明确不包含

题面、子问清单、仓库名、文件路径、引用内容、回答原文、发现记录里的那句自由文字与证据指针、失败的原始输出，都不回传。某道题的失败细节一旦需要看，它就按 Z6 转成开发题并换一道新的。

## 14. 第 0 步的做法，以及它不改变引擎行为的证明

### 14.1 做法

1. **定模型。** 起点轮在 cz 指定的模型下跑，模型名与版本写进批次头。以后换了模型，起点轮在新模型下重跑，两批不混用。
2. **写三样只读工具。** 都放在引擎之外，都只读运行结束之后的导出：
   - 盲判：第 5 节的三段，包括回原文抽样核对。每个不利的判断写成一条发现记录。
   - 汇总：从盲判的产出与花费记录生成第 13 节的汇总数。
   - 表项计数：数引擎里的词表条目、正则、门槛常量、提示词里的硬规则。
3. **选题。** cz 那边准备一批新题（估算按 15 道），按 Z9 至少覆盖四种问法，并含一道引擎现在读不进的语言的题，沿五条轴分散。每道题附一份子问清单（5.2）。题目内容不进会话。
4. **跑。** 用现在部署着的引擎，原样不动，记下提交号与配置摘要。每道题跑本火与同火对照各 2 次。并行路数固定为 4（cz 2026-11-27），两条臂交替排队。**原形臂这一轮不跑**（N12），等原形适配的六条具备后，在同一批题、同一个模型下补跑。
5. **判。** 用盲判工具对每个题次判过线定义的三条。
6. **存发现记录。** 发现记录留在 cz 那边。这一轮不做归类，也没有人来起名；第 1 步的归类器就位后补算，得到新类别曲线的第一个点。
7. **数表项。** 留下初值。以后每一步拿它对比，表项只许减不许加。
8. **回传。** 按第 13 节的格式回传汇总数。它同时是炼档 002 照实判一次所需的读数（N8）。

起点轮用的新题按留出题的规矩对待：哪道题的失败细节被拿来指导修改，哪道题就转成开发题。

### 14.2 不改变引擎行为的证明

「不改变行为」分成六件可以逐项检查的事：

| 要证的事 | 怎么证 |
| --- | --- |
| 引擎、适配层、体质、提示词、表、Schema、夹具，这些路径一行没动 | 第 0 步的改动按路径清单检查，这些路径下的改动行数为零。清单写进 CI |
| 引擎用的提示词与表没变 | 功法摘要不变，火清单里各提示词的哈希不变。前后各取一次，逐项相等 |
| 引擎对同样的输入给出同样的输出 | 现有 14 份录音原样回放，全部通过，录音文件一个字节不动（Z5） |
| 新写的工具不会被引擎用到 | 依赖方向检查：引擎与适配层的代码不引用这三样工具所在的目录。工具只读运行结束之后的导出，不读运行中的状态，也不往运行里写任何东西。盲判自己的模型调用不经过引擎 |
| 量具现有的判法没变 | 检验代码不动（Z4）。盲判是新增的，不替换任何现有检验 |
| 汇总数对应的确实是没改过的引擎 | 每份汇总带提交号与配置摘要，与第 0 步开始前记下的一致 |

前五件在三样工具合入时由 CI 检查，第六件由回传的汇总自带。任何一件不成立，第 0 步就不算完成。

### 14.3 回退

第 0 步没有改动引擎，回退就是把三样工具删掉。汇总数与发现记录留在 cz 那边，不受影响。
