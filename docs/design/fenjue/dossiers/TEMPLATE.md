## 四、验体

### 4.1 体质改动行数：〈0〉

非 0 说明这次夹带了体质修炼，拆开另走变更表。

量具改动行数：〈0〉（检验、Schema、表、夹具、评测工具、判定函数）。量具的改动单独提、单独裁；自炼的炼档这一项非零，验体不过。

### 4.2 静态验体

`fenjue/tests/test_fenjue.py`：清单形状、经脉越界、依赖方向、体质内部不可达、领域词、入库四问、资产寻址。

### 4.3 动态验体

`uv run python tests/fenjue/trials.py`，以及换上本火的功法再跑一遍：`uv run python tests/fenjue/trials.py --gongfa 〈功法文件〉`。写结果与提交哈希。

**CI 核对什么**（`tests/fenjue/test_dossiers.py`）：七节齐全；命令生成的炼档 `.md` 与 JSON 一致；JSON 的必填键、状态与结局的取值；已裁决的有裁决人、日期、结局与品阶，且结局只能是火莲或合炼；不收或已散火的火不在功法里；功法里每一团不是本火的火都指向一份已裁决的炼档，档里的火与清单的 id、火位一致；品阶史里带档号的每一阶与那份档的裁决品阶一致；读数表里每一条的出处测试都还在。

**可选键**（12 §2.3、§2.4）：`group` 是火组的其余成员（每个 `{fire, replaces}`，跨火位、行为有变时一份炼档一起走）；`engine` 是方案分析导入时记下的结构化产物（`run`、`candidate`、`decided_by`、`artifacts` 四个 sha256、`essence` 全文、`placement_extra`、`readings_extra`、`provenance`），有它时 `.md` 第三节后多“冲突报告”“实现步骤”两小节，CI 另核第二节与 `engine.essence` 按 12 §2.2 渲染的一致。读数出处的测试从验体起才核（入位时实现线还没写）。
