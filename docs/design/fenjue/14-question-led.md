## 0. 结论

1. 第 1 版从头到尾没有用到题面：读哪里由八个火位的词面线索打分决定，读丹的问题是火位模板，报告是按候选排的表。
2. 第 2 版在固定流程里加五步、改两步：题面解析、领读、追读、答题稿、回头核对；识别候选换一版提示词并加一条
   “点名主题不许消失”的检查；提炼与归位只加并发。全部落在引擎（`fenjue/src/paoding_fenjue/engine/`）与驱动程序里。
3. 题面没有点名任何问题时（四个合成夹具的题面都是这样）走原路径：每一次模型调用的键与输入逐字节相同，现有录音
   原样回放。两条路径的报告第一行都写明走的是哪一条。
4. 体质路径（`KERNEL_PATHS`）、验证器 `engine/checks.py`、`engine/schemas/`、量具表 `engine/tables/`、夹具目录
   `fenjue/tests/engine_fixtures/` 零改动。没有放宽任何一条现有检验。
5. 预算总额、分步份额、端点代理的硬顶都不动。另加三条线（token、调用次数、时间），到线就停并照实交“没读到”
   “未核对”，不追加、不借份额。

## 3. 流程

走哪条路由确定的规则定，立项时定一次、记进簿记（`engine.json` 的 `ql`）：题面里有“怎么、如何、怎样、how”引出的
问句，且有一份代码或文档形态的外部材料，就按题读；否则走通用勘察。规则在 `wenti.questions`：按顿号、逗号、分号
切开，带问句标志的一段起一个子问（至多 4 个），从“有什么……值得我们……”起的收尾问不算子问。

| 步 | 做什么 | 模型 | 模块 |
| --- | --- | --- | --- |
| ① 题面解析 | 一次调用把每个子问换成中英文检索词（模型此刻看不到对方仓库）；引擎在路径、符号、标题、正文里检索。某个子问零命中时把各词的命中数交回再要一次词。再一次调用，让模型从**对方仓库里真实存在的名字与文件**里挑词（名字表是定界包裹的外部数据；挑中的必须逐字在表里，否则不收） | 轻量档 2 到 4 次 | `dati.ask_terms`、`dati.ask_pick`、`wenti.vocabulary`、`wenti.rank` |
| ② 领读 | 第一批是各子问排最前的文件，各子问轮流取。整文件读；超过 300 行的按顶层定义切成几部分，每部分附本文件的定义大纲 | 轻量档，并发 | `wenti.parts`、`dati.read_part` |
| ③ 追读 | 每批读完，引擎按“追的名字的定义处、用到它的地方、对应的测试、题面检索的底分”给没读过的部分打分，取最高的一批。停止：读满份数、连续两批没有新事实、没有可追的、到任何一条线。对方读了两批之后固定插一批我们自己的实现（有归档时） | 同上 | `wenti.Frontier`、`qled.read_phase` |
| ④ 通用勘察（缩小） | 每个火位至多读一段，同一文件同一火位读过的不重读。保住题面之外的候选 | 轻量档，至多 8 次 | `run._shihuo` |
| ⑤ 识别候选 | 新版提示词 `shihuo/v2`：异火榜只作参考，已登记不是不提名的理由；输入多一栏“子问与它的观察”。引擎检查每个有观察的子问都有候选或“已有不差”用到它的观察，否则带原因重问；三次仍没有，不算检验未过，但在给人的话里写明。按上限截取候选时，点名主题的候选不许被截掉。预评估自动取候选时先取点名的 | 高性能档，同第 1 版 | `shihuo.uncovered`、`shihuo._keep_asked`、`qled.pick` |
| ⑦ 答题稿 | 一次调用，只凭细事实回答每个子问、给集成建议、不建议的、拿不准的；每条引用细事实编号 | 高性能档 1 次，可重来 1 次 | `dati.draft` |
| ⑧ 回头核对 | 结论与它引用的原文（前后各多 3 行）交给另一个隔离的调用判“支持、部分、不支持”，6 条一批、并发；部分支持的改写一次再核一遍 | 标准档，按条数 | `dati.verify`、`dati.fix`、`qled.answer_phase` |
| ⑥ 提炼、归位 | 内容不改，候选之间并发 | 同第 1 版 | `run._cuiyi_units`、`run._ruwei` |

次序是 ①②③④⑤⑦⑧⑥。⑦⑧放在⑥之前：回答是这道题最要紧的交付，先保住它。

交付：人读报告第一行写走哪条路，接着是“回答”一节，然后才是原有的候选表或预评估表；与异火榜重复的候选在表后
旁注“已有登记 Y-00x”，不剔除。

## 4. 细事实：读回来要细到可逐条核对

第 1 版的观察按规定不带对方的任何名字，一段 60 行交回一两句概括，答不出具体的东西。第 2 版把阅读交回的东西分成
两套：

- **观察**：形状、检查、用途都不变（不带名字，供识别候选、提炼、归位用），只是出处的行区间收窄到模型指的那几行。
- **细事实**：答题用。一条只说一件可以对着原文核对的事：一个触发条件、一个阈值或缺省值（写出数值）、一个分支
  怎么走、一个不变量、处理的先后、做不到时的退路、一处有意的取舍或局限。可以也应该写出原文里的名字与数值。
  每条带行区间（至多 60 行，必须落在给它看的范围内）、它回答的子问、类别（机制、行为、文档声称、配置、测试规格）。

以“上下文压缩”一问为例，细事实的粒度应当说得出：触发分软硬两档、事件条数与 token 两个门槛各是多少、开头几条
不压、切点不拆原子单位、各缺省值、压不出来时的退路、摘要的输入是有损的。提示词（`adapter/prompts/tunshi-reader-q.md`）
按这个粒度写的要求。

引擎对每条细事实做确定的检查，不合格的单条丢掉并计数：行区间在范围内且不超过 60 行；子问编号与类别合法；不带
代码围栏；不是指令的口气；与原文的最长公共片段短于 12 个词元（与现有“不抄写”的门槛同一个数）。合格的记下所在
文件、行区间、该区间原文的 sha256、所在的定义名。

**隔离规则的出入（这一版与一页设计不同的地方）**：细事实带对方的名字，所以只给答题与核对两步看，留在工作区的
`facts.jsonl`，不登记成产物、不进识别候选、提炼、归位任何一步的输入。那三步的隔离规则与检验原样不变。

**对 token 线与输出上限的影响**：

| 项 | 第 1 版（片段阅读） | 第 2 版（按题阅读） |
| --- | --- | --- |
| 一次读多少 | 60 行，约 2 千 token 输入 | 至多 300 行，约 4 千到 6 千 token 输入（含提示词与大纲） |
| 一次交回多少 | 至多 5 条观察 | 至多 24 条细事实、5 条观察、12 个追的名字；可见输出约 3 千 token |
| 输出上限（含思考） | 8,000 | 16,000（可见输出加思考估到 9 千以内，留近一倍余量） |
| 被截断时 | 记为没读成 | 带着“上次被截断，只留最要紧的”重读，至多 2 次；次数记进报告与试算报告 |

基线里 48 次阅读合计入 94,381、出 108,327。第 2 版按题阅读至多 24 次（对方 20、我们自己 4），按每次入 5.5 千、
出 5 千估是约 25 万 token，落在“阅读至多占 token 线一半”（约 29.5 万）之内；通用勘察 8 次约 3.4 万。这些是估算，
实数由 cz 真跑后看 `ql.json` 与 `model_stats.json`。阅读份额一到就停止扩读，不挤后面各步。

## 5. 标注以回头核对的结果为准

答题稿里模型不写“确认”或“推断”，写了也不采用。每条结论最后的标注只取核对的结果：

| 核对结果 | 报告里 |
| --- | --- |
| 支持 | 留在回答里，标「确认」 |
| 部分支持 | 带着核对意见改写一次（只许删改、收窄，不许新增），再核一遍，按第二次的结果标；仍是部分支持的标「推断」并写明哪一处没有依据 |
| 不支持 | 不留在回答里，移到「拿不准的」并写明原因 |
| 没来得及核 | 标「未核对」，单列一节，写明不当事实用 |

核对的调用只看到结论的文字与它引用的原文，看不到答题稿别的部分。“不建议的”“拿不准的”本来就不当事实交，不核。

行号不由模型写：模型只引用细事实的编号，文件、行区间、所在定义名由引擎从细事实推出。答题稿里自己写了文件名加
行号的条目会被退回。所以带行号的引用按构造不会越界；读的时候行区间对不上的细事实在入库前已经丢掉并计数。

## 6. 各条线，不够时怎么交

不动的：整题预算、分步份额（识别 45%、提炼 35%、归位 20%）、预评估减半、端点代理硬顶、花费逐次留账。题面解析
与阅读记在识别这一步，答题与核对记在归位这一步。

另加的线（`qled.Limits`，〔占位〕，取自 cz 给的同题五次运行）：

| 线 | 值 | 出处 |
| --- | --- | --- |
| 整次运行的 token | 590,000 | 五次中位数 393,182 × 1.5 = 589,773 |
| 整次运行的调用次数 | 85 | 五次中位数 57 × 1.5 |
| 阅读占 token 线 | 至多一半 | |
| 对方仓库 / 我们自己 | 至多 20 部分 / 4 部分 | |
| 通用勘察 | 至多 8 次，每个火位一段 | |
| 留给后面各步的调用 | 26 次 | 识别 1–3、答题 1–2、核对与改写约 5、提炼与归位约 14 |
| 阅读的时间线 | 第 8 分钟后不再开新的一批 | |
| 核对的时间线 | 第 20 分钟后不再开新的一轮，剩下的标「未核对」 | |

**用时不作过线。** 过线看三样：题面的每一问都答了、现有检验照过、未核对的结论不超过两成。用时与调用量照实
记录，目标 30 分钟内。

任何一条线到了：停止扩读，排了队没读的部分原样列进「没读到的」（路径、行区间、为什么排它）；来不及核对的结论
标「未核对」单列；停在哪条线写进报告。不追加、不借下一步的份额、不超线。接着做时，从调用备忘里取回的调用也计
一次：偏保守，线只会早到。

并发：按题读的各步（阅读、通用勘察那一轮、核对、提炼、归位）同时发出的调用数是配置项 `analysis.parallel`（1 到 8，
缺省 4）。通用勘察的路径始终顺序执行。并发与顺序的结果相同（有测试）。

  程序数得出的几项。

## 8. 对合成夹具的影响

四个夹具的题面是“看看验收夹具甲里有什么值得我们集成的做法”，没有问句，走通用勘察：不多调一次模型，每次调用的
键与输入指纹不变。机械核对的办法就是现有 14 份录音原样回放（`Recorded` 按键加输入 sha256 核对，输入变了会报
“录音过期”）。夹具目录、`script.py`、录音文件一个字节不改。唯一看得见的变化是报告多了第一行（§7）。

按题读的测试（`fenjue/tests/test_engine_question_led.py`）换一句带问句的题面去读同一份组合夹具，模型由夹具目录
之外的脚本扮演。

## 9. 过线标准怎么核

| 标准 | 怎么核 |
| --- | --- |
| 同题三遍都答两问并给建议 | `ql.json` 的 `pass.all_answered`、`pass.has_recommendation`（只数核对过的结论） |
| 未核对的结论不超过两成 | `ql.json` 的 `stats.unverified_share`、`pass.unverified_within_20pct` |
| 核对通过率；另抽 10 条人工读 | `stats.verified_pass_share`；报告里每条结论后面就是文件与行，人工对着读 |
| 带行号的引用零越界、多数指向点名模块 | 行号由引擎推出；`stats.named_share`；读时丢掉的条数在 `read.dropped` |
| 调用数与 token 不超过 1.5 倍 | `ql.json` 的 `calls`、`tokens` 与上限；`model_stats.json` 是真的发出去的次数 |
| 现有检验通过、夹具不退步 | CI 全量；录音原样回放 |
| 验收用例甲、丙各一遍 | 两题题面都有“怎么”，走按题读；同样看上面几项 |

## 11. 入功法：第 2 版、留出、开关

- `h1.tunshi` 升到第 2 版，出身写明顶替的是它自己的上一版（`lineage.from = ["h1.tunshi"]`，记录 002）。
- **常设留出**（[09 §10](./09-engine.md#10-引擎自己的火位)）：`shapes.engine_variant` 推分析实例的功法时，把上一版
  `h1.tunshi@1` 放进 H1 的留出。留出份额（现在是 10%）的题拿到的形态是第 1 版，引擎见到第 1 版的形态就只走通用
  勘察、用第 1 版的提示词。用的是 F5 已有的留出机制，没有新机制。在跑的题锁在开题时的功法上，不受影响。
- **开关**：配置 `analysis.question_led`（缺省开）。关掉后一律走通用勘察，不用改代码就能退回去。
- **对照我们自己的实现**：配置 `analysis.own_repo` 写我们仓库的地址；立项单里出处是这个地址的来源（上传的归档用
  `--upload-origin <地址>@<提交>` 记出处）当作对照材料读，不当外部系统分析，不出观察，快照编号从 s91 起。提交号
  记在立项单与 `ql.json`。归档由 cz 真跑时准备，固定在引擎当时运行的同一提交；没有归档时只对照能力清单，报告
  写明“没有读我们自己的实现”。
- 记录 002 标自指，停在“设计已裁”：预登记的读数见该档第五节，过线读数由 cz 合并后在真系统上跑，裁决只由 cz 做。

## 12. 风险

1. **用时取决于上游输出速度。** 时间线到了就停并照实交，可能出现“答了但部分未核对”的一遍。
2. **细事实带名字**，是对“主模型不看对方名字”这条规则开的一个口子。口子只开给答题与核对两步，这两步的输出只进
   人读报告，不进任何后续步骤的输入；候选、提炼、归位仍然只看观察。
3. **夹带指令的原文**：按题阅读、挑词、核对三步的原文都在定界包裹里；注入探测照旧；指令口气的细事实被丢掉；
   “值得追的名字”只收在原文里逐字出现的标识符，只用于检索。
4. **题面规则判错**：有问句但其实没点名，会多花几次调用后因零命中写进「没读到」；点名了但没用问句，走通用
   勘察，等于第 1 版。规则与例子在测试里。
5. **调用次数的计数偏保守**：接着做时取备忘的调用也计数，被多次打断的题会早一些到线。
6. **阅读的 token 估算没有真数**：§4 的数是按基线比例估的，第一轮真跑之后按 `ql.json` 调 `Limits`。
