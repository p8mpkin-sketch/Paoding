# 庖丁核心创新与架构总览（项目名片 / 定盘星）

> 日期：2026-11-17｜性质：动工前的架构定盘文档｜同步到：[基座规格 v1.3](./base-layer-spec-v1.md)（与规格同一次合并）
> 存在的理由：**真正开始代码实现之前，程序的核心架构和设计决定了整个智能体项目的成败。** 这份文档让任何人在动工前（以及任何评审者、协作者、未来贡献者）在一页内看清：项目相信什么、骨架是什么、创新在哪、每件东西从哪来、还有什么没被证明。

## 1. 项目信条

**一句话：一条确定性事件日志做骨架，判官定真伪，模型只在缝隙处出场，器官随模型成熟逐步退位。**

| # | 信条 | 一句话表述 | 违反的后果 |
| --- | --- | --- | --- |
| 红线 1 | 写入路径无模型 | 共享状态的校验与应用是确定性纯函数 | 不可复现、不可审计、调度无法多实例 |
| 红线 2 | 反幻觉不变量 | 被信任的证据只能是执行层直接产出的内容寻址 Artifact；E3 的判定回路里永远没有模型 | 模型自述混入证据链，幻觉式成功 |
| 红线 3 | 领域不进内核 | 领域词只出现在锦囊与判官配置 | 内核长成某个领域的专用形状 |
| 红线 4 | 删简律 + 官知止律 | 每个结构回答"下一代模型会不会吃掉它"；官分三类：感知官带退役条款，守门官长存，量具只产生读数、不守门也不退役；只在规模上才需要的结构另声明启用条件（判别式：**它弥补的是模型的缺陷，还是世界的性质？它是要被相信，还是要被测量？**） | 结构僵化，被下一代模型整体淘汰 |
| 红线 5 | 诚实对照 | 赢不过"薄外壳 + 强模型"（瘦基线/等成本重试）就删 | 自欺：复杂度没有换来任何东西 |

三条主线（规格 §2）：**判据先行**（Goal、带判据的 Intent、观察类论断走同一条判定路径）· **结构自识**（画像、难度、能力全由题目推出，难度也是结构）· **自我删简**（每个 T-1 结构带开关、消融臂与归因账）。

## 2. 核心架构（骨架一张图）

```
基座 = 一条事件日志 + 确定性裁决器 + 四个插拔接口
       （判官 / Worker Adapter / 执行层 / Blob 存储）

 人 ──(open/hint/approve/裁决/验收)──▶ ┌──────────────────────────┐
   司南×N（无状态、不含模型）─────────▶│ 解牛图：事件日志+纯函数裁决  │
        │ 起会话                       │  ├─ 图与等级（派生，不存储） │
        ▼                              │  ├─ Artifact 登记（投影）    │
  Adapter（代理工具 exec/submit/show）──▶│  └─ 预算账本（投影）        │
   ├─ 模型容器：CLI，只有文件工具        └────────▲─────────────────┘
   └─ exec ──▶ 执行层（执行容器：授权编译、按风险配置能力、采集留证）
                       │                        ▲ 洁净重放
                       ▼                        │
                 Blob 仓库（sha256）      判官运行器（判官容器）
                                        哮天犬（纯脚本看门狗）
 ═════════ 题界：等级不出题，跨界只传封存摘录 ═════════
   题组 ⇄ 题 ⇄ 子题（各有独立日志）    通鉴日志（判例、Playbook、读数）
```

- **六契约，按三层表述**（规格 2.1 有逐条映射表）：信任根（Problem(TaskSpec)、Artifact 仓库、判官、执行层）、协调基质（解牛图即事件日志；预算是它上面的投影）、会话边界（Worker Adapter：双容器 + 三个代理工具，端点代理在容器外）。依赖单向：外壳依赖基质接口与代理工具，二者依赖信任根。
- **八条不变量**（规格 2.2，每条有强制点）：I1 写入路径无模型；I2 证据只认执行层产出；I3 等级不存储、不可写；I4 判据先于动手登记；I5 能力 ≤ Intent 风险 ≤ 授权；I6 预算硬顶在容器外；**I7 等级不出题；I8 估值不进等级**。
- **题界与封存**：日志按题独立，跨题只传可重放校验的只读摘录。题组、子题、判例、通鉴都建在这一个原语上。
- **机制（都在外壳）**：司南（调度 + 扇出规则表 + Hint 通道）、模型经济（分层路由 + 异构判定）、通鉴/锦囊（判例、Playbook、读数三类效力）、榷场（三级，降格为记账的分配算法）、闲人协议、子题与托管。
- **协调基质可插拔**：九操作接口（submit/adjudicate/snapshot/stable_dump/cas/query/settle/replay/history，映射表在规格附录 A）；M0 实现 = 事件日志（SQLite+reducer）；阡陌(git) 为规模化备选——基座不被任何一次基质押注绑架。榷场不再是备选基质：它是建在事件日志之上的分配算法，工人不知情。

## 4. 这套设计是怎么来的（方法论本身是资产）

```
两路独立调研（Claude 六场景 ∥ ZCode 攻防谱系）→ 交叉合并 v2（重叠区独立收敛）
→ 架构 v0（ZCode）→ 对抗评审七条（Claude）→ v0.1
→ 绿地对照运行（全新上下文、零预设）→ 核心三角再次独立收敛
→ 基座规格 v1.0/v1.1 + 可运行参考模型（Claude）→ A1–A10 异议
→ 人的裁决（全采纳 + 三补充 + 一项自我撤回）
→ 双轨典故深读（总纲 ∥ 逐句对账，第三次收敛）→ D1–D6 裁决
→ 总架构蓝图 v2（前沿展开）→ 独立评审 → 人的裁决（整体采纳，附 P1/P2 条件）
→ 人机界面设计 v1.1 → 评审与终审
→ 基座规格 v1.3（v1.2 并入；变更表 36 条，逐条可否决）+ 参考模型 88 测试
```

可复用的方法：**多模型交叉评审、绿地对照（fresh-context 控制实验）、人的裁决否决权、典故作为设计语料**。本项目每一步重大设计都至少经过两个独立上下文的推导或评审。蓝图 v2 对此有一条保留，照录：几次"独立收敛"用的是同一份证据浓缩与同一族模型，它说明结论对这些前提稳定，不说明前提为真；真正独立的检验仍然只有 M1 的四臂对照。
