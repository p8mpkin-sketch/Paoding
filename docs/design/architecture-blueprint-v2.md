## 0. 一页结论

1. **审计**：五条红线、七条立场全部维持。提出三处修正（F1 到 F3）和两条新不变量（I7 等级不出题、I8 估值不进等级），目的是让前沿设计不压坏已定盘的部分。
2. **一个原语贯穿全部前沿：题界与封存。** 日志按题独立，等级不跨题，跨题只传可校验的只读摘录。题组、子题、通鉴、判例都建在它上面。
3. **榷场的落点改了。** 千级并发先撞上的不是写入热点，而是每题一个 Reason 的互斥域和读图上限 [观点，M2 压测]。所以规模靠"题组、题、子题"三层展开，榷场在有判官、对象多的层上分配预算，题内仍用退化形态。榷场是记账的分配算法，不是激励机制：工人不知道它存在。
4. **通鉴的效力是建议，度量靠随机留出。** 判例是日志的确定性投影；Playbook 永远只是可读材料；每个锦囊以固定概率被留出，得到没有选择偏差的增益读数，退役与"由厚回薄"都由它驱动。
5. **三个新提案**（§3.6）：对照判据、常设留出、预测账。榷场建不建，由预测账的读数决定。
6. **第二场景选数学（Lean）。** 纸面走查的结论是内核零改动可接入，暴露的两处缝隙都在内核之外。

本文为内核新增的东西一共五处，集中列在 §5.2，其余全部是投影、判官配置、司南规则或外壳。

## 1. 定盘审计

### 1.1 方法

对每条约束问三件事。承重：拿掉它，哪条保证失效。出身：依据是实测、独立推导，还是共同前提。负载：任务 3 的前沿会不会把它压坏。

一条总的观察：名片所说的"三次独立推导收敛"，三次用的是同一份十一条证据浓缩和同一族模型，所以它说明"从这些前提出发结论稳定"，不说明前提是对的 [观点]。真正独立的检验只有 M1 的四臂对照。收敛是定盘的理由，不是正确的证据。

### 1.3 异议与修正

| 编号 | 被挑战项 | 替代方案 | 论证 | 迁移成本 |
| --- | --- | --- | --- | --- |
| F1 | 立场①：六契约平铺 | 按变化速率分三层表述（§2.2）：信任根、协调基质、会话边界；再立一个跨日志原语"题界与封存"（§2.4） | 三份文档说法不一，根子是把变化速率不同的东西排在一张表里。绿地运行与基质文档各自得到的"四契约加基质接口"与本表述相容。跨题引用是通鉴、子题、判例三处前沿的共同需求，不立原语就会各造一套 | 不改已有字段。内核增量是 `register_artifact` 的一条规则 |
| F2 | 基质文档 §3："价格机制天然无热点"，榷场是千级并发的调度答案 | 规模靠题组、题、子题三层展开；榷场只在有判官、可比对象多的层上分配预算（题组层、子题层），题内用退化形态 | ① 千个 Worker 的写入约 200 事件每秒（命令登记、用量、提交、续租合计），单写者加组提交在 10³ 量级 [假设 M2]。先撞上的是每题一个 Reason 的互斥域，和 400 节点的读图上限。决策单线程是多智能体有效形态的前提 [证据 S43][S44]，所以应当复制决策域，而不是在一个域里加调度。② 市场聚合的是分散的私有信息；同族模型读同一张图，私有信息很少，题内行情多半是同一个估计的回声 [观点]。③ 题组层的合约是"某题能否在期限内解出"：对象多、判官硬、席位的历史成绩可结算，流动性问题最小 | 无（尚未实现） |
| F3 | 红线 4：入库两问（感知官或守门官、退役信号） | 入库四问：加"启用条件"与"对照臂"。对照臂默认是该结构自己的退化形态 | 榷场与分片答不出"弥补模型缺陷还是世界性质"，它们弥补的是规模。没有启用条件，它们会在不需要的规模上常开，成为纯成本 | 退役条款表加两列 |

两条新不变量，是红线 1、2 在前沿上的延伸，不是异议：

- **I7 等级不出题。** 等级只在产生它的题内有效，因为它对应的是那道题的环境基线与判官。跨题只能传封存摘录，在接收方登记为 input 类材料；要在新题里得到等级，必须由新题的判官重新判定。唯一的例外是结构性的：父题可以用内建判官 `seal_check` 确认"某子题的终态封存有效且为 solved"，它检验的是日志的哈希链，不是内容。守门官，依据是世界的性质：环境各不相同。
- **I8 估值不进等级。** 报价、行情、预测概率、Hint、存活计数，一律不得出现在 `level()` 与 `gate()` 的输入里。它们只影响先做什么，不影响什么为真、什么可放行。参考模型加一条性质测试：任意改动估值类事件，等级与消费门逐例不变。守门官。

### 2.2 六契约的关系

| 层 | 契约 | 守的保证 | 什么时候才会变 |
| --- | --- | --- | --- |
| 信任根 | Problem | 判据先行；授权范围与风险；画像由它推出 | 发现新的独立画像轴 |
| | Artifact 仓库 | 出处类别；内容寻址 | 不变 |
| | 判官 | E3 与 X 的唯一来源，回路里没有模型 | 新领域只加配置 |
| | 执行层 | 能力不超过 Intent 风险，风险不超过授权；证据在容器外采集 | 威胁模型变化 |
| 协调基质 | 解牛图 | 写入无模型；等级为派生；租约与预算原子 | 换基质时整体替换，九操作接口不动 |
| 会话边界 | Worker Adapter | 模型对外只有三个代理工具；密钥与计量在容器外 | 换后端时重写绑定 |

依赖方向是单向的：外壳依赖基质接口与代理工具，二者依赖信任根；信任根不读外壳的任何状态。预算与行情是基质上的投影，不是契约。

### 2.3 八条不变量

I1 写入路径无模型。I2 证据只认执行层产出的可采信 Artifact，E3 与 X 只来自判定性判官的洁净重放或人的裁决。I3 等级不存储、不可写。I4 判据在动手前登记，之后不可改。I5 能力 ≤ Intent 风险 ≤ 授权范围，r2 的一次批准只管一次租约。I6 预算硬顶在容器之外执行。I7 等级不出题，I8 估值不进等级（均为新增，见 §1.3）。

前六条的强制点见规格；I7 的强制点是 `register_artifact` 的摘录规则与 `seal_check`，I8 的强制点是参考模型的性质测试。

### 2.4 题界与封存 [T-0，守门官]

```ts
type Seal    = { problem_id: string, head_seq: number, head_hash: string,   // 该题哈希链的链头
                 state_hash: string, reducer: string,                       // 状态哈希与 reducer 版本
                 terminal?: "solved"|"accepted"|"unsolved" }
type Excerpt = { seal: Seal, nodes: object[], supports: object[],           // 被摘录的节点与支持记录
                 blobs: string[] }                                          // 所引 Blob 的 sha256
```

1. 导出是日志的确定性投影（`history` 加 `snapshot`），不调用模型。校验方式是把来源日志重放到 `head_seq` 并比对 `state_hash`。
2. 接收题把摘录登记为 input 类 Artifact，登记方是接收题的图服务，先校验再追加。这是 `register_artifact` 新增的一条规则。
3. 摘录里的等级接收题不认（I7）；以它为 `grounds` 的观察仍要在本题重放判定。
4. 内建判官 `seal_check`（判定性，不含领域词）：核对一份终态封存的哈希链，终态为 solved，且子题 Goal 判据的哈希等于父题 Intent 登记的判据。
5. 封存可以被撤销：来源题的判官版本被撤销或人改判时追加 `seal_revoked`，订阅它的父题据此重算。r2 的 Intent 在申请租约时同步核对所依赖封存的最新状态，r0 与 r1 接受最终一致。

**题组**是没有 Reason、Intent 全部是子题委托的父题；它的 Goal 判官只做计分（`advisory`），由期限或人关闭。**子题**是由带 `delegate` 的 Intent 开出的独立 Problem：独立日志、独立 Reason、独立预算，深度上限为 2（§3.4）。

### 2.5 数据流

一题之内沿用规格 §2 的七步。跨题只有四条流：

1. 父题向子题划拨预算：父题追加 `escrow_out`，子题的 `open_problem` 引用它。
2. 子题关闭后给出终态封存；父题用 `seal_check` 判定，对应的 Intent 达成，余额以 `escrow_in` 回拨，幂等键是封存的哈希。
3. 任意题关闭时，判例投影写入通鉴日志；复盘任务产出 Playbook 候选。
4. 新题开题时，Adapter 按结构签名从通鉴取判例索引与锦囊，列进任务包第③段。

### 2.6 基质接口：九操作不增不减

| 前沿需求 | 落在哪个操作 |
| --- | --- |
| 报价、预测 | `submit`（都是提议） |
| 押注、托管划拨 | `cas`（租约预留加保证金锁定） |
| 行情、名额、判例索引 | `query` 的视图 |
| 合约结算与赔付 | `settle`（与判官裁决是同一个事件） |
| 封存与摘录 | `snapshot` 加 `history` |
| 子题校验、通鉴审计 | `replay` |
| 跨机一致的任务包前段 | `stable_dump` |

六项前沿都没有要求第十个操作，这是接口切对了的一个旁证 [观点]。

### 2.7 三机制的统一表述

- **司南是估值排序器。** 它的输入从"Reason 填的 `expected_gain`"推广为"行情"；没有他席报价时两者相同。
- **模型经济是预算在档位与家族之间的分配。** M2 用路由表配置；榷场的二级形态用席位资本学出来；席位只有一个时退回路由表。
- **通鉴与锦囊是跨题记忆。** 判例是记录，Playbook 是建议，读数驱动退役与由厚回薄。

## 3. 前沿设计

### 3.1 榷场：市场基质全规格

**定位。** 榷场是一个记账的分配算法：把"谁估得准"变成"谁的估值权重大"，把"谁花钱有产出"变成"谁拿到更多预算"。它不是激励机制。模型不会因为有赏金而更努力，告诉它有赏金反而可能诱发对判官的投机 [观点]。所以工人的任务包里没有行情、赏金、资本的任何信息；知道榷场存在的只有报价会话，它被要求的只是一个校准的概率。

**三级形态。** 每一级是下一级的退化形态，也是它的对照臂。

| 级 | 内容 | 启用条件 | 引入 |
| --- | --- | --- | --- |
| 零级：估值排序 | 行情等于先验，即 Reason 的 `expected_gain` 或通鉴里同签名的基础解出率；名额按八仙规则表 | 默认 | M2 |
| 一级：盲报行情 | 多个席位盲报概率，按家族聚合后取加权中位，向先验收缩；名额按边际期望值排序；预算仍从公共池出 | 该层家族数 ≥ 2，且（席位、合约）的可行组合数 ≥ 2 × 可用名额 | M4，先在题组层 |
| 二级：席位资本 | 席位持有资本，押注即出资，按公平赔率赔付，罚没"折" | 并发 ≥ 50，且一级的行情读数为正 | M5 |

```ts
type Contract = {                  // 只有带判据的对象可成约：无判据不成约
  id: string
  target: string                   // 带判据的 Intent | "goal" | 观察类论断 | 子题
  oracle: Check                    // 照抄 target 已登记的判据，不可另设
  settlement_tier: "decisive"|"consistent"      // 取自判官 grade；consistent 的赔付减半
  side: "achieve"|"assert"         // 待达成（Intent、Goal、子题）| 断言（观察）
  deadline: { budget_mark?: number, seq?: number, wall_s?: number }
  cap: number                      // 奖池对该合约的赔付上限，share × 开约时的奖池
  vest: number                     // 结算即付的比例；余下在"解出且在解题链上"时付清
  state: "open"|"frozen"|"pass"|"fail"|"void"   // frozen：target 带 knot
}
type Desk = {                      // 席位：估值与出资的记账单位。由配置登记，模型不能自建
  id: string; family: string; tier: "strong"|"mid"|"cheap"
  strategy: ArtifactId             // 提示词与锦囊组合的哈希
  weight: number                   // 估值权重，按结算更新
  gamma: number                    // 能力指数：该席位的通过概率估为 π^gamma
  capital: number }                // 二级才有；席位之间不可转让
type Quote = { desk: string, contract: string, round: number
               p: number           // P(期限内判官给出 pass | 强档做一次完整尝试)
               p_goal_given?: number   // P(上层目标终将达成 | 本合约 pass)，仅 achieve 类
               cost: number }      // 估计一次尝试的花费
type Stake = { desk: string, contract: string, lease: string
               reserve: number     // 即租约预留额，从席位资本划出
               bond: number }      // 履约保证金，β × reserve
```

规则：

1. **成约。** 带判据的对象出现时，图服务自动开出合约。没有判据的东西不成约：想得到注意力，先登记判据。
2. **盲报。** 每轮由"成批出现新合约、有合约结算、预算标记"触发并防抖。每个席位用一次廉价档的批量调用给一批合约报价。报价会话的 `context_manifest` 里不得有本轮他席的报价与行情视图，否则报价被拒，与 `independent` 是同一机制。
3. **定价。** 先在家族内取中位，再跨家族按权重取中位，得 m。n 为报价的家族数，κ 默认 2：`π(c) = (n·m + κ·prior) ÷ (n + κ)`。没有报价时 π 等于先验，名额规则退回八仙规则表，这就是司南。退化是逐合约、连续的，不需要全局切换。
4. **权重。** 合约结算后，每个席位的权重乘以它报给实际结果的概率（pass 乘 p，fail 乘 1−p），再归一；作废的合约不更新。这是专家混合的贝叶斯更新，有遗憾界 [证据：在线学习的经典结论，不在调研编号内]。权重按（席位、结构签名）存入通鉴，作新题的初值。
5. **名额，即注意力等于期望值排序。** 席位 d 做合约 c 的通过概率估为 `π(c)^γ_d`。γ 是能力指数，强档为 1，按历史结算做单参数拟合，初值取档位（中档 1.5、廉价档 3，[假设 M4]）。对每个（合约 c、第 k 个名额、席位 d）算边际值：
   `ρ = share(c) × π(c)^γ_d × ∏(1 − 前 k−1 个名额持有者的通过概率) ÷ cost_d(c)`
   全体按 ρ 降序，在并发上限与席位资本之内贪心填充。k ≥ 2 的名额必须给不同家族或不同策略的席位；席位不重押自己失败过的合约。`share` 在题组层是开题时给的分值，在子题层取条件报价之差 `p_goal_given − π(上层目标)`。高 π 的合约，第二个名额几乎不值钱；低 π 而分值高的合约会得到多个名额。这就是"价格即扇出控制器"，启用后取代 `race_k`。对象带 knot 时合约为 `frozen`，名额为 0，直到它的观察合约结算：D1 先于价格。
6. **押注与赔付（二级）。** 押注就是租约，另锁 `bond`，β 默认 10%。
   - pass：赔付 = `min(实际花费 ÷ π(c)^γ_d, cap)`，由奖池付给完成它的席位。这是按"市场对该席位的估计"给的公平赔率：做得比估计好的席位资本增长，反之缩水。
   - fail：花掉的已经花掉，未花的 `reserve` 与 `bond` 退回。
   - 折，即 D2 折损账里可归责于会话的四类（`no_output`、`stalled`、`reject_loop`、`scope_violation`）：`bond` 罚没。**保证金罚的是折，不是败。** 罚没款的去向：对象带 knot 时注入它的观察合约的 cap，否则回奖池，不加到原合约上（理由见决策日志）。
   - 守恒：席位资本之和 + 奖池 + 已花费 = 预算上限，逐事件成立。硬顶仍由端点代理执行（I6），榷场出错的最坏后果是分得差，不会超支。
   - 单个席位的资本不超过总额的一半，超出部分回奖池。种子资本一半均分，一半按通鉴里的权重分。
7. **结算信任根。** 合约只随判官裁决结算。achieve 类到期未过为 fail；assert 类 E3 为 pass、X 为 fail、到期为 void。行情不进等级与消费门（I8）。

**与事件日志的关系。** 不设第二条流。`quote_batch`、`round_close`、`stake`、`payout`、`forfeit` 是同一条按题日志里的事件，行情是第四个投影。合约与图节点一一对应，结算与等级变化由同一个 `judge_verdict` 触发，所以不存在"订单簿怎样投影回解牛图"的问题：没有第二份真相。报价按席位按轮成批写入，一道题约 10² 条事件。资格由图服务校验（资本够、名额未满、未冻结），先后仍由司南用纯函数排。

**防失真。** 规则 2、3、7 之外还有四条：同族席位再多也只算一票；席位由配置登记，没有女巫问题；Reason 不持有资本，它的 `expected_gain` 只作先验；子题层赔付分两段。最近 W 个已结算合约上行情的 Brier 分不优于先验时，该签名自动退回零级。

### 3.2 通鉴与锦囊全设计

**三类记录，三种效力。**

| 记录 | 怎么来 | 效力 | 官 |
| --- | --- | --- | --- |
| 判例 | 关题时由日志确定性投影，不调用模型 | 事实记录：发生过什么 | 守门官 [T-0]，审计的延伸 |
| Playbook 与锦囊 | 复盘会话蒸馏，人审，签名 | 建议：可读材料，永不作前提（I7） | 感知官 [T-1] |
| 读数 | 判例上的统计 | 驱动退役、由厚回薄、席位初值 | 守门官 [T-0] |

```ts
type Signature = { profile: Profile, judges: string[], resources: string[], tags: string[] }
                 // tags：开题人给的不透明字符串。签名只存在于通鉴，内核不解释
type Case = { id: string, seal: Seal, sig: Signature, model_epoch: string,   // 主力模型的家族与版本
  terminal: "solved"|"accepted"|"unsolved", path: "thin"|"thick"|"none",
  cuts: { title: string, judge_id: string, on_chain: boolean, attempts: number, knot: boolean }[],
        // 切口骨架：本题带判据的 Intent 序列，即"这类牛的关节图"
  excluded: string[],                         // 已排除路径
  attribution: Attribution, wear: object }    // 规格 8.4 的归因行与 D2 的折损账
type Playbook = { id: string, sig: Signature, applies_when: string, status: "proposed"|"published"|"retired",
  steps: { text: string,
           cites: { case: string, fact: string, check_hash: string }[],   // 引用的是判据，不是标题
           commands?: string[] }[],           // 步骤中的命令
  kit?: { name: string, hash: string, signature: string } }
type KitStats = { kit: string, sig_key: string, model_epoch: string,
  shown:    { n: number, solved: number, cost: number },
  withheld: { n: number, solved: number, cost: number } }
```

管线：

1. **封存。** 关题即追加 `case_sealed`。它是纯投影，M3 起对每道题自动做，成本为零。
2. **蒸馏。** 复盘任务在没有 `exec`、没有网络的会话里只读封存日志，产出 Playbook 候选。
3. **发布检查**（确定性）：每一步的 `cites` 非空，被引论断在来源题里是 E3 且在解题链上；`commands` 里的每条命令必须逐字出现在被引 exec 类 Artifact 的 `command` 字段里；正文不含外部链接。
4. **人审与签名。** 审批卡片展示被引的判据与判官输出，不展示标题（沿用规格 5.2 场景 2 的做法）。
5. **取用。** 开题时 Adapter 先按签名做结构匹配（判官、资源种类、tags 的集合包含），再用题面对判例标题做词法排序（BM25，确定性），取前 5 个判例和匹配的锦囊，只把元数据列进任务包第③段。下钻哪一条由模型自己决定。
6. **随机留出。** 每个匹配的锦囊以概率 ε（默认 10%）不进索引，记 `kit_withheld`。随机数由题目 id 与锦囊哈希导出，可重放。
7. **退役。** 增益 = shown 的解出率 − withheld 的解出率，另看每解成本之差。withheld 满 8 题且增益的 90% 置信上界小于 0，标为待退役，由人确认。`model_epoch` 变化时读数另起一行重新累计，留出率临时升到 30%：换代之后每个锦囊都要重新挣得位置。

**判例检索与类比。** 类比的对象是切口，不是文本。同签名判例的 `cuts` 给 Reason 一份分解先验：这类题上次是沿哪几个判据切开的，哪几刀碰了骨头。它直接作用于 D3 的切口命中率。跨签名的判例只给 free-form 闲人读（§3.3），用来做跨界联想。

**由厚回薄的驱动规则。** 对每个签名键，看最近 n ≥ 10 道题：厚路径独占解出数为 0，且薄路径解出率不低于 70%，则建议把该签名的 `bootstrap_share` 调为 1，由人确认。调整之后仍留 ε 的题走完整路径当回归哨兵；哨兵里厚路径独占解出累计 2 题，自动恢复并告警。判例还会加强薄路径本身：Bootstrap 读到切口先验后更容易一次解出，记忆加模型逐步取代编队。

**复利的度量。** 学习曲线：同一签名下第 k 题的每解成本对 k 作图。M4 的出口条件：第 6 到 10 题的每解成本比第 1 到 5 题下降不少于 20%，并且留出组没有同样的下降，以排除"题变容易了"和"模型自己变强了"两种解释。

决策日志：

| 议题 | 选定 | 被否方案 | 理由 |
| --- | --- | --- | --- |
| 检索 | 结构签名、词法排序、渐进披露 | 向量库与嵌入相似度；专门的检索智能体 | 可审计、可重放；纯文件记忆胜过专用记忆系统 [证据 Z21]；锦囊已是渐进披露 [证据 S42] |

### 3.3 闲人生态全设计

按裁决 A8，写支持记录的复审属于 Verify 角色，由消费门按需触发。闲人只有两种：**falsifier** 是供给侧的验证，在论断被消费之前先攻击它；**free-form** 是停滞时的多样性注入。二者都是感知官 [T-1]，补的是锚定与过早收敛 [证据 S28]。

`/work` 新增两条派生规则，都由事件触发，不用定时器：

```
attack(f) := level(f) ≠ X ∧ load(f) ≥ L ∧ fragile(f) ∧ (f, 证据版本) 尚未被攻击 ∧ 闲人池未超
   load(f)    := 以 f 为前提（含传递）的未终态 Intent 数；f 在待提交的 Goal 候选的解题链上时取最大
   fragile(f) := level(f) < E3 ∨ f 的判据出自模型撰写的脚本且没有对照（§3.6 N1）
   knot 联动  := Intent 带 knot 时，它的前提按 load 降序优先入队：一刀下不去，先怀疑前提
wander    := 停滞信号之一成立：处于预算复盘期 | open 的 Intent 全部带 knot |
             自上次判官确认的进展以来花费 ≥ 15% 题预算；每个信号至多派一个
```

| 项 | falsifier | free-form |
| --- | --- | --- |
| 任务包 | 目标论断的证据层与前提链；不含提出者会话的推理正文 | 题面、已排除路径的标题、判例索引（含异类签名）；**不含**活跃假设的摘要层，避免被现有思路锚定 |
| 可提交 | 引用可采信 Artifact 的反证；带 `check` 的观察类论断（`grounds` 引已有的可采信 Artifact，由判官重放） | 不带支持的猜想，每任务至多 3 条 |
| 执行能力 | 不挂 `exec`。要新证据就写判据，由判官在洁净容器里跑，只限 r0，花费计入验证池 | 无 |
| 漫游范围 | 本图 | 本图标题层与通鉴。外部语料不开放：它是注入面，评测中也关闭联网 |
| 模型 | 家族必须不同于目标论断的提出者；没有可用的异家族时不派 | 廉价档，优先异家族 |
| 预算 | 两者合计不超过题预算 10%，falsifier 6%、free-form 4% | 同左 |

采证要求不变：模型反证只产生争议，X 只来自判定性判官或人。falsifier 以 `nothing` 结束时，图服务给目标记一次存活；`attack_survived` 是派生计数，只用于不再重复攻击和写进报告，不影响等级（I8）。

防添乱的六条约束：操作白名单由图服务按租约角色强制，闲人不能加 Intent；每任务写入配额；去重键（节点、证据版本）；每个节点至多一条未决反证，反证被驳回后该节点对闲人关闭，直到证据版本变化；针对 E3 的反证只触发一次带冷却的重跑（规格 3.1.3）；**吸收率自限**：吸收率 = (被 Reason 用作前提的猜想 + 成立的反证) ÷ 闲人任务数，最近 10 个任务低于 10% 时节奏减半，连续两次减半则本题停派。

消融：`idlers=off|falsifier|freeform|both`，只跑中、难两段。读数：falsifier 在节点被消费之前促成的证伪数，以及因此释放的预留额（归因表的 `pruned`）；free-form 猜想的在链率；E3 观察的"标题超出谓词"审计比例在有无 falsifier 时的差。证伪线沿用规格 8.4：贡献率低于 10% 而成本占比高于 5% 即为待删候选。退役信号：反证成立率趋近于 0，或 Verify 路径已能拦下同一批错误。

决策日志：触发方式在"定时"与"事件派生"之间选后者，否则闲人在顺利的题上也花钱；falsifier 是否挂 `exec` 选否，保住"提出质疑的会话不持刀"，证据仍由判官产出；漫游范围在"本图、通鉴、外部语料"中选前两者。

### 3.4 多节点与分布

**分区单位是题，不是节点区间。** 规格的哈希链已经按题独立，所以"一题一个写者、一机多题"不需要新机制。新问题只有一个：单题上千个 Worker。F2 的论证是，此时该复制的是决策域。

```ts
type Delegate = { goal: Check,                  // 子题的 Goal 判据，即本 Intent 的 done
                  scope: Problem["scope"],      // 必须是父题范围的子集，逐条确定性比对
                  escrow: Budget,               // 从父题预算划出
                  env: Problem["env"] }
// add_intent{ …, done: { judge_id: "seal_check" }, delegate } → 父题 escrow_out → 子题 open_problem{ parent, escrow_ref }
```

- **子题是一道完整的题**：独立日志、独立写者、独立 Reason、独立画像。父题只看见三件事：子题开出、终态封存、余额回拨。子题拿不到父题的节点等级，只拿到作为 input 材料的摘录。
- **为什么这不是多智能体的交接失配** [证据 Z32]：父子之间的接口是一条事先登记的判据和一份可校验的封存，没有自然语言的交接语义。可能出的错只有"子目标切错了"，它会显示为父题的切口命中率（D3）偏低。
- **跨日志一致性只有三处**，都不需要分布式事务。托管：钱要么在父题账上记为已划出，要么已凭封存回拨，回拨以封存哈希幂等。失效上传：`seal_revoked` 由父题订阅，最终一致；r2 之前同步核对。硬顶：子题的任务令牌由子题预算派生，各子题预算之和受托管约束。
- **单写者的容量** [假设 M2 压测]：组提交下 10³ 事件每秒量级；等级按批重算，每 50 毫秒或每 100 个事件一次。高可用用同步副本，故障时提升副本并重放，正确性来自"落盘后应答加幂等键"，不引入共识协议。读扩展靠只读副本订阅事件流，以 `as_of_seq` 保证读一致。
- **Blob**：对象存储，键为 sha256，只写一次；元数据仍是日志事件。采集器用范围受限的凭据直传，凭据不进容器。内容寻址使跨区域复制没有一致性问题；回收的根集合是全部题日志与通鉴封存所引的哈希。
- **端点代理到模型网关**：网关无共享状态，一个任务的会话按令牌哈希粘在一个实例上，计量在本地精确完成，再以 `cost` 事件写回该题日志；不用分布式计数器。实例崩溃则该任务的请求失败、租约过期，失败是关闭方向的。多厂商路由与回退在网关内，家族标签仍取自路由表。
- **跨机的 `stable_dump` 一致性**：任务包前段对同一 `as_of_seq` 必须逐字节相同。四项保证：规范序列化（规格已定）；快照记录里带 reducer 版本哈希，版本不同的副本拒绝出包；写者每 N 个事件追加一次 `dump_mark{seq, listing_hash}`，副本出包前比对，不一致即告警并回落到写者；持续集成里加"两个副本、随机日志、字节相等"的黄金测试。

决策日志：

| 议题 | 选定 | 被否方案 | 理由 |
| --- | --- | --- | --- |
| 单图的水平扩展 | 按题分区，大题拆子题 | 按节点范围分片的多写者；共识复制的单写者扛吞吐 | 最小不动点要全局视图，跨片的边会让等级函数变成分布式算法，丢掉"百行纯函数"。吞吐本来就不是瓶颈 |

官的声明：子题与托管是感知官 [T-1]，补的是单个规划会话管不了那么大的图。启用条件：单题 open 的 Intent 数持续超过 Reason 一轮能处理的量，或并发超过 10。退役信号：单个 Reason 能管理的并发翻倍而切口命中率不降。对象存储、网关粘性、`dump_mark` 是守门官 [T-0]。成本：无模型成本，每个子题多一次开题与一次封存，毫秒级。

### 3.5 第二场景接入蓝图：数学（Lean）

选数学而不选运维：规格 6.2 已走查过运维；数学是完全信息范式，与 M0 的 CTF 相对；Lean 内核是最硬的判官 [证据 S24]，红线 3 的终审应当在判官最不含糊的地方做。

**判官配置**（领域词只出现在这里与锦囊里）：

```yaml
id: lean_check          version: "1"
kind: deterministic     grade: decisive
applies_to: [goal, intent, observation]
runner: { type: container, image: "lean-pinned@sha256:…", cmd: "judge/lean_check.sh", base: lean-pinned }
timeout_s: 900          auto: false            # 编译以分钟计，按消费与 claim_done 触发
flake: { reruns: 0, require: all }             # 编译是确定的；超时记为无结论
params:
  assemble: statement_from_spec    # 命题取自已登记的 spec，候选只提供证明体
  axioms_allow: [propext, Classical.choice, Quot.sound]
  forbid: [sorry, native_decide, unsafe, implemented_by]
  kernel_recheck: true             # 编译产物再由独立的内核检查器复核
  feedback: full                   # 命题无秘密，报错全文返回；不需要 vault
```

判官做四件事：把登记过的命题与候选的证明体组装成文件，候选改不了命题；编译；检查主定理所依赖的公理集在允许表之内（用了 `sorry` 或 `native_decide` 都会在这里露出来）；用独立的内核检查器复核编译产物 [待核：具体工具与其覆盖面在 M3 核对]。

**资源插件。** 没有外部资源，只用内建的 `workspace` 种类（C1），画像推出 `{complete, costly, r0}`。完整版提供两个类型化只读工具：库内定理检索、取某一位置的证明目标。

**锦囊 `lean-proving`。** 声明 `applies_to.judges: [lean_check]`，按结构匹配自动列入。内容是工程约定、读报错的方法、常用策略、如何把目标抽成独立引理。

**映射。** 引理是带判据的 Intent，判据就是引理的形式陈述；这里的 E3 确实等于"该陈述可证"，标题超出谓词的缺口最小。骨架检查是一条带判据的 Intent：在允许若干引理留空的条件下主定理通过编译（`expect.allow_sorry_in`）。引理为假时，反例是一条观察类论断，判据是对否命题的证明。

**走查。** 题 T：人提供形式命题文件，主定理体留空，登记为 input 类 a_1。Goal 判据为 `{lean_check, spec_ref: a_1}`，题预算 11.5 美元。

### 3.6 新创新提案

三个提案都过三问：会不会被下一代模型吃掉、破不破红线、在哪个里程碑怎样被证伪。

**N1 对照判据 [T-0，守门官]。** 现有的三个洞出自同一个原因：恒真的谓词也能到 E3。它们是空谓词与标题夸大（规格 5.2 场景 2）、续期门被琐碎观察满足（规格 §10 第 6 条）、榷场的刷单。提案是给判据加一个负对照：同一份规格，换一组输入，结果必须相反。

```ts
type Check = { judge_id: string, spec_ref?: ArtifactId, expect?: object,
               control?: { inputs: ArtifactId[] | object } }    // 同规格、异输入；判官要求它不通过
```

判官在两个洁净容器里各跑一次，主运行通过且对照不通过才给 pass，支持记录带 `controlled`。因为规格相同，直接打印常量或恒真的脚本过不了对照。用途有四处：续期门的进展只认有对照的观察或达成的带判据 Intent；r2 的前提要求有对照或人的豁免；榷场的断言类合约只对有对照者赔付；闲人的 `fragile()` 读它。局限要说清：对照输入由提出者选，它证明的是"结果依赖输入"，不是"标题为真"。
三问：不会被吃掉，不会失败的检验什么也证明不了，这是世界的性质；它收紧红线 2；M1 抽样审计恒真谓词与标题夸大的比例，有对照与无对照的 E3 论断若没有差别，就删掉。成本是判官多跑一次，不耗 token。

**N2 常设留出 [T-0，守门官]。** 官知止审计现在靠里程碑上的专门消融，贵而且稀。提案是每个感知官常年带一个留出率 ε：开题时以 `hash(题目 id, 官名) < ε` 决定本题是否关掉它，结果写进开题事件，可重放。归因表旁边因此长出每个官的增益及其置信区间，退役距离成为在线读数。§3.2 的锦囊留出是它的一个实例。约束：守门官永不留出；含 r2 规则的题不参加；ε 默认 10%。同一原则用于评测本身：G1 到 G3 的阈值和本文每一条证伪线，以 input 类 Artifact 的哈希写进评测题组的开题事件，改阈值就得开新题组，"不许赛后移动球门"由此变成机械保证。
三问：模型越换代，它越有用；随机数是确定性的，不破红线 1；M2 到 M4 核对留出读数与专门消融的结论是否一致，不一致则只保留专门消融。成本是 ε 乘以该官的真实增益。

**N3 预测账 [T-0，度量]。** 每个会话领到任务后的第一次 `submit` 必须带一行预测 `forecast{p, cost}`：本任务目标被判官确认的概率与预计花费。Reason 的 `expected_gain` 同样入账。只有带判据的对象参与结算，无判据不结算。投影出每个（家族、角色、签名）的校准曲线与 Brier 分。四个用途：按校准收缩 `expected_gain`；早停，校准后的"余下预算内解出的概率"低于阈值时题目进入 human 项，把"知道自己不会" [证据 S23] 做成续期门的预测版；作为榷场一级形态的启用与退役判据；作为模型换代时元认知变化的读数，供官知止审计使用。
三问：它是量具，模型变强只会让读数变好；预测不进等级（I8）；M1 即可验证，若各角色的 Brier 分都不优于"永远报基础率"，说明自报概率不可用，榷场的一级形态不必建。成本是每个任务约 20 个 token。

## 4. 压力预检

影响与概率各按 1 到 5 打分 [观点]。

| 3 | 通鉴污染与漂移：错误、过时或被注入的 Playbook 跨题放大 | 5 | 3 | 15 | 见下 |
| 4 | 闲人同源互证与争议淹没：falsifier 与提出者有同样的盲区，或用争议拖住 r1 的消费 | 3 | 4 | 12 | 异家族为硬要求；每节点一条未决反证；吸收率自限；争议不阻塞 r0（§3.3） |

**场景 1：行情回声。**
- 结构：盲报；家族内先聚合；向先验收缩，报价的家族越少越接近司南。
- 探测与退回：滚动比较行情与先验的 Brier 分，不优即逐签名退回零级；跨家族离散度接近 0 而结算屡屡相反时 κ 加倍。N2 的留出让一部分题常年跑 `market=off`，行情的增益是在线读数。
- 兜底：行情不进等级（I8），错的行情造不出假的达成；knot 冻结先于名额；`quote_share` 封顶 3%。
- 残余：所有家族共享同一个误解时，行情会一致地错。损失是预算分得差，上界是该题组的预算。

**场景 2：判据通胀与刷单。**
- 成因：本文把"带判据"变成了得到注意力、进展和赔付的条件，造判据有了回报。
- 对策：对照判据（N1）挡住恒真谓词；赔付的后一段要求在解题链上；子题层的分值来自他席的条件报价；Intent 配额不变；Reason 不持有资本，工人不知情。
- 探测：切口命中率里"达成但不在链上"的比例（D3）是通胀的直接读数，超过 50% 时续期门的进展谓词收紧为只认在链的达成。
- 残余：有对照、在链、贡献却很小的判据。它们浪费判官算力，不耗 token，也造不出假的 Goal 达成。

**场景 3：通鉴污染与漂移。**
- 入口：来源只限本项目的封存日志；每步引用在链的 E3，命令逐字出自被引的 exec 记录；蒸馏会话没有 `exec` 与网络；人审看判据。
- 效力：Playbook 只是可读材料（I7），最多误导探索方向，由它产生的论断仍要在新题里过判官。
- 漂移：随机留出给出无偏的增益；换代时读数另计、留出率升高；由厚回薄留有回归哨兵。
- 止损：增益的置信上界小于 0 即待退役；发现注入时按锦囊哈希撤回，日志里的 `kit_loaded` 列出全部受影响的题。
- 残余：看似合理、实际略差的做法只能靠成本读数慢慢显形，所以留出读数同时看解出率与每解成本。
