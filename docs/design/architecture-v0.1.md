# 庖丁架构设计 v0.1

> 状态：历史桥接文档（2026-11-17 归档）｜本版 = [v0](./architecture-v0.md) + 七条外部评审修订的落实稿
> **后续演化已取代本文**：绿地对照（[greenfield-base-run.md](./greenfield-base-run.md)）、协调基质（[coordination-substrates.md](./coordination-substrates.md)）、**基座规格 [base-layer-spec-v1.md]（当前权威）**。与规格冲突处一律以规格为准；差异清单见规格开放问题 10 与裁决书。

## v0 → v0.1 变更（对应评审七条）

1. **两范式拆为三根独立的轴**：信息完整度→生长规则；判官类型→证据梯可达上限；可逆性→审批门。三者不同步变化（CTF 信息不完全却判官最硬；数学信息完全判官却贵）。
2. **E3d（延迟证据）单独设级**，不再与 E3 混用；执行链与 proves 边只认真 E3。运维"指标恢复≠根因修复"显式建模：症状压制类判据须配守护项。
3. **唯一写入者是确定性图服务**（代码强制 schema、晋级规则、传播规则），司南与所有 Worker 一样只提交提议——写入路径过模型既不可复现也是瓶颈；司南因此可多实例。
4. **验证定价公式改为"消费时验证"**：Intent 引用等级不足的节点才触发 Verify，消费门槛即定价（原公式有"新节点依赖为 0"的先有鸡先有蛋问题）。
5. **证伪传播加阻尼**：有独立支持的节点不连坐；E3 只能被"重跑判官失败"降级，不能被连坐。
6. **M1 增加瘦基线对照**：单个 Claude Code 直接做同样 20 题；北极星 = 每解出一题的成本与解题率并排报告。
7. **引用勘误**：MAST 改引 [Z32]（[S31] 为解读文）；ACI 补引 SWE-agent 论文（arXiv:2405.15793）；删去"token 用量解释 80% 方差"作为司南选强模型的依据（该结论讲总投入规模，不是调度者模型选择），改为：Reason 承担全局判断、错误代价高，属 [观点]，M2 消融验证。

## 0. 设计哲学：解牛五诀 → 五条设计公理

| 庄子原文 | 设计公理 | 架构落点 |
| --- | --- | --- |
| 臣之所好者**道**也，进乎**技**矣 | 通用方法论 > 领域技巧；领域知识走锦囊不进内核 | 内核不含任何领域逻辑 |
| **依乎天理**，因其固然 | 先识别问题结构，再选解法形态 | 问题 intake 做三轴测定（§1.2） |
| 批大郤，导大窾 | Intent 从证据缺口里长出来 | 解牛图生长规则（§3.4） |
| 以无厚入有间 | 最小干预：薄内核、薄 harness | Worker 复用成熟 CLI（§5） |
| 每至于族，**怵然为戒** | 高危处自动降速 | 审批门 + 预算节点（§8） |
| 善刀而**藏**之 | 收尾归档：复盘 → 通鉴 | 记忆层（§10） |

元公理——**约束删简律**：每引入一个结构，必须回答"下一代模型会不会把它吃掉"；会被吃掉的放外壳（便于拆除），不会被吃掉的（验证、工具治理、预算）才进核心。

## 1. 问题模型与三轴

### 1.1 收口类问题

```
Problem = (Origin, Goal, Judge, Env, Budget)
```

- `Judge`（判官）：能独立于模型自述判定 Goal 是否达成的机制；进入一个领域先找判官
- `Env`：沙箱化工具容器（Kali / Lean+sage / k8s 诊断环境 / 病例模拟器）
- `Budget`：token、钱、动作数、时间、请求频率上限——显式参数

### 1.2 三根独立的轴（v0.1 修订）

intake 时测定三个各自独立的观测量，各驱动一件事；原"两范式"保留为词汇（A：不完全信息序贯决策；B：完全信息搜索验证），但**不再是捆绑标签**——一个真实任务可在轴上取任意组合：

| 轴 | 观测 | 驱动什么 | 范式 A 端 | 范式 B 端 |
| --- | --- | --- | --- | --- |
| 信息完整度 | 需要侦察/问诊/查日志吗 | **生长规则** | 按信息增益给 Intent 定价，广度优先 | 按证明义务收拢，深度优先 |
| 判官类型 | 有判官吗，判官多贵 | **证据梯可达上限** | 无即时判官→假设面板+唱反调+延迟证据（上限 E3d） | 确定性判官→形式验证（可达 E3） |
| 可逆性 | 动作可逆吗 | **审批门** | 低可逆→审批门+预算约束 | 高可逆（git/沙箱重置）→放手并行 |

子目标可各自声明轴值；一道任务可以跨段。

## 2. 总体架构：五层 + 两横

```
治理层   预算 / 审批门 / 哮天犬(watchdog) / 审计追踪
验证层   判官池（谛听）：确定性优先 → 程序化 → 模型面板 → 延迟证据
执行层   沙箱分级 + 工具容器（如意）+ 交互式工具会话化
状态层   解牛图：fact-intent 图（唯一写入者＝确定性图服务）
内核层   强模型 × 单循环 Worker（CodeAct），平等无预设角色，编排尽量薄
两横     司南（调度，只提交提议）· 通鉴（跨项目记忆）
```

## 3. 解牛图：状态层

### 3.1 节点

`Origin` / `Goal`（绑定判官）/ `Conjecture`（E0 猜想，须引用 Artifact 或已有节点）/ `Fact(E1..E3d)` / `Intent`（携带 expected_gain、budget、risk）/ `Hint`（人类注入，下次读图吸收）/ `Artifact`（内容寻址）/ `Playbook`

### 3.2 边

`supports` / `contradicts` / `derives_from` / `yields` / `proves` / `invalidates`（证伪传播，见 3.3）

### 3.3 证据等级（v0.1 修订）

| 等级 | 名称 | 晋级条件 | 谁能消费 |
| --- | --- | --- | --- |
| E0 | 猜想 | 提出 + 引用 Artifact | 只能推导新 Intent |
| E1 | 单源佐证 | 一个独立会话复核通过 | 低风险 Intent 可引用 |
| E2 | 异构佐证 | **不同模型家族或不同方法**的第二次独立确认（机检定义：模型家族不同，或引入了前条没有的执行证据；仅换提示词不算） | 高风险/高扇出 Intent 可引用 |
| E3 | 判官确认 | 确定性判官在洁净环境独立重放通过 | 进执行链、触发 proves |
| **E3d** | 延迟证据（v0.1 单独设级） | 相符性/延迟判官通过：预测结果出现，但不排除其它解释 | **不进执行链、不触发 proves**；后续判定性证据到达可升 E3 |
| X | 已证伪 | 判官重跑失败（连续两次一致）或人裁决 | 保留在图上（负知识） |

- **执行链与 proves 边只认真 E3**——E3 的含义必须是"回路里没有模型"，不能同时表示两种东西
- **运维陷阱**："指标恢复"只是症状判据；根因论断停在 E3d，需副本环境反事实验证（引入原因症状出现、移除则消失）才到 E3；指标类判官须配守护项（流量未压零、告警未静默）
- **反幻觉不变量**：任何晋级必须引用沙箱真实执行产生的 Artifact 哈希；模型自述不构成证据
- **证伪阻尼（v0.1 修订）**：① 有独立支持的节点不连坐；② E3 只能被"重跑判官失败"降级，不能被连坐降级；③ 一次证伪导致 K 个以上节点降级时告警

### 3.4 生长规则

- Intent = `(claim, expected_gain, budget, risk)`；信息完整度=partial 时按 `expected_gain/cost` 排序扇出，complete 时按证明义务收拢
- 三层访问视图（title/summary/evidence）按需下钻——物理隔离上下文、逻辑共享状态
- **消费时验证（v0.1 替代定价公式）**：Intent 引用等级不足的节点 → 自动触发 Verify；消费门槛即定价。防重复：去重键 =（节点、目标等级、证据版本），每键最多 2 次；r0 意图永不阻塞

### 3.5 写入协议（v0.1 修订）

**唯一写入者 = 确定性图服务**：schema 校验、晋级规则、证伪传播全部由代码强制；**司南与所有 Worker 一样只提交提议**，经 commit 门校验后应用。写入路径不含模型 → 可复现、可审计、司南可多实例（反单点）。并发提议按到达序串行；同 idem_key 幂等。

## 4. 司南：调度

- 读图生成四类任务：Bootstrap / Reason / Explore / Verify；**只提交提议，不是写入者**
- 扇出策略控制器按三轴取值决定并行度（partial→广度 3–5；complete→深度 1–2 + 正交竞速；judge=deferred/none→并发 ≤2 且 verify_share 上调）
- Hint 人机通道：注入即时、防抖触发 Reason、在途会话不注入
- 崩溃恢复：重读 `/work` 即可——图是唯一事实源

## 5. Worker 与闲人

- M0 复用成熟 CLI（Claude Code/Codex/GLM CLI）+ Worker Adapter；预留自研薄循环插槽
- Worker 无固定角色；任务由图状态动态生成
- 闲人（外壳层）：falsifier（专找反证）/ reviewer（干净上下文复审，属 Verify 角色）/ free-form（时间盒漫游）；**闲人只读图、只写 Conjecture(E0) 与反证**，不写决策性 Intent

## 6. 谛听：验证层

### 6.1 判官池（成本从低到高）

1. 确定性判官：flag 比对、测试套件、Lean、ASan、指标断言（含守护项）
2. 程序化检查：重放、复算、schema 校验
3. 模型面板：干净上下文独立复核 + 唱反调（无判官场景主力；**面板通过最高到 E2，不产 E3**）
4. 延迟验证：E3d 证据登记，后续证据到达后回溯

### 6.2 消费时验证（v0.1）

**消费门槛即定价**：被引用且等级不足才验证。叶子猜想无消费者→自然过期不花钱；扇出中心节点被多条 Intent 引用→自动进入验证队列。配 verdict 缓存（同 judge+同输入不重跑）。"未解决 + 已排除路径"是合法输出。

## 7. 如意：执行层

沙箱分级（bwrap→Docker→VM）；工具容器按域配置；工具接口即人机接口（防呆参数、有指导性的报错——ACI，[arXiv:2405.15793]）；扩展三档：钩子→锦囊→MCP。

## 8. 治理层

预算硬顶 + 50%/80% 节点触发复盘；动作风险分级（r0/r1/r2），r2 需审批门（一次批准一次有效）；哮天犬纯脚本零策略；审计=append-only 事件流 + Artifact 哈希链；授权范围必填、越界拒绝。

## 9. 模型经济

Reason/Bootstrap 用强档（[观点]：全局判断错误代价高，M2 消融验证）；Explore 中档多厂商；闲人异构便宜档；判官是程序不占模型预算；正交竞速=同任务 2–3 家先到先得。目标：单题 token 效率对标 sapper（1B 赢 4.5B [Z4]）。

## 10. 通鉴与锦囊

复盘 → Playbook（每步引用 E3 论断）→ 人审 → 锦囊（SKILL.md 开放标准）；胜率退役；防投毒：仅本项目复盘生成 + 审核 + 签名，不接第三方市场（[S34]：市场 12–20% 恶意）。

## 11. 创新点对照（v0.1 口径）

| 机制 | 最近前身 | 庖丁增量 |
| --- | --- | --- |
| 证据梯 E0–E3d/X | Cairn 二元 Fact、MAI-DxO 假设集 | 认识论一等属性 + 证伪阻尼 + E3d 独立设级 |
| 消费时验证 | RoboDuck 两级过滤 | 消费门槛即定价 + verdict 缓存 |
| 三轴分立 | 调研 v2 §9 | 三轴各驱动一事，去捆绑 |
| 闲人生态 | MAI-DxO 角色面板 | 常设化 + 只写猜想与反证的约束 |
| 司南 | Cairn Dispatcher | 只提交提议 + 扇出控制器 + 多实例 |
| 确定性写入者 | 事件溯源 | 图服务的晋级/传播规则代码化 |

## 12. 里程碑

- **M0**：图服务（事件日志+reducer）+ Worker Adapter + Docker 沙箱 + 司南最小版；验收=端到端解 1 道 CTF 题 + 全轨迹回放
- **M1**：证据梯 + 判官 + 预算 + **瘦基线对照（v0.1 新增）**；20 题评测集；坏事实注入验证阻尼
- **M2**：闲人 + 模型分层 + 扇出控制器；消融
- **M3**：第二场景验证三轴切换（数学/Lean 或运维）
- **M4**：infra agent + 通鉴 + 多节点

## 13. 评测方案

- 自建 ~20 题代表集，检查点式部分得分
- **瘦基线（v0.1 新增）：单 Claude Code 直做题，同题集同预算**；北极星 = 解题率 × 每解出一题的成本，与基线并排报告
- 每天跑防漂移；保留完整轨迹与错误

## 14. 开放问题

图服务选型（SQLite 起步）、三层视图失效策略、闲人漫游范围、三轴测定的实现（规则表先行）、锦囊审核工作流。
